## 三、对宏观路线图的对抗性修正

宏观路线图把方向写清了，但以下表述不能直接当架构事实：

1. **“trunk 清晰”只是约定，不是保护。** `integration/batons` 没有 branch protection，且 PR 运行期间 base 继续前进，导致一次检查同时变旧。真正的单一候选需要冻结候选 SHA、required checks 和合并策略。
2. **证据分散不只是运营债。** fail-open runner、过窄摘要与缺少 state projection 是测试/代码架构债；只整理分支不能修复它们。
3. **文件级 `owns` 只能减少文本冲突，不能证明语义正交。** Narrative、wiki、事件结果模型、state projection 都消费事件/关系 schema；接口未冻结时即使改不同文件，也会发生语义漂移。
4. **把场景、跨进程锚和视觉门移到非 required nightly 会削弱 PR 门。** 本次耗时构成显示问题是串行化，不是覆盖过多：最慢的 `story_test` 约 491s，其他大门各约 2–4 分钟。独立 clean checkout 的 required jobs 并行后，有机会在 10 分钟左右保留同等覆盖。
5. **“可比性当且仅当 `game/scripts` 与 `game/data` 相同”过强。** Godot 版本、addons、scenes、bench/gate 代码、命令行和环境都能改变结果或改变量具；必须把这些写进 provenance。
6. **state projection 是生产级换页/冷热镇的前置，不应禁止一次性 research spike。** 正确边界是：在投影和恢复等价门落地前，不合入持久化多镇实现；可以用 disposable headless spike 反过来验证投影边界。
7. **wiki 不是当前最高产品价值轨。** 它冲突少，但用户当前明确优先的是 map/building/interior 与可拖拽探索、多楼层。选择 wiki 会优化“容易绿”，而不是优化当前产品目标。
8. **“Narrative 与 trunk 已有 `docs/README.md` / `docs/05` 文件冲突”不符合当前树。** 以共同基点 `dae2fbe` 实测，trunk 改 5 个 path、Narrative 改 60 个 path，交集为 0；当前没有已证实的文本 merge conflict。仍需做语义 reconcile，但不能把预期冲突写成既成事实。
9. **历史 APK 的归属不成立。** 路线图指定的 `competent-noether` worktree 当前没有 `build/out/*.apk`，且有 8 个未提交修改；APK 只存在于主 checkout 的 ignored `build/out`，最新时间为 2026-07-30。它最多证明历史导出管线曾跑通，不能证明该 branch 或当前 HEAD 有 commit-bound 构建。
10. **“多镇只有 state projection 一个先决条件”遗漏知识权限。** 编号 62 的既有裁决把 `epistemic locality` 和 domain-scoped `KnowledgeState` 三臂列为第一刀：哈希能证明冷热态等价，却不能阻止 B 镇直接读取 A 镇尚未传播的事实。两条都要做，但作用不同。
11. **仓库并非完全没有权威快照。** `Sim.save_game` 已有反射式全量 snapshot/schema 与 load 恢复；真正缺的是从该 codec 抽取出的 canonical、versioned、hashable 等价性 oracle，以及能咬住遗漏字段的 mutation/round-trip 门。另造一套 projection 会制造第二个 source of truth；未审计所有 mutation path 前直接承诺增量摘要也过早。
12. **`IndustryState` 与 Narrative readiness 都被写成了结论。** 具名工人与 N=60 左尾目前是相关性候选，须用“总 capacity 不变、只解耦完成时刻/具名到达”的干预验证；Narrative 自己的生产合同仍是 NO-GO，S18 尚未裁决，不能先整支吞入再补边界。路线图引用的 S21–S28 在四个已推远端 ref 中也没有定义，当前不可复现。
13. **#43 的双防线只对已知 bug 完整，不是通用事件合同。** 采集侧依赖 `_nearby_agents(actor)` 排除买家，观察侧只显式排除 vendor；若未来采集侧把 actor 混进 witnesses，#43 仍会被买家“自证”喂绿。PR 前至少增加 buyer-only / actor+target 负控，并决定通用语义应为“所有观察者”还是 `witnesses - {actor,target}`；最好由统一 helper/schema 表达。
14. **#43 仍用终态职位反解历史事件。** 判据以最终 `_holder_of_title`、当前 action 与 `buy:` note 识别过去的 vendor pay；换岗、迁镇或配置演化后，历史账本可能被重新解释或整段豁免。短期应集中 participant 判定，中期让事件携带结构化 mechanism/role/vendor provenance，而不是用 note + 终态 holder 猜历史。

## 四、更新后的实施顺序

### P0：先获得可信候选（立即）

1. 对 #43 的 `a3b2e0f` 做提交级双评审；补 buyer/actor-side 负控、观察侧双端点排除与 machine-readable provenance 后，在最新 `925a260` 上重放或无冲突整合。
2. #43 只能以独立 draft PR 进入 `integration/batons`；PR 里审查 `witnesses` 是否应代表“全部观察者”还是“排除交易双方的第三方”，并同时跑显式 head gates 与 synthetic-merge gates。当前机制/R12 证据足以开 PR，不足以原样 merge。
3. 修 CI：短期把总 timeout 提到 30–35 分钟；正式方案拆成全部 required 的并行 jobs，而不是把现有门降级为 nightly。
4. 把当前候选 SHA 构建成带 git SHA/versionCode 的 APK，先做最小设备 smoke；release 级音频/触摸/HUD 验收可后置，但不能继续用 07-30 的 ignored APK代表当前 HEAD。

建议的 required job 组：

- static/provenance：版权、data、map、links、资产重建、recalc、complement；
- core-sim：S0 与宏观池（可再拆两 job）；
- deterministic-backends：LOD、DetGate、BackendGate、ModelPath、Voice；
- scenes：fast scenes、goals、story；
- rendered/device：在真正支持渲染的 runner 上 fail-closed，设备回执另绑 APK SHA。

每个 job 使用 clean checkout，不共享可变工作目录；始终上传逐门日志与 `head/base/checkout/toolchain` receipt。扩展 seed 网格可以留给 nightly，现有 required 判据不应被移走。

实现上应由同一 phase manifest 驱动本地全量与 GHA matrix，避免维护两份 gate 列表。PR 同时保留 `head-static`（显式检出 PR head，抓分支自身 lint）与 `merge-gates`（检出 synthetic merge，抓集成问题）两个口径；二者都不得冒称对方。Godot 下载校验和、Pillow/runner 固定版本、`fetch-depth` 与 `if: always()` 上传日志/receipt 也应进入 provenance 合同。

### P1：清正确性债，再接叙事

完成 #43 后，优先统一事件结果 schema（attempted / accepted / effect_applied / rejection reason），并让 fixture/scale 子进程非零即失败、产物 fresh 或 content-addressed。`codex/narrative` 先开只读 reconcile/PR，不直接合；Narrative、Story、Main 对 rejected event 的解释必须等 schema 稳定后再接。

### P2A：复用 save codec 建立 canonical witness

先审计并抽取现有 save/load codec，形成单一版本化 canonical projection；再加 component hashes、合法可达 mutation、round-trip、save/resume、LOD/focus/page boundary 与静态/晚触发负控。AC1 当前 probe 只能提供字段清单，不能整包当验收门合入。

### P2B：并行证伪 KnowledgeState 主诉

在单镇或 abstract domains 上跑三臂：即时全局知识、匿名延迟传播、具名 carrier 传播。衡量跨域泄漏、延迟、可追责性和叙事收益；这一研究 spike 不依赖完整多镇地图，也不应被 P2A 阻塞。

并行产品轨应优先做一个 **town-completeness vertical slice**：选一栋建筑及周边街区，完成外立面、不同室内布局、多楼层 portal、拖拽/探查、返回世界坐标与视觉回归。该轨不碰社会决策 schema；wiki 延后到事件结果与 projection 稳定之后。

### P3：Narrative 与经济只做判别性推进

Narrative 先完成 S18/生产合同裁决，再选择性合入必要组件；不整支吞入 8k 行。`IndustryState` 先做保持总产能的反事实干预，证实因果后才建模。

### P4：多镇恢复顺序

只有在唯一候选 SHA 的 required CI 全绿、#43/事件结果/fixture fail-close 关闭、canonical witness 与 KnowledgeState 两条边界成立后，才按 **消息 → macro shipment → transient carrier → 完整 agent travel → 最后 hot/cold materialization** 推进。贸易、货运和观察驱动的换页现在仍不应实现。
