### 已实质关闭 — 卸货 rollback 与 same-day manifest 复活

P1-g 已把卸货从顺序写变成可回滚事务：preflight 后保存 town/external coin、stock、event length/next id/digest、manifest/order 快照，`after_pay/after_stock/after_manifest/after_receipt/after_retire` 任一 failpoint 都恢复原状态；成功路径以 `cargo_unload/<manifest_id>` 绑定 pay→stock→receipt。工资仍在通用工作管线中 best-effort，这是当前明确边界，不应宣传为四者原子。

P1-h 将 complete manifest 从 live dict/order 退休。上一轮抓到的“卸货后同日再次 `_logi_import()` 会复活同 id cargo”也被 P1-j 实质修复：唯一 exact arrival receipt 充当 tombstone；live/retired replay 均不改货、钱、event/digest；conflict、duplicate、live-without-receipt 均 fail-closed。

但实现代价必须记录：每次 scheduled arrival 都线性扫完整 `event_log` 找 tombstone，而 `event_log` 仍 append-only 且无界。随模拟天数与人口事件量增长，长期累计成本接近 `O(N·D²)`；数百 NPC/多年存档前应新增 saveable deterministic arrival index / per-lane last-arrival-day，并用 receipt 重建/校验，而不是每次在线全史扫描。

### P1（权威边界）— pending manifest 仍可携带非 authored 价格/日期

当前 `_validate_cargo_state()` 对 pending record 只校验类型、范围和 dict/order 自洽；它不把 record 精确比对 `logistics.import_lanes[lane_index]`。`_validate_loaded_state()` 只调用前者；#44 的 live arm 主要核 route/node/good/batch/arrival identity，也不核 `price_per/price_den/arrived_day`。完成单的 load-compaction 才执行完整 authored-lane 对账。

而 `_first_unloadable_manifest()` 与 `_commit_manifest_unload()` 会直接信 record 的 price。于是 schema2 pending record 的价格或日期被篡改后可成功 load，并按坏价格付款/入库；#45/#44 可能事后红，却没有 fail-before-mutation。

最小正确修法是唯一 `_validate_manifest_against_lane(id, rec, logistics, state_day)`，由 load、commit preflight 与 #44 共用，验证：

- lane index、canonical id=`route/day/index`；
- route/node/good/batch；
- price numerator/denominator；
- `arrived_day>=1 && arrived_day<=state.day`，并符合 cadence/到港规则。

负牙必须逐字段 mutation，分别证明 load 拒绝且 receiver 不变、direct commit 返回 0 且钱/货/cargo/event 不变。未来同一 good 多 route/不同价格还需修 #45 当前按 good 键价的覆盖问题。
