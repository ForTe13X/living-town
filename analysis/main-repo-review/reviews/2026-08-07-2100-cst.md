## 三、对抗性 findings

### P0 — AO1 修了 projection，没修持久状态边界

[Sim.gd@505359d](https://github.com/ForTe13X/living-town/blob/505359d963c3a4e86c9ca412d1d425fc203c8b26/game/scripts/Sim.gd#L1163-L1248) 的 `save_game` 反射所有 script variables，只显式排除少量 derived/view/bench 字段，并按运行时值类型跳过 `Object/Callable`。结果是：

- `backend/ext == null` 时会进存档；注入 Object 后反而不进；
- `load_game` 对 blob 的每个键直接 `set(k, state[k])`；
- [Main._quick_load](https://github.com/ForTe13X/living-town/blob/505359d963c3a4e86c9ca412d1d425fc203c8b26/game/scripts/Main.gd#L2363-L2375) 没有重新注入 `Sim.backend/Sim.ext`。

因此 headless 生成的 `backend:null` 存档可清掉窗口里已接好的 AIBackend。`docs/137@integration/batons` 所说“load 时重接线”与代码不符。[StateProjection.gd](https://github.com/ForTe13X/living-town/blob/505359d963c3a4e86c9ca412d1d425fc203c8b26/game/bench/StateProjection.gd#L126-L155) 仅从 hash 中删 `backend/ext`，没有修 codec，而且会把这个真问题隐藏掉。

同一 codec 还保存并投影 `auto_run/speed/tick_interval/_accum`、`cand_calls/ext_veto`、若干 replay/record 控制。窗口镇和 headless 镇即便处于同一逻辑 tick，也能只因墙钟 `_accum` 或 `auto_run` 不同而得到不同 projection。现有第⑥臂只合成“两个键在/null vs 不在”，并非真实 window/headless 对拍。

**第一修法不是再加 projection 白名单**，而是建立版本化 `PersistentStateSchema`/DTO：每个字段明确 `authoritative persistent / derived rebuild / runtime handle / wall-clock & UI / bench diagnostic`，save、load、projection 共用同一分类；另有独立反射库存门保证新增 script variable 必须被分类。

### P1 — AO1 门有四类确定假绿，不能充当换页正确性证明

1. [tools/ci.sh:607-610](https://github.com/ForTe13X/living-town/blob/505359d963c3a4e86c9ca412d1d425fc203c8b26/tools/ci.sh#L607-L610) 只 grep 任意位置的 `state_projection_gate: PASS`，不检 `PIPESTATUS[0]`，也不跑已有 runtime-error scanner。先打印 PASS 再 exit 1 / `push_error` 仍可绿。
2. round-trip 只测固定 seed、tick 160 的一个自然态。若 decoder 漏字段，而该字段恰等于 fresh Sim 默认值（如 `day=1`、`speed=1.0`、`auto_run=false`、`spawn_count=0`），save→fresh→load→resave 仍相等。mutation sweep 只证明 projector 对字段敏感，不经过 decoder。
3. projection、manifest、分母都来自同一个 save blob；save 一开始就漏掉的字段会在三处一起消失。agent 分母只取 `agents[0].keys()`，看不见后续 agent 或晚期才出现的字段；不支持的 mutation 只记 `skip`，却不让 gate 红。
4. `project_sim` 和 gate 使用固定 `user://__ao1_*.dat`。并行 Godot/worktree、多镇 checkpoint 或后台任务可互相覆盖/删除；这与其未来消费者正面冲突。

此外，32-bit FNV 只能当快速诊断提示，不能当长期状态身份或“证明逐字节等价”；`_sorted_keys` 的 `typeof|str -> key` 单值反查也不是注入映射。正确产物应是 canonical bytes + SHA-256/BLAKE3，未知类型 fail-closed，临时 I/O 则最好由纯内存 snapshot 消除。

## 五、阶段实施方案

### Phase 0 — 候选与状态契约短闸

1. **冻结 `49d2de3` 或唯一后继**。AR1 保留，但同一 SHA 的全量 receipt 必须补成可达 artifact；在此之前停止新经济、视觉 reference 和重复 rebake。
2. **建立声明式持久状态 schema**。save/load/projection 三者共用；显式排除 runtime handle、wall-clock/UI、bench diagnostic，保留真正决定未来 tick 的权威态。修 headless save 清空 PC backend/ext 的反例。
3. **让 AO1 门真咬**：Godot rc + runtime scanner + 唯一末行 PASS；每字段先注入非默认 sentinel 再 decoder 对拍；agent key union、late/mid-lifecycle 样本、unsupported=red；真实 PC-like/headless、并发两进程和损坏文件负对照。
4. **升级状态身份**：输出 canonical bytes 与 256-bit hash；去掉固定 `user://` 临时文件，或使用 caller-owned run-id 路径和原子清理。
5. **建立 exact-SHA 交付**：从 frozen integration 开产品 PR；head-static、synthetic merge、pinned visual 分 job；保存 source/base/merge/game tree、dirty、命令、Godot/Python 版本、逐步 rc、raw-log SHA256 和 artifacts；required check 阻止后续直推绕过。
6. **证据卫生**：删除 phantom 引用和 placeholder；修 `docs/146@integration/batons`/PNG 错绑；ledger producer 拒 duplicate/extra/missing，使用唯一 run-dir/manifest/lock 并绑定 probe/audit/spec/toolchain hash。为 138 个 worktree 建 owner/keep/delete 清单，不自动删除 18 个 dirty tree。

**退出条件**：同一 frozen SHA 的 save contract 负对照、完整 CI、visual job 与 artifact 全可从 PR 复核；AO1 不再依赖自洽 blob 证明自身完整。

### Phase 1 — 一条“世界承认”的 town 纵切

范围固定为 `住宅 → 街道 → 广场 → cafe/shop → library/wash → dock`，不横铺更多建筑：

1. 把 `road/surface/prop` 从 WorldView 私有派生提升成 authored 空间数据；旧 map 走 compatibility adapter，先证编译后的 blocked/interactable/portal 集逐字节相同。
2. prop 显式分类 `solid / walkable_decor / interactable`，渲染与导航共读；道路有较低 nav cost，让 NPC 长距离迁移真实偏好沿街。
3. 给 bench/read/bathe/cook 各一个最小、可观测活动；允许这一步有意移动 golden，但必须走 R12 双烘与 held-out，而不是继续为“零金标”牺牲产品语义。
4. 修 Probe bounds/history/double-push，并覆盖 pan/zoom、楼层、ESC、真实 pointer hit、access policy；桌面 PC-first，不把旧 Android build 当本 SHA receipt。
5. 用显式 `clone_roster` 取代 `personas.keys()`；N=24 至少保证无重复显示名且有 home/job/schedule 映射，VoiceGate/model-prompt snapshot 在 N=24/48 运行。
6. 加 AP/AM 专属存在性负对照：删道路、广场焦点或特色家具必须红；不能只靠“没有破坏旧截图”的无回归门。

**退出条件**：玩家可拖拽/缩放并走完整纵切；NPC 多数长距离移动沿街；实心街具不穿模、座椅真能坐；每栋开放建筑至少一个空间专属活动；N=24 身份/声音/住址/工作闭合。

### Phase 2 — 叙事与经济按领域边界增量

- AR1 是已落远端、小而合理的 storylet 内容片；先补齐 Phase 0 receipt，再开下一幕。它不能替代 town 纵切。
- 经济不要从“无限 import 往全局单例 `town_stock` 加货”直接开工。先引入带 `town_id` 的库存/货币账户、显式 external counterparty，以及确定性的 `Shipment{origin,destination,cargo,depart_tick,arrival_tick,carrier}` 队列；运输者携带消息/知识是上层 bridge。第一条 lane 应有有限配额、负对照和延迟，不可把 #40 缺货门灌绿。
- 多镇/lazy swap 等 Phase 0 的 persisted schema 与 KnowledgeState 成立后再做；异步只允许纯预计算或确定 tick/排序的 commit，完成先后不得进入仿真态。
