## 四、对抗性 findings

### P0（anchor authorization blocker）— `C` 键绕过只读观测室与 same-plane authority

直接读当前代码得到完整链：

1. 真实 portal 进仓后 Main 把 `_selected_id` 设成 `player`；
2. `_update_obs()` 只把 `_chat_in.visible=false`，并不禁止 chat command；
3. `_unhandled_input()` 的 `KEY_C` 无条件调用 `_on_player_say("你好，最近怎么样？")`，旧注释还刻意说明
   不 gate 在 player mode；
4. `_on_player_say()` 只查 selected id/text/agent existence，随后立刻写 `thinking=true`，调用 backend，并
   在 callback 写 memory；它没有拒绝 self、warehouse、不同 plane 或超距；
5. `_select_at_world()` 按所有 `Sim.agents` 的 local `pos` 做 hit-test，不过滤 active space/floor；
   `_cycle_selection()` 同样遍历所有非玩家 agent；
6. P1-v test 只断言 `_player_do("greet")` 被只读门拒绝，没有模拟 `C`、输入框或 cross-plane selection。

因此至少有两个可达反例：进仓后直接按 C 自聊并改变 player memory；或 Tab/局部坐标点中镇上 NPC 后按 C，
产生跨平面 chat/thinking/memory。AI chat 虽不走 standing/acceptance，但它是明确的 Sim 状态写，已经违反
observatory 的 no-op 合同，也绕过 P1-t 希望建立的感知边界。

修法不是再给 KEY_C 一条特判。应建立唯一 chat preflight/authority，由键盘、输入框、demo 自动 chat 共用：

- 必须是真实 player context，target 非 self；
- target 与 player same space/floor 且满足明确 reachable 规则；
- 当前 context 允许 chat（observatory 明确拒绝）；
- callback 前后重新验证 agent/session，防异步回调在换页/换档后写旧对象；
- selection/hit-test/Tab 只产生当前 active player plane 的合法目标；Probe-only 浏览与玩家交互分开。

必须补三条 exact no-op 负牙：warehouse self-chat、warehouse 选中 town NPC 的 cross-plane chat、远程 Probe
点击观测柜台。另补同平面正臂，证明没有把旧 `chat-shoot` presentation seam 静默杀死。

### P1（future-proof/performance）— P1-v 每次 redraw 多次扫描无界事件史

`WorldView._draw_port_warehouse_status()` 每次绘制调用投影。投影的 receipt 路径：

1. `_latest_cargo_unload_receipt()` 从 `event_log.size()-1` 逆扫；
2. `_cargo_unload_receipt_at()` 再遍历整个 log 收集同 txid 的两/三行；
3. `_historical_manifest_from_receipt()` 调 `_manifest_authority_error()`，其中 arrival validator 又遍历完整 log。

WorldView 接 `Sim.ticked` 与 `agent_changed` 重画，默认 `tick_interval=0.08`。所以仓内待机也会以约 12.5 次/s
重复历史验证。P1-h 只让 live manifest queue 有界；append-only `event_log` 仍增长。今天 d60 约 3.8k–4.0k
事件时可能没体感，N=500、360/1000 天、多镇合并历史时会直接放大。

推荐：维护 deterministic derived `latest_unload_receipt_by_node` / `event_id -> index`，在 append 时 O(1)
更新、load 后一次性从 ledger 重建并严格校验；cache 不入 digest，权威仍是 receipt。或直接利用相邻 event-id
和已知 index 做有界三行检查，避免按 txid 全表聚合。加 d60/d360/d1000、不同 event count 的投影延迟门与
load-rebuild 等价牙，防“缓存快但信错账”。完成这一 game-tree 修复后再 bake anchors。
