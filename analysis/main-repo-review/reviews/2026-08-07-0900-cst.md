### P1 · AK1 有真实门，但既非 GitHub required，也有一个雪层假负控

AK1 确实把 AF2/AI1 判据接到 `tools/visual_gate.sh`，并让每次截图先删旧图、检查 Godot rc、致命日志标记和非空产物；本地 curated receipt 也给出 season/precip PASS。实现不是纸门。

但有三处必须降级措辞：

1. [visual_gate.sh](https://github.com/ForTe13X/living-town/blob/a0634574e87fdd4df71c3c5897505c8ca26be468/tools/visual_gate.sh#L258-L286) 在 `GITHUB_ACTIONS=true` 且未显式 require/runner 时直接退出 77；[ci.sh](https://github.com/ForTe13X/living-town/blob/a0634574e87fdd4df71c3c5897505c8ca26be468/tools/ci.sh#L683-L707) 把 77 当 SKIP。workflow 没设这两个变量。因此“进 required CI”只表示接进脚本控制流，不表示 GitHub required check 实际执行像素门。
2. 冬雪 off 采集只传 `--draw-skip snow`。生产调度是 `if winter and snow_enabled: snow; elif weather==rain and rain_enabled: rain`。在冬季雨天禁 snow 后会回落画 rain；这使删除/空实现 `_draw_snow` 的回归可能仍由 on/off 之间的雨丝差异放过。应先把调度改成“冬季分支内部决定是否画 snow，不允许 fall-through”，再用**真实删空雪层变异体**验证门红。
3. `vg_shoot` 的 fatal regex 刻意排除裸 `ERROR:`；Godot `push_error()` 不保证非零退出，这仍可能生成图后假绿。应复用 `ci.sh` 的完整 scanner + 精确 benign allowlist，而不是用较弱的第二套错误定义。

此外 `analysis/ak1/green_full.txt` 只是一份整理后的摘录，并引用未入库的 `analysis/ak1/ci_full.log`；它没有 commit/tree/完整命令/外层 exit 的机器绑定。可以作为局部读数，不能作为 current-tip release receipt。

### P1 · AL1 守了判决结果，没有守四个输入臂确实不同

`tools/aa3_regression_gate.sh` 会运行 natural/vendoronly/buyeronly/partiesonly，并正确要求 `[]/[43]/[43]/[43]`；缺行、JSON 解析失败、成交低于豁免线都能判红。这比一次性手工 census 前进了一步。

漏洞在输入身份：runner 只从 `[FIXCENSUS]` JSON 取 `hard_fails` 和 `buy_total`，没有校 `mutate`、seed/days/N，也没有校 witness 形状。若 `buyeronly` 的实现误改成 `vendoronly`、`partiesonly` 或空 witnesses，它们仍都可能产出 `[43]`，四臂门全绿，却不再能抓“观察侧又只排 vendor”的原始回归。

现有所谓 teeth test 只是把 gate 里的**期望常量** `[43]→[]`，没有变异生产观察侧或 collector；它证明比较器会比较，不证明 buyer-only 臂仍是 buyer-only。

修法很小：census 输出并由 gate 断言 `mutate/seed/days/n_agents`，以及每臂的 exact witness-shape 计数（第三方、buyer-only、vendor-only、parties-only、empty 必须互斥且成交全覆盖）；然后把 #43 观察侧临时退回“只排 vendor”作为端到端负对照。CI glue 同时检查 gate 的 `PIPESTATUS[0]` 与唯一 PASS sentinel，不能只 grep 一行。

### P2 · 室内美术与 Sim 导航仍隐式耦合，是下一轮内容规模化的主要摩擦

本轮最有价值的架构发现不是一个新模型，而是一个已跑红的具体耦合：`interiors.json` 的每件家具会同时被 WorldView 当装饰、被 `_compile_interiors` 当 interactable 来源、被 `_build_interior_grids` 通过 slot 白名单隐式推导为阻挡格。结果是增加一件“纯装饰”也可能改 NPC 路径和逐 tick chain。

AM1 用保持挡格集同构避开了回归，这对当前小片正确，却不适合作为完整 town 的长期 authoring 纪律：它会迫使所有美术打磨在旧布局上换皮。

更好的低成本 bridge 是保持旧数据逐字节行为的 legacy adapter，同时给新内容拆出显式层：

- `visual_decor`：只渲染，不进入 Sim；
- `nav/collision`：显式 `blocks_nav` 或独立 occupancy mask；
- `interactables`：显式 action/advertises/stock；
- `portal/access`：空间连接与访问策略。

先证明“旧数据经 adapter 编译后 blocked/interactable/portal 集合逐字节相同”，再让新街区只使用显式字段。这样不是大重构，而是直接降低后续每栋室内的集成成本。
