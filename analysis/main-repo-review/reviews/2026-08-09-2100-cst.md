### P0 — standing 漂移会翻号，E7 的社会因果基线无效

`Sim.gd:1646-1654` 注释称每三天让 standing 向 0 漂移 1，实现却是：

```gdscript
r["standing"] = float(r["standing"]) - signf(float(r["standing"]))
```

对 `abs(x) < 1`，它不是归零，而是永久跨零振荡：

```text
-0.20 -> +0.80 -> -0.20 -> ...
-0.35 -> +0.65 -> -0.35 -> ...
+0.25 -> -0.75 -> +0.25 -> ...
```

E3c/E4b/E4c/E4d-B/E7 的 shortage standing 使用的正是 `-0.2` 一类小数，craft credit 也可写入正小数；接受规则再以 `STANDING_K=6` 放大其符号变化。一次三日漂移就可造成约 6 分 acceptance 摆动，不能当作可忽略数值噪声。

所以 E7 最多能说明：**在当前带 bug 的 standing 写入/漂移整条路径中，关掉该路径会消除某个 supply-rate 差异。** 它不能把差异归因于一个语义正确的负声誉模型，也不能据此授权新的 grievance 架构。docs/174 自己警告不要复用“翻号漂移”，却没有先修这个共同基线。

正确顺序是先加性质测试：`{-2,-1,-0.6,-0.2,0,+0.25,+0.5,+1,+2}` 经一次 drift 后不换符号、绝对值不增加、零保持零；确认旧实现先红，再用 `move_toward(x, 0, 1)` 或等价式修复。长期轨迹必然改变，不能直接重烘 golden 把变化合法化。

### P1 — multi-good reader 有价值，但不是事务化产业基础

两条代码增量的正面结论成立：旧 dict 形状兼容；数组按 authored order 遍历；没有新增 RNG、墙钟或异步完成顺序；当前默认数据仍为单货，因此 S0 digest 保持不变。本地独立运行 E4a/E4d selftest 均通过。

但 generic schema 的隐藏语义需要先冻结：

- multi-consume 是逐项 best-effort；缺少其中一项时，其余货已被扣除，动作仍获得完整 need recovery。没有 bundle 原子性或逐货 receipt。
- multi-produce 按数组顺序消费输入；记录之间会争夺同一输入。一次工作可同时产出所有 outputs。
- 每个 output 都独立触发 craft fallout/memory，社会信用可能随 output 数量成倍增加。
- `_stock_pull_mult` 与部分 trade fallout 只读取第一条记录，次产物短缺不会同等反馈生产。
- #39 对同 subject/同 good 的重复记录可能只取第一项。
- `audit_map.py` 未 fail-closed 拒绝空数组、非 dict 元素、非正 amount、重复 good 等非法 schema。
- 两个 selftest 明写未接入 Harness/`ci.sh`；正常 S0 只经过当前单货数据，不能覆盖新数组路径。

在任何生产数据开始使用数组前，先明确 `mode=all_or_nothing|best_effort`、primary good、输入/输出原子事务、逐货 receipt 与 fallout 归属；补结构 validator 与能杀死 array reader 的 required negative tests。否则“支持多货”会把不明确的部分提交、顺序依赖与社会倍增固化为公共 API。
