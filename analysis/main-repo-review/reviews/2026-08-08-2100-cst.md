### P0 — import 的“先付后到、无免费货”被代码和运行时反例直接推翻

`Sim.gd:3716-3729` 先计算 `fit` 与 `cost=floor(fit*pnum/pden)`，检查余额后却先 `_stock_move`、再 `transfer`；`transfer()` 在 `amt<=0` 时直接返回 false（`Sim.gd:3244-3254`），调用方没有检查返回值。

本轮在冻结 tip 上用 bench-only 临时探针构造 `fit=1`，运行后立即删除探针，未改产品树。观察值：

```text
stock 79 -> 80
town_coin 60 -> 60
external_coin 0 -> 0
event: import*1
#45: PASS, expected external=0
```

价格是 `3/4`，所以 1 件货的逐批地板价为 0。这不是抽象舍入争论：货已进入权威库存，付款事件没有产生，硬 #45 仍把“应值 0”判绿。配置缺失/非法 price 时还会静默退回 E1 免费到货，使 typo 可以悄悄改变经济制度。

最小产品修复不是把 import 改为 `ceil` 一行，因为这会引入 import/export spread 与长期钱量偏差。应先冻结一种明确合同：最小货币单位 + deterministic remainder account、整批报价，或显式 import-ceil/export-floor；paid/free 模式必须在 schema 中具名，paid lane 的分子分母必须为正。无论采用哪种，quote、余额预检、库存预检和两腿提交必须进入一个 reducer，成功才一起产生事件。

### P0/P1 — #45/#46 证明的是总量/邻接，不是逐笔金额或原子性

`transfer()` 的 pay event 只有 from/to/reason，没有 amount、tx_id 或 lane_id；`_export_commit()`（`Sim.gd:3805-3821`）先转钱、后减货，第二腿失败只 `push_error`，没有回滚。同步且当前只有一个 emitter，使常规路径“不容易失败”，并不等于事务原子。

#46 从 free-form note `export*<qty>` 解析数量，要求 pay 与 stock event 相邻并且 qty 相等；它不读取实际 money amount。#45 则按所有 stock qty 和 lane price 重建最终 external 净额。于是错误逐笔价格只要互相抵消，就会全绿。

本轮第二个临时只读探针在同一冻结状态注入两笔 export：正确收入 `[1,2]`，实际收入 `[2,1]`，总额仍为 3；结果 #34、#38、#45、#46 均 PASS。由此可执行地证伪“#46 守贸易原子性/逐笔对账”。

正确的最小事实应类似：

```text
TradeCommitted {
  tx_id, lane_id, direction, origin, destination,
  good, qty, price_num, price_den, rounding, amount,
  payer, payee, tick
}
```

同一 reducer 在零 mutation 的完整预检后一次性写 money + stock + event；#45/#46 按 tx 检查 exact lane tuple、实际 amount、两条腿和方向。import/export 必须对称，不能一边靠 aggregate、一边靠 note 邻接。

### P1 — logistics 仍是定时库存函数，不是 transport 或 multi-town bridge

可肯定的是：当前单 lane 调度使用整数 day/cadence，没有新增 RNG/墙钟；S0 的 237 次 import、63 次 export 均保持 deterministic。不能外推的是：

- `tools/lint_data.py` 的 required/schema 没有 logistics；删文件、空 lanes、非法字段会让 #44–#46 真空通过。
- `_logi_on()` 只看 dictionary 非空；只剩 `_doc` 也算启用。
- #44/#46 分别收集 node set 与 good set，不验证精确 `(lane,node,good)`；第二 lane 后交叉拼错仍可过。
- #45 以 good 映射价格；同 good 不同价的两条 lane 会发生归属碰撞。
- 没有 shipment attempt/arrival、due tick、carrier、route、in-transit state、blocked outcome 或到期完备性。
- export 在 `prod_pool_num != prod_pool_den` 时直接返回，即明确只支持 N=12；它不是当前规模线或多镇进展。
- `external_coin` 从 0 开始且不得为负，export 只能取回此前 import 注入的余额。它更像封闭 clearing pot，不是外部需求市场；nightly 中 import 先于 export，还隐式决定了结算优先级。

因此不要继续加第二 lane。先给 `LaneSpec` 和 `ShipmentAttempt/Outcome` 稳定身份，再让交易、载货者、消息 carrier 和未来 town partition 共用。若保留当前 external 语义，应改名并写明 clearing balance；若目标是 world economy，则必须另行定义 counterparty、信用/负余额和钱量守恒边界。

### P1 — 视觉有 polish，但没有推进 exterior/interior 或运输世界模型

AV1/AV2/AV3/port 的增量是看得见的：建筑轮廓更有层次，五张 terrain tile 变暖，码头在整镇截图中更易辨认。量化上，AV1 昼图改变约 0.689% 像素，AV2 改变 31.31%，AV3 改变 2.95%，port 只改变 0.0939%；因此 AV2 是唯一全画面量级的变化，其余是局部 polish。它们也遵守 pure-View/off-product 的金标纪律。

但能力边界没有变化：本窗没有修改 map、spaces、interiors、portal/floor 或玩家拖拽控制；`Main.gd` 仅给 feed 抑制增加 export。`WorldView.gd:3519` 还明确写着 `_draw_port()` 不读 logistics 的 `port_dock`，只从 `world.areas.dock.rect` 硬派生像素。船屋、船、箱桶和路牌没有 world object/nav/collision，agent 会按原 dock walkability 穿过这些“实体”。为了不碰 POND 水线，船本身也被 clamp 在水线以下的铺装格上，视觉上更像摆在甲板而不是进入水域。

因此下一片视觉工作不应是 AV4。应让港口船屋/仓库从 authored `Building/Portal/Space/Floor` 与 logistics node 数据同时驱动外观、入口、碰撞和 nav；视觉 dock 与 `port_dock` 必须共读同一位置/身份，而不是两个约定恰好都叫 dock。terrain gate 也应在临时目录中执行 recipe 并逐像素比对，同时锁 reference/provenance manifest。

### P1 — replay 锚仍没直接观察经济值，贸易边界读档也未被覆盖

`event_digest` 折叠事件 id/type/actor/target/accepted/subject/tick，但不折 `note`，也不直接折 `town_coin`、`external_coin`、town stock 或 agent coin。pay event 又没有 amount，所以“金额错但事件形状相同、且暂未影响后续选择”可能不移动现有 golden digest/chain。

## 五、分阶段实施方案与明确第一刀

### Phase 0A — 先恢复“红绿灯可信”

**第一刀只改 complement tooling + 负对照，不重烘行为。**

1. 强制 `HARD_IDS ⊆ SPEC`，每个 C/G hard 必有 provider；unknown hard 默认失败。
2. 为 #44/#45/#46 增加 fixture/provider，并把 logistics 加入 shipping profile 的 required/schema lint。
3. 落两个本轮已证实的负对照：`fit=1 @ 3/4` 的免费进口必须红；两笔错误 amount 互相抵消必须红。
4. 再加 cross-lane tuple、同 good 不同价、删除调用/空 lane、强制第二腿失败的负对照。
5. clean committed tree 重烘；默认 guard 必须零 warning、strict/default 都 rc0。漏掉任一 hard SPEC 的 self-test 必须 rc1。

退出条件：旧代码必被新负对照打红；修复后才允许移动 golden/ledger。此片不新增 Sim 功能。

### Phase 0B — 统一 TradeTxn，而不是继续修补两个 wrapper

1. 冻结 `LaneSpec` 与 `TradeQuote`，明确 paid/free、价格分数、舍入和 remainder 语义。
2. 新建唯一 `_trade_commit`：完整预检后一次提交 stock + money；失败零 mutation。
3. 事件携带实际 `tx_id/lane_id/amount/qty/price/rounding/counterparty`，而不是从 reason 字符串猜。
4. #44 守 exact lane provenance/due outcome；#45/#46 按 tx 守 amount 与两腿；import/export 使用同一谓词族。
5. 冻结新的真正 held-out seeds（建议 61–126）后再选阈值；跑 60/120/240 天以及 trade-boundary save/load/continue。

退出条件：任何一笔错价、半提交、交叉 lane、重复/漏 due 都能被对应门精确抓住；正常满仓/余额不足有具名 outcome，不靠真空 PASS。

### Phase 0C — 建立 exact-head 交付门

1. Actions 增加 `integration/batons` exact-head job，同时保留 PR synthetic merge job。
2. 保护 integration/master：required check、必须 PR、禁直接 push。
3. artifact manifest 至少记录 SHA、`HEAD:game`、clean status、完整命令、Godot/Python/OS、开始结束时间、rc、raw log SHA256。
4. state projection timing 使用 pinned runner 或相对基线；视觉 job 用 pinned environment、`LT_VISUAL=require` 并上传原帧。

退出条件：当前 product SHA 有 GitHub 可下载的 exact-head receipt；仓内手写 `CI PASS` 不再被当作唯一交付证据。

### Phase 1 — 港口端到端 world vertical slice

把已经画出的港口作为第一位真实消费者，而不是再选一栋无关建筑：重做北池南岸为真实水陆边界；`port_dock` 的位置/形状由 shared node schema 驱动视觉、碰撞、路径与物流 attempt；栈桥是 walkable，船占 water，船屋/货箱是 blocker。给船屋或仓库一个可点击 portal、独立 interior 和可选 2F，完成 town exterior→door→interior→floor→return。

玩家在可拖拽 town world 中完成整套往返，Probe 与真玩家路径各跑 screenshot + portal/nav 负对照。门至少包括：visual footprint == nav mask、NPC 不穿实体、portal/worksite 可达、overhang culling 不 pop、默认全镇 zoom 昼夜仍可读。先让一批货从这个节点产生可追责 arrival，再考虑船/承运人动画。

退出条件：删除 portal、错 floor、视觉与 nav 错位都能被门抓住；不再由 pure draw 伪装实体。

### Phase 2 — 再谈规模、多镇与 page swap

先完成版本化 `PersistentStateSchema`，明确 authoritative / derived / runtime / UI / diagnostic / config 分类，让 save/load/projection 共用；再以 town partition 和 deterministic committed tick schedule 做冷热镇等价。export 的 N=12 限制、资源/岗位密度和 travel-social 安全均未解决前，不应把当前 clearing pot 外推为区域经济。

### 明确暂停

暂停第二条 import/export lane、N>12 export、多镇实现、AV4/更多纯 View building dressing、继续重烘贸易 golden，以及新的“committed CI PASS”文档。20 个 dirty worktrees 只做 owner/keep/delete 清单，不自动删除。
