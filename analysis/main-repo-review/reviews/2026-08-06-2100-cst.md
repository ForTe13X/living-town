## 三、对抗性 findings

### P1 · AE2 仍可把旧测量盖成当前树，不能标“fail-closed 已收”

这是本轮最确定的新缺陷，而且已做隔离复现。

1. [参数与 bake 路径](https://github.com/ForTe13X/living-town/blob/6666d6a57652bf871e3f818d3dbcc84f459cd292/tools/gate_fixture_audit.py#L690-L742) 仍允许 `--from OLD_DIR --bake-ledger`。不带 `--run` 时 `tree_sha=None`；[树比较](https://github.com/ForTe13X/living-town/blob/6666d6a57652bf871e3f818d3dbcc84f459cd292/tools/gate_fixture_audit.py#L428-L498) 因 `tree_sha is not None` 才执行而被跳过，写 ledger 时却用 `tree_sha or cur_tree`。结果是旧/伪输出被盖上当前 `HEAD` 和当前 `HEAD:game`。
2. 即使走 `--run`，工具只 archive `HEAD:game`，随后从工作树复制 `tools/gate_fixture_probe.gd`。dirty probe 没有 hash 或 clean-tree 检查，ledger 仍只盖 committed HEAD。
3. 默认输出目录固定且不清空；parser 扫所有 `.txt`、信任文件内 tag 并可覆盖同 seed。bake 只要求每个 tag 非空，不验证期望 seed/invariant/`live` 全集，也没有 completion sentinel。残留、并发或“退出 0 但只吐一个合法 seed”的输出仍可能进入锚。
4. [consumer](https://github.com/ForTe13X/living-town/blob/6666d6a57652bf871e3f818d3dbcc84f459cd292/tools/gate_complement_guard.py#L244-L270) 只打印 metadata，不比较当前依赖树。当前入库 ledger 仍写 `baked_commit=3412b253`、`baked_game_tree=6c13be2…`，而冻结点 `HEAD:game=a176d686…`；守卫照样返回 0。

隔离负对照使用系统临时目录，不写仓库：

```text
python tools/gate_fixture_audit.py --from %TEMP%\lt_gate_fixture_out \
  --bake-ledger --ledger %TEMP%\lt_ae2_from_backdoor_review.json

source iso marker game tree = 6c13be2…
current HEAD:game            = a176d686…
result                       = RC 0
scratch ledger stamped       = current commit + a176d686…
```

这不证明当前 provider 表一定算错；它证明工具**不能证明它是新鲜且来自所盖的树**。`gate_fixture_audit --self-test` 与 `gate_complement_guard --self-test` 本轮都通过，但现有 self-test 没覆盖上述路径。

### P2 · “state projection 是当前生产 bug”属于过度外推

AF1 的干预实验证明了**现有验证 oracle 会漏掉字段突变**：手工删除一条 belief 后，当前 digest、chain 和延续窗口仍可能相同。它没有证明当前 save codec 在自然 round-trip 中真的丢 belief。准确措辞应是“当前 save/load 正确性门存在盲区”，而不是已经观测到产品数据丢失。

风险仍然真实且优先级高：存档、回滚、换页、冷热镇等价都需要 canonical、versioned、hashable 的状态 witness。实现应从现有反射式 save codec 抽取单一 oracle，而不是另造第二套状态真源。

### Phase 2 — 从纵切扩为完备小镇内容矩阵

先把 outdoor map 本体与连续街区纳入验收，再给七栋建筑逐栋建立同一矩阵：

| 维度 | 最低完成定义 |
