## 四、对抗性 findings

### P0 — P1-aa 没有关闭异步聊天 authority

当前 `Main.gd` 的同步路径在调用 backend 前检查：观测室拒绝、target 非 player、target 与 active plane 相同。
但 callback 直接使用捕获的 `ag`：

1. 无条件 `ag["thinking"]=false`；
2. 无条件输出气泡/日志；
3. 直接向捕获对象的 memory 写入玩家问答；
4. 不检查 player 是否已经进入 `port_warehouse/1f`、target/player 是否换层、agent 是否仍属于当前 Sim、
   是否 load 了另一局，或该请求是否被后一个请求替代。

这不是理论上的未来 async 风险；`AIBackend.chat` 本来就是 callback API。只要 backend 回答不是同步完成，
“发问后立刻过 portal/读档”就是可达路径。P1-aa 卡片宣称“观测室聊天与选择权限收口”因此过度。

修复应使用一份 immutable request context（target id、player/target address、Sim/load generation、request id），
callback 前重新 resolve agent 并复用同一 chat authority。失败时只清理属于该 request 的 presentation 状态，
不能写 memory/气泡/日志。负牙至少覆盖：发问后进仓、target 换 floor、load/session replacement、旧 reply 晚于
新 reply；同平面邻近正臂必须保留。

### P1 — P1-aa 仍允许 same-plane 远距聊天

`_agent_on_active_plane()` 只比较 `space/floor`。Tab 会枚举当前平面的全部 NPC，`_focus_agent()` 也只做 plane
检查；`_on_player_say()` 没有距离或 `_socially_reachable` 等价条件。因此“same plane”被当成了“可以当面
聊天”。如果设计希望电话/无线电，这是一个未建模 channel，UI 与记忆也没有说明；如果是普通打招呼，则是
权限缺口。

不要在三个入口各加距离 if。先决定 chat channel：当面聊天要求 same plane + bounded distance/LOS；远程聊天
必须是显式设备/关系/费用通道。当前项目没有后者，故 P1-ac 应先采用当面规则并加远距负牙。

### P0 — P1-ab 的“历史有界化”仍是 O(E)

当前调用链可直接证明：

```text
warehouse_observatory_projection
  -> _latest_cargo_unload_receipt        # 最多扫 1024
  -> _cargo_unload_receipt_at            # tx 邻域最多 5
  -> _historical_manifest_from_receipt
  -> _manifest_authority_error
  -> _manifest_arrival_receipt_error     # for raw_event in source_events：全 event_log
```

所以有合法 recent receipt 时，每次 redraw 仍至少一次 `O(E)`。上一报告要求 append/load 派生 index 或真正有界
proof，并要求 d60/d360/d1000 性能牙；P1-ab 两者都没有做。常量存在只证明搜索窗口有上限，不证明整个
projection 的复杂度有界。

应维护可重建的 arrival/tx receipt index：event append 时更新，load 后从账本一次性重建并核 exact count/
adjacency；View query 只读派生结果。派生 cache 不进 digest，但 ledger/cache 不一致必须 fail closed。测试要用
增长 event history 的操作计数或稳定基准证明 query 不随 E 线性增长，而不是只断言常量。

### P1 — 局部 tx 窗口削弱了 projection 自身的 exact-set 证明

P1-ab 只在 receipt `index-2..index+2` 收集同 txid。现有 mutation 把 duplicate stock 紧贴在 receipt 后，
因此会红；若先追加至少三条无关事件，再追加同 txid duplicate，projection 邻域看不到它。全局 hard invariant
与 save migration 仍会在完整审计时抓住，所以正常已验证 state 不会自然产生该形状；但
`warehouse_observatory_projection` 自身不能再宣称“同 txid exact-set”。

最佳修法是由同一个 ledger index保存 txid 的完整 count/contiguous span，而不是重新全扫，也不是假设坏行
必紧贴 receipt。补 far-separated duplicate 负牙，并在文档中区分“projection proof”与“全局 invariant proof”。
