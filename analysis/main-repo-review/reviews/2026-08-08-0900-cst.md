**总判决：REQUEST CHANGES。**

因此明确裁决是：**不要继续落 E2，也不要重烘 E2 金标。第一刀先修守卫与 E1 的可追责 lane 合同。** 隔离 worktree 里正在做的 E2a 仍是未提交 WIP，现有设计会在 `fit=1, price=3/4` 时产生 cost=0 的免费货；货先入库、钱后转，`pay` 事件又不记录 amount/tx/lane，所谓 #45 只能做 aggregate 对账，不能证明一笔货对应一笔付款。现在把它重烘，只会把未闭合协议固化成新基线。

### P0 — complement guard 对新增硬不变量 fail-open；E1 的核心 receipt 不成立

当前 `tools/gate_fixture_audit.py` 的 `HARD_IDS` 包含 44，但 `SPEC` 只定义到 43；ledger 的 `invariant_kinds/providers` 因而没有 #44。当前 tip 实跑：

```text
python tools/gate_complement_guard.py
⚠ Invariants.gd 有 1 条锚不认识的不变量：#44
exit 0

python tools/gate_complement_guard.py --strict
❌ Invariants.gd 有 1 条锚不认识的不变量：#44
exit 1
```

`tools/ci.sh` 调的是默认非 strict 形式，所以“全门绿”与“#44 没进 ledger”可以同时成立。这不是文档措辞争议，而是现行 CI 路径的确定假绿。

最小修复不是再重烘一次：

1. `SPEC ids == live invariant ids`，并至少要求 `HARD_IDS ⊆ SPEC`；未知 hard invariant 默认红。
2. 给 #44 明确定义 kind/provider；其 provider 不能只是“logistics 非空”，必须消费 due-attempt/arrival 事实。
3. self-test 加“新增 hard id 但漏 SPEC ⇒ 默认红”，不能只在 `--strict` 红。

在这一步之前，`docs/147@integration/batons §七`、AS1 verdict 与 roadmap 中“ledger 含 #44、权威 committed CI”均应降级为错误/未证，而不是继续被后续 docs 引用。

### P1 — E1 当前单 lane 可运行，但合同既不保活，也不能扩到第二条 lane

可保留的部分：`_logi_import()` 只用整数 `day % every_days`、数组书写序和 `_stock_move()`；实际 applied amount 入事件，#38 对 import 取正号。当前一条柴薪 lane 的 deterministic stock effect 是真的。

不能接受的部分：

- `_logi_on()` 只看整个 JSON dictionary 是否非空；只剩 `_doc` 也算“开”。
- `lint_data.py` 不把 logistics 列为 required，也不校验 lane/node/good/cadence schema。
- #44 只审已经出现的 import；删除调用、空 lane、未知 good、`batch/every_days<=0` 会零事件、真空全绿。
- #44 分别建立 `node_ids` 与 `lane_goods`，不审 `(lane_id,node,good)` tuple；不审 amount 上限、due day、重复到货和漏到货。
- `Harness` 只把 import 数打印出来，没有 liveness lock。
- fixed batch 在 N 增大时人均作用趋零；N=16/24/60 只测 seeds 1–12，而 #40 源码自己的统计注释要求至少 48 seeds。现数据甚至出现 N=60 最差货 `0.564→0.543`，所以只能说“这 12 个 seed 没红”，不能说规模安全。

正确抽象应是 `LaneSpec` + `ShipmentAttempt/Arrival`：稳定 `lane_id`、origin/destination、good、scheduled_tick、requested/applied、outcome。#44 守每条事件的 tuple provenance；另一条完备性门守“每个 due 恰有一个 arrival 或具名 blocked outcome”。这才是以后载货人、消息 carrier、多镇交换可复用的 bridge。

还要补读档边界。现 save/projection 会自动包含 logistics，但现有 save tests 没跨过“读档后的下一次到货”：应固定测 tick 479/480/481 与 1199/1200/1201，并明确 snapshot 是冻结旧 config，还是加载当前 config；不能让反射 codec 偶然决定版本语义。

### P1 — 当前 E2a WIP 不应提交或重烘

本地 `agent-ac176…` worktree 已开始 external coin/price/#45，但有四个架构缺口：

1. `price_per/price_den` 缺失或非法会静默退回免费进口，而不是配置错误；E2 可被一处 typo 关闭且全绿。
2. `fit * 3 / 4` 逐批向下取整；cap 只剩一件货位时 cost=0，货先入库，`transfer(...,0)` 返回 false，#45 仍因 expected=0 而绿。这与“先付后到、无免费货”直接冲突。
3. 货先 `_stock_move`、钱后 `transfer`，没有单一 atomic trade reducer；未来任一中间失败会形成半笔交易。
4. 今天的 `pay` event 不记录 amount，也没有 tx/lane id。#45 只比较 `external_coin == Σ(import-derived expectation)`，不能做逐笔 1:1 对账，错单互相抵消也可过。

此外，`external_coin=0` 且要求非负意味着未来 export 最多只能花掉本局此前 import 收入；这不是“外部无限市场”，而是隐含的 session balanced-trade 规则。应先选择：有限外部 treasury，还是可为负的 clearing account；两者的不变量不同。

dirty held-out 的 seed 18 还暴露出另一条未拍板政策：进口仍一路付到 day 59，却出现 `wages_skipped=10`。这不是“穷镇进不起口”，而是**外部供应商优先于本地工资**；流动性冲击由工人承担。必须先定义 insolvency priority（工资准备金、进口限额、欠款/信用），并同时验 imports missed 与 wages skipped，不能看见 held-out 后把任一结果事后解释成 self-contain 成功。

E2 第一片应先把 money event schema 做成 `MoneyTransfer{tx_id,from,to,amount,reason,lane_id}`，再用同一 reducer 同步提交 money + stock，或显式 escrow/in-transit。没有这层，所谓 MoneyLedger/#36 无法从现有 `pay` 事件重放。

`docs/154@integration/batons` 所称“两路独立评审收敛”在仓内也不可审计：没有 committed prompt、输入 SHA、模型 build、五个独立 verdict 或 transcript。它可以作为 decision memo，不能作为 §0.8 独立性/覆盖证明。两路真正证明的是加一个 external account 后的算术守恒，不是流动性、优先级、原子贸易或多镇账户语义已经收敛。

### P1 — AO1 状态契约没有前进，仍阻断 lazy town swap

本窗 12 commits 没有触碰上一轮指出的 save-state 问题。`save_game` 仍反射 script variables，运行控制、配置与权威状态的分类仍由当前值类型和几个排除表间接决定；projection 只是从同一 blob 再折叠。新增 logistics 也被这种反射策略自动存入，使“存档冻结哪版配置”成为未声明行为。

因此“旅行即换页、冷热镇 lazy load”仍没有现成正确性条件。先做版本化 `PersistentStateSchema`：字段逐项归类 persistent authoritative / derived rebuild / runtime handle / UI-wallclock / diagnostic / build config，save、load、projection 共用它；再做 canonical bytes + 强 hash 与跨 due-boundary round-trip。否则多镇只会把当前单世界的不明确边界放大。

### P1 — AT1 是小幅 facade polish，不是完整建筑系统

### P1 — AR2 的小收益成立，但稳定性与事件语义各有一处明确错误

措辞去重肉眼有效，且没有进入 Sim/RNG；现有 AE1 test 也证明一组接受/拒绝模板没有把拒绝说成成功。但两处需在下一片前修：

1. `_pick()` 使用 `String.hash()`。同仓 `Sim.gd` 已明确记录：引擎内部 hash 可能随 Godot 小版本变化，所以 Sim 改用带测试向量的 FNV-1a。AR2 不影响 simulation golden，但会让同一 event_log 在升级引擎后重建成不同编年史文字。应复用项目稳定 hash，并加固定向量/variant-index 测试。
2. `betray` event 的 `subject` 是 secret id，`target` 才是被背叛的原托付者；AR2 的 `C!=empty` 分支却把 subject 解释成“听见秘密的人”。`_nm_opt(secret_id)` 当前通常返回空，所以错误分支接近死代码，但 schema 一变就会显示假叙事。要么删除该分支，要么显式在事件里记录 listener。

现 `event_prose_test` 仍只测 10 类的一组固定 hash 落点，不会枚举 19 类全部 variant leaf。应把每个 leaf 的成功/拒绝词、占位符和 subject 语义做参数化测试，避免“数组里第二条坏了但测试永远选第一条”。

部分新模板还写入 event 没有的事实，例如 greet 的“在路上碰见”、confide 的“挑了个僻静处/红着眼”、meet 的“聊得投机”；社交实际可在室内发生，事件又没有 location/emotion 字段。应让模板声明所需事实，没有 grounding 字段时只能选中性句。AR2 的核心承诺是多样性，但当前门连“把每组 variants 全复制成第一句”都抓不到；需要至少断言每个条件叶可产生两个 unique prose。

## 五、分阶段实施方案与第一刀

**第一刀：只改 complement tooling，不动 Sim、不重烘产品行为。**

### Phase 0B — 把 E1 从 stock injection 升为最小可追责 shipment contract

1. 定义并 lint `LaneSpec{id,origin,destination,good,batch,every_days}`；shipping profile 中 logistics required，测试关闭用显式 fixture/flag，不靠删出货文件。

4. 跑 N=12/16/24/60 的冻结 held-out ≥48 seeds，报 paired delta 与分布；加 479/480/481、1199/1200/1201 save/load/goto tests。

退出条件：删 import 调用或交叉接错 lane 必红；合法满仓不假红；跨 due 存读档逐字节一致。

### Phase 0C — 再做 E2，而不是给现 WIP 重烘

1. 先扩 money event：amount、tx_id、lane_id、account kind、opening balance；运行态和 replay 共用 reducer。
2. 交易以一个原子 command/event 同时提交 stock + money，或进入显式 escrow/in-transit；禁止“货先到、付款随后尽力”。
3. 明确定价取整：累积 rational remainder、整批定价或最小正价；正 applied 不得零成本。
4. 拍板 external 是 finite treasury 还是 signed clearing account，再写 #34/#35/#36；不要用 `external=0 且非负` 偷渡 balanced-trade 规则。
5. 先跑负对照/held-out，再决定是否移动三份 golden；未达成前不 bake。
