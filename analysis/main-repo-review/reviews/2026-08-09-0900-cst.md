### P0 — standing 漂移反号，使 E3b 的社会语义失真

`Sim.gd:1646-1654` 的注释是“名声每 3 天向 0 漂移 1”，实现却是：

```gdscript
r["standing"] = float(r["standing"]) - signf(float(r["standing"]))
```

这只在 `abs(x) >= 1` 时不会越过零。对所有小数增量：

```text
-0.20 -> +0.80 -> -0.20 -> ...
+0.20 -> -0.80 -> +0.20 -> ...
-0.35 -> +0.65 -> -0.35 -> ...
```

E3b 的糕点 `shortage_standing=-0.2`（`production.json:60-65`），`_shortage_fallout` 又确实把它写入观察者对 coco 的 standing（`Sim.gd:3492-3532`）。仓内 13–30 数据里糕点断供 9–34 天，绝非死路径。本轮在当前 Sim 上构造 `standing=-0.2` 并跨过 drift 日，直接得到：

```text
[CODEX_STANDING_DRIFT] before=-0.200 after=0.800
```

因此当前不能声称 shortage 产生合理的社会后果。问题不止糕点：其他货的 `-0.25/-0.35`、默认 `-0.5`，以及正向 craft credit 的小数 standing 都会振荡。

修法应是 `move_toward(x, 0.0, 1.0)` 或等价的 `sign(x) * max(0, abs(x)-1)`。但关键不是那一行，而是先落一个固定向量门：`[-2,-1,-0.6,-0.2,0,+0.25,+0.5,+1,+2]` 每次 drift 后绝不换符号、绝对值单调不增。旧代码必须先被这门打红；行为修复会改变大量长期轨迹，不得用机械重烘把变化直接合法化。

### P1 — E3b 是 object sink，不是人际 social treat

直接读执行路径：

- `production.json:79-88` 把所有名为 `闲聊` 的对象动作映射到糕点。
- 室外与室内的消费点是咖啡馆吧台对象；`闲聊` 经 `_advance_object`（`Sim.gd:1500-1572`），不是有 responder 的 `_advance_social`。
- 进入 use 的第一 tick 就调用 `_consume_for`（`Sim.gd:1510-1518`）；need 无论有无糕点都照补（`1565-1569`）。动作之后还可能被 survival pre-emption 清掉，所以能出现“货已扣、闲聊未完成”。
- 成功消费只扣库存并返回 true（`3463-3473`）；夜间把全天消费合成 `actor=town,target=town` 的总量事件，无法回答谁、在哪里、和谁吃了糕点。
- 缺货才写 belief/memory 并归罪 coco；糕点师不在正向 `craft_credit` 署名名单中，相关 produce/consume/shortage 又被 feed 隐去。

因此可构造“居民独自站在吧台旁，仍扣糕点并补 social”的合法路径。当前机制更准确的名字是：**咖啡馆对象使用附带的 luxury inventory sink，缺货时触发糕点师告警。** 若产品真的要“社交点心”，扣货应挂在一次被接受且完成的 social commit 上，事件携带 actor、partner、place、interaction id；负对照至少要守“独处不扣、拒绝不扣、被生存动作打断不扣、一次完成互动只扣一次”。
