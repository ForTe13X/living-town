## ★ 它顺手抓到的那条真发现（**不是注入，是野生的**）

**任何单 seed 的 `Harness` 跑法，`#40` 与全部软不变量按构造不可能变红。**

`game/bench/Harness.gd:313`：

```gdscript
return mini(int(ceil(float(n) * SOFT_RATE)), n - 1)      # SOFT_RATE := 0.90
```

`n=1` ⇒ `mini(ceil(0.9)=1, 0)` = **0** ⇒ 软门要求「≥0/1」＝**恒真**。
它那次 seed 18 的输出逐字：`#40 0/1` **而门印 `=== S0 GATE: PASS ✅ ===`**，
抬头写着 `软通过率门 ≥0/1(90%) 过`。

⇒ 这是契约 §2.5 第三个盲区（**判据跑在一个它守的事不可能发生的配置上**）的又一实例，
而它落在一个**人人都会用的跑法**上：`docs/71 §一②` 正是让人去复核 seed 18，
照最自然的 `--seeds 18` 跑，**读到的是 PASS**。
`n=12` 时 `mini(11,11)=11` 与「≥11/12」一致 ⇒ **CI 那一格没问题，问题只在小 n。**

### T2 独立复核，并把它推广了一档

我自己核了 `game/bench/Harness.gd:37`（`const SOFT_RATE := 0.90`）与 `:313`，然后逐 n 算：

```
n= 1  soft_min = mini(ceil(0.9)=1,  0) = 0     ← 恒真
n= 2  soft_min = mini(ceil(1.8)=2,  1) = 1     ← 实际 50%，不是 90%
n= 3  soft_min = mini(ceil(2.7)=3,  2) = 2     ← 实际 67%
n= 4  soft_min = mini(ceil(3.6)=4,  3) = 3     ← 实际 75%
n=12  soft_min = mini(ceil(10.8)=11,11) = 11   ← 恰好 = 90%
```

⇒ **B1 说的"问题只在小 n"是对的，但真正的机制比"n=1 恒真"宽**：
`n - 1` 这一项在 **n ≤ 11 的每一格上都是绑定项**，
所以软门在那整个区间里执行的判据不是「≥90%」而是「**最多允许一个 seed 红**」。
`n=1` 只是这条规则的退化端（允许唯一那个 seed 红 ⇒ 恒真）。
**它在 n=12 上与 90% 重合，纯属巧合**——而 CI 恰好跑 n=12，所以从来没有人撞见过。

⚠️ 这条**不在我的行里**（`game/bench/**` 是 T1 的），**我没有改它**，只把它量清楚记在这里。
