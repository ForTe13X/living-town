# v1 四臂：**作废**，因为隔离方式泄漏了答案

## 泄漏是怎么发生的

v1 的隔离副本是 `git clone --local --shared` 之后**把变异 brief `cp` 到工作区上**。
于是那份副本里：

```
$ git status
 M docs/71-wave-s-plan.md          ← 工作区已改、未提交
$ git diff -- docs/71-wave-s-plan.md
（一次性交出全部 10 条注入）
```

**两根棒的第一件事都是跑 `git status`。** 逐字（A1 回执 §〇 抬头）：

> `git status` 显示 `docs/71-wave-s-plan.md` 是 ` M`（工作区已改，未提交）。`git diff` 给出 **10 处改动**，
> 且它们**整齐地落在 5 个层各 2 条**……⇒ 这份 brief 极可能是 `brief_mutate.py inject` 的产物，
> 即 S2 交付的那个分母实验的**前瞻注入**那一半。

A2 独立地做了同一件事，逐字：

> 另外：**`docs/64-wave-q-plan.md` 在工作区是被改过的**（`git status` 显示 ` M`）。
> `git diff` 显示相对 HEAD 有 **8 处改动**，下面 B/C/D/E 组里的问题**全部**落在这 8 处里。
> 查法：`git diff -- docs/64-wave-q-plan.md`。

⇒ **它们不是"发现"了注入，是被递了答案。** v1 测到的是"棒子会不会跑 `git status`"，
不是"棒子能不能核出 brief 里的假断言"。**四臂全部作废，一个数都不进分层表。**

**C1 臂（提法对照）也漏了，而它本来是用来量"不宣布"值多少的。** 逐字：

> 工作副本里 `docs/64-wave-q-plan.md` 相对 `HEAD` 有未提交改动，**10 条注入的错误全在这个 diff 里**。

⇒ **连一根被派去"出实施方案"、根本没被要求找错的棒，也是先跑 `git status`。**
这条本身是个有意思的观察（它说明 `git status` 是这些棒的开场白，与任务无关），
但它把 v1 唯一一个用来量"宣布效应"的臂也毁了。

A1 还顺带指出第二个设计错误：v1 的派棒 prompt 说"三根棒动手之前"，而树上 HEAD 是
`d13f448`、`docs/72/73/74` 都已存在 ⇒ **"动手之前"这个前提本身就是假的**，
一根认真的棒会先撞上它。v2 的 prompt 改成了"这一波已经合流，做一次事后核对"。

## v2 的修法

`mk_iso2.sh`：`git archive` 出无历史快照 → 覆盖 brief → `git init` + 一次 import commit。
`git status` 干净、`git diff` 为空。**代价**：`git log -S` 在 v2 副本里查不到东西（只有一个 commit）——
这条写进了局限，因为契约 §1.5 那条纪律在 v2 的棒身上结构上不可用。
