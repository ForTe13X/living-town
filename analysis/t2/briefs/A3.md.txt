## 一、为什么是"社会产出"——先说清现状，别在推断上盖楼

**实测（以代码为准，不是设计文档）**：`game/data/jobs.json` 给每个居民一个 `{title, action, wage, shift}`，
`Sim.gd:1281-1300` 在有薪动作完成时由**镇库**发工资，`_wage_for` 让本职在班拿职位工资、其余人拿零工价。
经济闭环是 `吃饭付费 → 镇库 → 做活发薪`，由硬不变量 **#34（金钱守恒）** 与 **#35（余额非负）** 守着。

> **★ 所以现在的分工只有【行为】没有【产出】：木匠"做活"什么也没造出来，面点师"做活"没有面包被谁吃掉。**
> ~~**把全镇的工作行为全部删掉，除了钱包数字，世界逐格相同。** 劳动是**装饰性**的。~~
>
> **⚠️ 删除线那句是我写错的，E1 实测撤回（2026-07-28）。** 行号对（`Sim.gd:1281-1300`，现为 `:1309-1328`），
> 结论过头了。今天一次本职工作已经写了三样**非钱包**状态：
> ①`ag["skills"][action] += 1`（`:1313-1319`）——60 天终态实测 aria 5-7、ben 12-14、dan 10-18、hai 8-13、lin 5-16、shu 14-17 级次，**不是零**；
> ②两条记忆（"上工…挣了 N 个钱"、升级里程碑），进 voice grounding；
> ③而技能经 `_wage_for` 加薪、工资经 `poor_line` 的 `work_urgency` 加分**反过来改决策**（`_object_candidates:1504-1506`）
> ⇒ **删掉工作，agent 的行走轨迹就变了，不只是钱包数字。**
> **真正缺的是「物」**：没有东西被造出来、被别人消耗、缺了有后果。方向对，措辞会让人以为工作是个 no-op 分支——它不是。
> 这正是本波要改的那一件事——也是"商贩/环卫/建筑各有 behavior 和社会产出"这句话的落点。

**必须一起说清的边界**：钱在本项目里的设计意图是**造分化与戏剧，不造饿死**（`economy.json` 的 `_doc` 明写：
付不起照吃 `meals_free`）。**产出系统必须继承这条**——缺货可以让人不满、可以造成八卦与冲突，
**不得**成为新的饿死通道。硬不变量 #01 是硬的。

### E1 · 劳动产出与消耗闭环（**本波核心，会移动金标**）

**独占 `Sim.gd` + 新 `game/data/production.json` + `Invariants.gd` + `golden_digests.json`。不得动 `Main.gd`/`WorldView.gd`（E2/E3 在用）。**

**做什么**：让"做活/看摊"产出**具体的东西**，让别人**消耗**它，让**缺货有后果**。最小闭环建议：

- **产出**：本职在班完成一次工作 → 往一个**镇级库存**里加一件（面点师→面包、木匠→木料、商贩→货、环卫→"整洁度"）。
- **消耗**：既有动作去扣它（吃饭优先扣面包；修缮/建造扣木料；整洁度随时间衰减、环卫补）。
- **后果**：缺货**不造成饿死**（红线：`meals_free` 那条设计意图继承下来），而是造成**可观测的社会后果**
  ——不满、议论、声誉变化、或某个动作变贵/变慢。**后果必须写进 `event_log`**，否则 E2 讲不出故事、编年史也看不见。

**数据驱动 + 缺文件即零扰动**（照抄 `jobs.json`/`economy.json` 已经验证好用的那套）：
`production.json` 缺失 ⇒ 产出系统整个关闭 ⇒ **逐字节回到今天的轨迹**。这条本身要有一个断言。

**验收（R12 全套，一条都不能省）**
- **零扰动对照**：删掉 `production.json` ⇒ 金标**逐字节等于今天**。**这是最重要的一条**，它证明新机制是可 ablate 的。
- **开启后**：`Harness --bake-golden` + `DetGate --bake-golden` 都跑；`_meta.rebake_history` 补一条。
- **留出种子**：改前/改后各跑 `--seeds 13-30 --days 60`，**两侧数字都报**。硬不变量必须 18/18 全绿。
- **硬不变量 #01 不许破**：报**逐 seed 的饿穿计数**，不是"没看到饿穿"。
- **#34 金钱守恒不许破**：如果产出涉及买卖，`transfer` 仍是唯一通道。
- **新增至少一条不变量**守着新机制（例如"库存非负"、"产出/消耗账本可溯源"），并给它一个**负对照**证明它会红。
- **R9**：能证明的是"劳动现在改变世界状态"，**不是**"游戏更好玩了"。

## 三·六 ★ E2 回执——**我当成旗舰的那条弧，一次都没发生过**

⚠️ 注意：`tools/ci.sh` 的视觉门会覆盖这一条，改坏了它会在第 6 步变红。

`Story.gd`（新）是对 `event_log` 的纯 fold，产出**有始、有中间节拍、有结局**的因果弧，四类（grudge / promise / secret / pact）。
面板走 K 键、与小镇纪事**共用同一块左上角**（互斥，零新增屏占）；feed 只在**弧收束时**弹一条

**这份 brief 哪里是错的——四条，第一条最重要：**

2. **「或 → 冷战 → 泄密 → 背叛」那条分支：`betray` 与 `leak` 在默认沙盒 60 天里是 0 事件——不是稀有，是零。**

3. **「引擎已经产出那些链」半对**：grudge 与 promise 链**大量**产出，**我点名的那条不产出**。
4. **「必须复用 `Sim._verb`」——它没有复用，理由成立**：`_verb` **对 `conflict`/`meet`/`pact`/`betray` 根本没有条目**

**被它自己的测量杀死的四个假设**（值得记，全是"看起来很有道理"的那种）：

## 三·八 ★ E4 回执（W8）——那条断言**早就在 CI 里，而且是绿的**；它跑在一个刚出生的世界上

**W8 属实，且比 E2 说的更早、更大。** 用 `--obs-fit`（新，Main.gd）逐个居民 × 两档量**真实控件**的
`get_content_height()`（**不自己数行**——自己数行会复刻 W8 本身那个错误）：

| 树 | 网格 | 溢出 | 最坏 |
|---|---|---|---|
| 未修 | 12 居民 · 第 5 天 | 5/12 | 799px / 可用 664px（**−135px**） |
| 未修 | 60 居民 + 玩家 · 第 30 天 · 两档 | **60/122 格** | 853px / 664px（**−189px ≈ 10.5 个视觉行**） |
| 已修 | 同上 | **0/122** | 637px / 664px（**+27px**） |

**根因**：`OBS_MAX_LINES` 数**逻辑行**，面板截**视觉行**，中文还会折行。
**修法**：版式预算改成按**量出来的像素**排（`Main._obs_fit_lines`），排不下的**写在末行**而不是静默掉出去
（与 `Story.panel_text` 同一条纪律）；信念长尾的额度也改成按剩余像素算。
留 **2** 行余量而不是 1：`_obs_rows` 算的是 `ceil(裸宽/可用宽)`，而 RichTextLabel 的 `AUTOWRAP_WORD_SMART`
在中英混排行上**可能提前折** ⇒ 我这个估计是**下界**。只留 1 行时实测最坏余量 +9.0px（半行），留 2 行后 +27.0px。

**代价（R11，实测 `--obs-fit` 打印）**：排一次完整卷宗 **406µs（基线）→ 498µs（+23%）**。
中间还踩了一脚：第一版的 `_bb_strip` 是 GDScript 逐字符拼串 ⇒ **604µs**，换成编译一次的 `RegEx` 回到 498µs。
+92µs × 12.5 tick/s = **+0.115% CPU**。

### ★ 这份 brief 哪里是错的（W8 部分）——**这一条是本棒最值得记的**

**W8 的断言 `player_touch_test.gd` 里【本来就有】，叫「完整卷宗装得下」，用的就是 `get_content_height()`，
而且它在 CI 里一直是绿的——面板同时在溢出。**
原因是它跑在一个**刚开局**的世界上（`aria`、tick≈0：没有冲突、没有记忆、信念寥寥），那一格无论如何都装得下

的又一例，而这次那个"什么都不做"是**世界还没长出内容**。写视觉/版式判据时要多问一句：
**你的 fixture 有没有长到能触发你要防的那件事？**

## 三·九 ★ E5 回执——W1-W8 收口；**它先造了量具，然后用量具证伪了我给它的七个数字里的五个**

**量具本身比结果更值钱。** 此前本项目每一个 ΔE00 都是**锚点对锚点**；真正到达帧缓冲的东西是
**alpha 合成 → 季节色调 → 大气罩 → 昼夜乘暗**。E5 把这条链**标定**出来，而不是推导：

- **合成律是标定的**：在引擎里渲 63 个已知色块 × 3 个昼夜档再读回来 ⇒ `out = a·src + (1−a)·dst`
  **在 sRGB 码值上**成立，逐通道最大误差 **0.84**（舍入）。**线性空间混合被证伪：误差 73.23。**
  乘暗与合成**可交换**。
- **整条链在真帧上验过**：纹理 → 季节 → 大气罩 → 昼夜，四张 `--shot` 帧的草地**误差 0 个码值**，
  并且能预测道路与水的众数。它**量出**seed 3 / 第 3 天是春/阴，而不是假设。
- 三条此前没人建模的保真事实：大气罩**只覆盖 town 分支**（室内家具从不被罩）；
  区块地板是 `base@0.80` 压在**泥土**上（它第一版按草地算错了，逐行重读时自己抓到）；社交层画在罩**之上**。

### E4 · 回放安全到底覆盖到哪（W1）+ 档案面板溢出（W8）

**独占 `Goals.gd`、`Story.gd`、`Main.gd`。**

**W1 是这批里唯一可能推翻已发布结论的**：README 与 docs/46 都写着"回放安全 30/30 seed"，
而 `goals_test` / `story_test` **都钉 `Sim.backend = null`**。评审指出三条它们够不到的路：
① `Sim.goto_tick` 会置 `replaying = true`，而 `AIBackend.gd:788` 是 `if backend == "logic" or Sim.replaying`
⇒ **重演永远走 logic 地板** ⇒ 非 logic 后端下拖时间轴会**重新生成一段不同的历史**；
② **玩家事件计入 `Goals`（`NON_AGENT` 不含 `"player"`）却不在重演里**（`Sim.gd:911-912` 自己写着"玩家的历史干预不在重演里"）；
③ **前向拖动不重置**——`Goals.sync` 只在日志**变短**时自重置，而 `]` 是 `goto_tick(tick+240)`，日志**变长**
⇒ fold 从 `_cursor` 接进一段**前缀已经不同**的日志，`chain` 于是见证一个**从未存在过的序列**。

**先量，再决定改代码还是收窄措辞——不要直接改措辞了事。**
建议顺序：先给 `goals_test`/`story_test` 各加一条**能证伪**的臂（非 null 后端 + 有玩家 + 前向拖动），
看哪一条真的红；红的那条再决定是修（例如任何 `goto_tick` 都强制 `reset()`）还是限定声称范围。

**W8**：档案面板**在 E2 改动之前就已经溢出**——`OBS_MAX_LINES` 数**逻辑行**、面板截**视觉行**、中文还会折行。
E2 留了改前图为证。修法自便，但**必须给一个断言**：在最坏的一档（玩家模式 + 展开档 + 长选举串 + N=60）
内容高度 ≤ 可用高度。

**验收**：金标逐字节不动；两个 test 场景绿；W8 给出改前/改后的**内容高度与可用高度**两个数字（不是截图印象）。
