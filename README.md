# 小镇有灵 · Living Town

[English](README_EN.md) · [文档索引](docs/README.md)

[![CI](https://github.com/ForTe13X/living-town/actions/workflows/ci.yml/badge.svg)](https://github.com/ForTe13X/living-town/actions/workflows/ci.yml)

像素小镇生活模拟原型。居民有需求、记忆、性格和关系，会赴约、爽约、争执、和解，也会形成声誉与派系。底层是一套确定性的社会引擎；本地 LLM/SLM 只负责把引擎给出的合法候选转成台词和选择。

模型不可用时，游戏仍然运行。断网、超时或非法输出都会自动回退到规则决策，因此接入模型只改变表现层，不改变世界状态的可靠性。

## 当前状态

下列**世界与社会系统**都已出货，且各自有 CI 门守着——点名不变量编号的由 [`game/bench/Invariants.gd`](game/bench/Invariants.gd) 守，其余由 [`tools/ci.sh`](tools/ci.sh) 的数据 lint / 地图审计 / **三道美术门**（步骤 2b·2c·2d）/ 台词门 / 9 个集成场景守。末三条（外壳、后端、推理延迟）是实测记录，不是不变量。

- **确定性社会底座**：打招呼、赠礼、八卦、邀约、对质、道歉、关系账本、知识边界、承诺、冲突和解决流程。关系变化能追溯到事件，因此系统能解释一个居民为什么生气或信任某人。
- **一座生成的小镇**：64×48 网格、8 个功能区，**walkability 是权威数据**，寻路是确定性 A\*。`tools/audit_map.py` 是专为此设的 CI 门——校验 typed-layers 自洽、全图可达、每件家具都有可达的交互格、区间有 ≥2 条路线，以及节日当天 spawn 的机会地形同样落在合法可交互的格子上。
- **多层室内**：七栋楼都有数据驱动的内部（`game/data/interiors.json`），居民真的会进屋、上楼、回家睡觉，不是贴图。
- **工作、班次与工资**：`game/data/jobs.json` + `skills.json`，技能等级影响工资。
- **分工有自己的地方**：木匠/杂役/渔夫/教书先生/泥瓦匠等各有自己的工位（`production.json` 的 `worksites`，每个工位挂着自己的 `advertises`），商贩把镇级库存转成个人可买的货（实测 **141-165 次 `transfer`/seed/60 天**，约占全镇饭口 **15%**），环卫工按整洁度自己成环（广场干净就去玩，脏到约 **45%** 以下去扫）。
  **G3 之后还有了第一条"货由货做成"的链**：屋瓦要烧、烧要柴薪，而柴薪同时被澡堂和瓦窑抢——**镇上第一件被争夺的资源**（`production.json` 的 `produce.泥瓦匠.inputs`）。
  短缺**不是一个库存告警而是一件社会事件**：屋顶漏了没瓦补，居民会**记恨到具体的人**，那个人的声誉随之下滑（`shortage_standing`）。
  ⚠️ 这条链上的**配方与产量数字这里一律不给**——它们正被"双尺度"改动中，见「还不到位的」里那条。白话版见 [docs/56 §二/§三](docs/56-阶段报告-给非技术读者.md)。
  > 这一条曾经是假的，而且是**眼验过之后仍然是假的**：全镇**每一次**「做活」都发生在**同一格** `desk_1[40,31]`（152-186 次/60 天），四个岗位共用它——包括**在雕刻台上打渔的渔夫**；而那批新工位的 ID 命不中任何精灵槽，**一直以占位框出货、把原始数据键印在草地上**。两条都是后一棒实测捞出来的。见 [docs/48 §一·五](docs/48-wave-f-plan.md)。
- **一套货币经济**：价格、工资、镇库、贫困线。由**硬**不变量 #34（金钱守恒）与 #35（余额非负、不可透支）守着。人→人的钱不止商贩：`transfer(房客, 房东, rent)` 每夜都在跑，`housing.json` 里有 **8 组在册租约**（[docs/48 §一·五](docs/48-wave-f-plan.md)）。
- **天气与季节**：`game/data/weather.json` 的类型与效用乘子。
- **节日**：世界对象按期生成/回收，硬不变量 #36 守"配对无残留"。
- **选举**：周期性投票，硬不变量 #37 守计票自洽。
- **涌现的社会层**：声誉与八卦级联、观点派系、互助盟约（含 GTFT 宽恕与 free-rider 解体）、秘密的吐露/泄漏/背叛。
  > **这里有两条是 Wave O/Q 才真正成立的，此前是"有机制、无效果"**：
  > ① **八卦级联此前止步于第 1 跳**——`greet` 对同一伙伴无条件发出且分数**严格支配** `gossip`
  > （非爱八卦者在 **25,567** 次机会里赢 **0** 次），而 12 个人设只有 1 个爱八卦 ⇒ **没有人能中继**。
  > 修好后 R1 的知晓人数 N=12 从 2-3 → **7-11**、N=60 从 2 → **53-55**，最深跳数 1 → **9-12**
  > （`def63e7`，[docs/61](docs/61-wave-o-plan.md)）。
  > ② **观点派系此前是"读心"结成的**：只改一个 agent 的私有 `attitudes`、零事件零信念，
  > N=60 下**一夜之间 60 人里 16+ 人被重贴标签**。加接触门后，从未谋面的对**逐字节零影响 25/25**
  > （`7dc8cd9`，[docs/66](docs/66-faction-contact-gate.md)）。**代价与只修了一半的边界见「还不到位的」。**
- **可玩外壳**：昼夜光照、时钟与速度控制、NPC 头顶台词和表情、玩家与 NPC 自由对话、回放观察台。可以在任意 tick 检查居民的需求、信念、关系和冲突。
- **三档 AI 后端**：`logic` 纯规则、`llm` 本地 OpenAI 兼容服务、`slm` 通过 NobodyWho 做嵌入式 GGUF 推理。所有后端运行同一套引擎，并能安全降级。
- **本地推理实测**：Qwen2.5-1.5B-Q4 在测试过的消费级 GPU/APU 机器上约 1-2.5 秒完成一次决策；3B 约 2.9 秒。启动探针按当前机器测得的延迟设置 deadline。

## 技术难点与创新

**1. 确定性 + 观察无关：世界怎么活，不取决于你在看哪。**
决策逻辑里没有墙钟、没有全局随机——所有随机由稳定派生的 `seed + tick + salt(+agent)` 决定（不依赖墙钟或全局 RNG），同一 seed 逐字节一致，回放观察台能从任意 tick 精确重建世界。

> **这句话的适用范围是量出来的，不是推的**（2026-07-30 复核）：它成立于**零模型 logic 地板 + 无玩家介入**——
> 该配置下 `goto_tick` 逐字节复现同一份 `event_log`。**换成非 logic 后端、或玩家已经入镇之后，拖时间轴重建出的是【另一段】历史**：
> 重演期被强制走 logic 地板（`AIBackend.gd:788`），玩家的历史干预也不在重演里（`Sim.gd:939-940` 自己写着）。
> 实测 8 天 · seed 1：`random` 后端 live 346 事件 → 重演 363；玩家在镇 live 376 → 重演 363（= 无玩家那一份，逐字节相同）。
> 派生视图（小镇纪事 / 小镇故事）**永远是当前 `event_log` 的纯函数**，它们不引入额外自由度；变的是那份 `event_log`。
> 逐条证据与永久门见 [docs/47 §三·七](docs/47-wave-e-plan.md)。

更强的一条红线：**渲染可以跟随相机，但决定"精细模拟谁"的仿真分级不能依赖相机**——否则同一存档不同看法就会回放出不同历史。这条"观察无关"贯穿整个引擎。

**2. 观察无关的聚合 LOD（本阶段核心工作）。**
要把镇子扩到数百人，必须对远处居民降精度；难点在于常规 LOD 按相机远近降级，会让历史依赖观察路径、直接击穿上面的确定性红线。这里做了一个**观察无关的聚合 LOD**——满帧 cohort 完全由 committed 仿真态选取（谁在做事 / 无状态轮转 / 玩家近旁），绝不读相机（唯一按相机半径降频的旧保守分支只用于 bench 诊断、不参与出货）。经六项验证：逐字节 default-off、**相机路径无关**（5 个固定 `lod_focus` 值 → 同一 digest）、存读/fresh-vs-restart 确定、规模硬不变量、诚实成本、liveness floor；其中【相机路径无关 + 确定性】两项已并入 CI 作为永久门。
> 诚实标注：这是一个**观察无关原型**，不是"已交付数百 NPC"。真机微秒实测：**sim-tick(~64ms) 与逐-agent/社交绘制(~60ms) 是两大成本**（合计约占单帧 ¾），其余为每帧开销与少量静态重绘。LOD 只砍 sim-tick 那块、不是充分解——另一大块要靠渲染裁剪。方法论上的教训（记在 [docs/33](docs/33-viewer-independent-lod-delivery.md)）：**别推断瓶颈，埋计时器测**——我曾三次凭直觉判错单一瓶颈；即便如此，复盘时我仍把没测的第三块顺手标成"静态重绘"，靠 N=12 整帧只 11ms 的上界才自己抓出这个过度归因。
> 真机上的当前读数（Wave C 的音频/触屏 + Wave D 的夜光/帧时 + Wave E 的产出闭环与调色板**第一次一起跑**）：
> 第 48 天 · **冬 雨** · ×1 · NPC 12 · 事件 2033 · 冲突 87(活 44) · 绘制 2903 · 节点 97 · 内存 85MB
> ⇒ **FPS 83 · 12.0ms**。对照：帧时那一棒之前，同类深度是 **11 FPS**。
> **这个读数仍压在约 90Hz 的刷新率天花板下**，所以它是"够用"的证据，不是余量的证据。（[docs/48 §二·一](docs/48-wave-f-plan.md)）

**3. 决策与表达解耦：模型永不改写世界状态。**
引擎枚举合法候选，模型只读候选与上下文、返回一个候选 index + 可选台词；世界推进完全由确定性引擎负责，模型永不直接写状态。非法输出 / 超时 / 无模型都安全回退到规则决策。表现层可换（罐头台词 / 本地 SLM / 云端 LLM），世界的可靠性不变。

**4. 涌现的社会动力学。**
八卦把第三方声誉传播开 → 形成共识 → 可能演成集体疏远；观点分歧结成派系；互助盟约带 GTFT 式宽恕。这些不是脚本，而是规则交互涌现的，且每一步都能溯源到具体事件——系统能解释一个居民为什么生气、为什么信任某人。

**5. 不变量回归门 + 影子反事实探针。**
CI 默认 12 seed × 60 天检查 **40 条**社会不变量（信念来源、承诺结算、金钱守恒、私聊边界……），
**25 条硬 + 14 条软 + 1 条诊断**。**权威清单是代码**：[`game/bench/Invariants.gd`](game/bench/Invariants.gd) 的 `HARD_IDS` 与 `DIAG_IDS`（这三个数就是数它们）。
更进一步，"影子探针"在**不改变轨迹**的前提下测量一个干预到底翻转了哪些决策，把"机制到底有没有用"从轶事变成可量化的数字。
> 诚实标注：其中 **#15「涌现放逐」是已知有缺陷的指标，只报不门**——它用终态声誉挑人、却用全程日志算接受率（时间泄漏）。修掉泄漏后的 #15v2 在 126 个 seed 上全部 INCONCLUSIVE，所以结论是**不加机制**、也不拿它当门。全链见 [docs/31](docs/31-15-resolution.md)。

**6. 端上 SLM：从 16GB 泄漏到手机上真的产出决策。**
在真机（红魔 8 Elite / Android 15）上，`backend=slm` 曾经是**发起 40 · 成功 0**，Native Heap `3 → 7.5 → 16GB` 无界涨直到 OOM。
- **根因不是它看起来的那个。** 第一版结论"Adreno GPU Vulkan 特定"**被我自己的后续测试证伪**——那次只测了最小冒烟路径。补一个跑真·游戏内决策路径的 bench 后，桌面 AMD Vulkan 上同样段错误，panic 直说 `access to instance after it has been freed`：真根因是**每次决策都新建一个 worker、在飞时 free**（use-after-free）。桌面模型快→free 抢在回包前→崩；手机慢→worker 释放不掉→泄漏。**同一个 bug 的两张脸。**
- **治法**：全局养一个池化的持久 worker，串行、绝不 mid-flight free，回包按 epoch 作废。**真机满负载复验**：Native Heap 峰值 3.2GB（加载时）→ **217MB 封顶不涨**，跑满 13 个模拟日、**0 崩**、FPS 88-91。
- **然后是第二次翻盘**：剩下的"手机不产出决策"也**不是挂死，是太慢**。加了延迟埋点才分得清——真机 A/B 显示 **Adreno GPU 满负载在飞解码 ~16-20s**（渲染器和推理抢同一块 GPU），而 **8 Elite CPU 只要 ~3-8s（暖）**。于是**安卓上默认改用 CPU 推理**，端上决策这才真正落地。
- **诚实的分母**：**不能**说"手机上 2/3 的 NPC 决策由端侧 SLM 驱动"——那是 landed/**fired**，换了个方便的分母。worker 严格串行，它本身就是镇级吞吐的上限。用诚实分母（实际落地的决策数）实测：桌面 **16.1%–62.3%**，随阵容规模与解码速度变化两个数量级；手机那一次运行约 **2%**。见 [docs/35](docs/35-slm-decision-share-and-lod-soft-gate.md)。
- **最不舒服、但最该写在这里的一条：`landed` ≠ `drove`。** 模型落地的编号，可能正好就是引擎自己会选的那个。于是我们做了 shadow 对照——在**同一份冻结候选集**上同时算出引擎基线，看两者到底有多少不同（Δ/C），并与**同配置的均匀随机零假设**对照。结论：**模型确实改变了决策（Δ/C 15%–55%），但改得与随机挑不可区分**——Δ/L 与随机零假设相差 ≤1.4 个百分点，分数序位 0.41–0.54（随机=0.50），而在引擎自己的效用轴上**比随机还多丢 0.6%–11.2% 的效用**。同一套仪器对 mock 鹦鹉给出的读数落在另一侧（序位 0.012–0.017、保住 97% 效用），所以这不是仪器的问题。
  **该怎么读**：这**证伪的是"模型让决策更好"**，不是"模型没用"——引擎的 `score` 是启发式而非真值，本项目的设计意图本就是**风味与声音**而非效用最优（模型只能在合法候选里挑，永远改不了世界状态）。但任何"更聪明/更合理的决策"的说法，目前**没有证据**。全文见 [docs/36](docs/36-model-influence-delta-over-c.md)。
- **于是我们把零假设做成了可运行的对照，再问一次：决策路到底值不值？** 加了一个确定性的 `random` 后端，并做**剂量配平**（模型因串行+延迟只驱动约 62% 的决策，同步随机驱动 100%——不配平就只是在量"模型慢"）。结论比上一条更不客气（[docs/38](docs/38-does-the-decision-path-earn-it.md)）：
  - 模型**确实**能与随机区分——但**没有一条差异指向好的方向**。在本设计自己声称的那条轴（行为多样性）上，它**输给随机数发生器**：logic 10.89 → slm 11.56 → random 13.84。
  - 它把小镇**去社交化**得比随机更狠：社交动作占比 29.4%(logic) → 17.2%(random) → **12.2%(模型)**；`gossip_rep` 7.2% → 0.5%。
  - **那点差异不是判断力，是位置偏好**：模型的选号直方图塌成了**位置分布**——`index 0` 在 3285 次里被选中 **0 次**、30% 压在 `index 3`。把这个直方图喂给一个**对内容完全无知**的采样器，它复现了模型的两条头条差异（p=0.24 / 0.25）。
- **🔄 后续更正（同日，[docs/42](docs/42-prompt-pathology-or-capability-ceiling.md)）：上面那两条结论对**当前出货的 1.5B** 成立，但**成因大半是可修的**，不是"端上决策做不到"的证据。** 用同一套 prompt 在 4090 上跑大模型对拍（5290 个真实决策点、判据与解析逐行复用、零假设解析计算）：
  - **31B 明显在读内容**：分数序位 **0.276**（随机=0.495、完美鹦鹉=0.000），效用保留 +0.538，p=0.0078 且 8/8 seed。**所以任务编码本身是可读的**——不是一个坏任务。
  - **1.5B 守恒的是"位置"而不是"内容"**：打乱/反转候选顺序后，它的槽位峰值始终停在 3、**槽位 0 恒为 0.0000**；而 31B 反过来守恒内容。冒烟枪是 system prompt 里那句示例——**"如 3 或 A"**：删掉它，index-3 的概率质量掉 62%；改成"如 0"，选中 0 的比例涨 24 倍。
  - **于是"饿穿"有了机制**：`index 0` 在 **74.8%** 的情况下就是"吃饭/睡觉"。生存动作占比——引擎 36.9%、31B 42.1%、随机 18.5%、**出货 1.5B 仅 4.8%**。**agent 饿死是因为模型从不选第 0 项，而第 0 项通常正是"去吃饭"——这是格式 bug，不是能力 bug。**
  - **而且我们一直在测一个代码并不想用的模型**：`AIBackend.slm_model_path` **本来就默认 3B**，是安卓的 `_resolve_model_path()` 把它绕过了。3B **没有塌陷**（accept 85%→100%、选中 0 的比例 0.00%→18.4%）。
  - 诚实的另一半：**修好格式并不能给 1.5B 买到判断力**（八种改法下序位始终 0.46-0.50）——所以"1.5B 到了能力天花板"同时也是真的。**两件事同时成立。**
  - ⇒ 下一步不是蒸馏，而是**先切到代码本就默认的 3B + 修那两条 prompt 字符串**，然后把 docs/36/38/40 的测量**全部重跑**。

- **⚠️→✅ 一条出货阻断项，也是 CI 结构性看不见的（已修、已加门）**：`backend=slm` 下硬不变量 **#01「无饿穿」在 8/8 个 seed 上被违反**（同配置 logic 是 0/8）。因为 CI 钉 `Sim.backend=null`，**当时模型路径上的硬不变量从未被任何门检查过**（这一条已由下面的 4d 部分补上，边界见「快速开始」的诚实标注）。已排除犹豫/串行化（`mock` 在同样的延迟与空转率下不饿死任何人）——是**选择本身**让 agent 不去吃饭。
  **根因不是"模型选得差"，是引擎少了一条边界**：引擎的生存保护里，只有"危机时摘掉社交候选"那一层是**禁令**，另一层（urgency 主导的打分让吃/睡胜出）**只是打分**——对"在同一候选集里按下标挑一个"的外部后端完全无效。#01 是**硬**不变量，不该建立在"后端会自觉挑对"之上。
  修法是两条**只长在外部后端分支上**的引擎边界（危机中只放行救急的选择 + 这趟差事的车费需求预算付不付得起），并新增 CI 步骤 **4d `BackendGate`**：用**确定性**的 `random` 后端（选号来自项目自有种子流、时延按 tick 计 ⇒ 逐字节可重跑，门自己每次都机检这条）在两档剂量上守 #01。实测 8/8 红 → **8/8 绿**，12 seed × 20 天 24/24 绿，N=48 下也是 0 饿穿；**金标一个字节没动**（`backend==null` 时那两条边界永不被调用）。代价：出货剂量下护栏动了 **7.3%** 的落地决策（有效 L/C 63.8% → 59.1%），多样性不受影响。全文见 [docs/45](docs/45-external-backend-invariant-gate.md)。
- **代价也说清**：CPU 推理活跃时 FPS 从 88 掉到 34-46。另一项此前没被计入的代价：等待期间 agent 会空转——N=12 下 5453 次询问里有 2835 次什么都没落地，**模型让小镇更"犹豫"**。
- **顺带修正一个我们自己的指标缺陷**：此前四处引用的"bad_parse 29–36% = 模型格式不遵从"是**混淆**——它把"模型回了 prose"和"回答有效但等待期间世界变了(候选过期)"算在了一起。拆开实测：真实格式不遵从 **7.5%–19.4%**，且**随镇子变大而下降**（世界翻动更快 → 更多有效回答过期）；N=60 时**三分之二的表观模型失败其实是陈旧**。这一点仓库其实 6 月就测到过（[docs/11](docs/11-LLM部署实测对比与选型.md) §S5：「合法率损失的主因是异步陈旧，不是模型错」），后来被写丢了——现在补回。

全文与全部实测表见 [docs/34](docs/34-slm-device-hang-leak.md)；出 APK 见 [docs/18](docs/18-android-apk-build.md)。

**7. 把"数字要有零假设"这条纪律用到画面上——以及为此付出的代价。**
这个项目一直用不变量门和零假设来管**仿真**，却从没把同一条纪律用在**视觉**上。2026-07-26 的一波并行改造把账算清了：

- **量具本身是坏的，而且没人知道坏了多久。** `--shot` 截图**永远渲不出昼夜**——`CanvasModulate` 建出来是白的，
  而日光曲线只在三个回调里施加，截图路径把 `auto_run` 关了，三条路一条都不走。
  证据是两张历史截图：HUD 一张写 `00:38 夜`、一张写 `12:00 昼`，**主草地色逐字节都是 (133,166,67)**。
  ⇒ 在此之前，本项目所有"画面偏亮/偏暗"的判断都不可信。修它的那一行现在由**本仓库第一条视觉门**守着，
  而那道门**探不到渲染环境就 SKIP**——*一道在别人机器上因环境变红的门，比没有门更坏，它训练所有人忽略红色。*
- **★ 六条验收判据被执行它们的子任务当场证伪，六条全是派任务者写的。** 例如「四季两两像素 diff 必须不同」
  在**未改动的树上就全过**（居民每天都在移动）；「面板边缘 16px 剖线的最大跃变」有 **8px 落在地图内**，
  而界内像素画本身就有约 130 的跃变 ⇒ **指标有地板，修好后只从 131.54 动到 129.93**；拆成"跨界/界外/保真度"
  三个量之后，同一份改动立刻显出 **131.54 → 2.92（−97.8%）**。
  **一个报不出成功的指标，和一个什么都拦不住的指标，是同一种失败的两面。**
  沉淀成一条可执行的规矩：**写下任何视觉判据之后，先问一句"一个什么都不做的改动能不能通过它？"**
  > **但"六条"这个数字要打折**：外部对抗评审用本项目自己的规矩（"相关症状 ≠ 独立证据"）反打回来，说得对——
  > 那更可能是**同一个上游错误被复制了六次**（没先定义"干预→观测→归因"的链条，就直接在最终截图上找一个数），
  > 而不是六种彼此不同的判据设计失败。**前者是一条可修的规矩，后者是一份虚增的统计重量。**
- **连验收取景都可能把问题藏起来**：指定的全镇取景下，信息面板大部分压在地图**之外**的背板上
  （文字带背景 29.4/255），而在玩家真正会看到的跟随相机下是 **102.3/255**——只看指定那一帧，"读不清"几乎不成立。
- **同期还查出四个不在任何任务书里的真实缺陷**：SLM 熔断器一旦触发**换模型也解除不了**
  （而"改用 CPU"正是我们自己文档给的自救处方）；"只改两个 prompt 字符串"的方案会把候选裁剪率从 0.4% 推到 5.84%、
  **把引擎自己的最优解顶到首位**，从而摧毁它正要修的那个性质；**每段录屏的前 5-7 秒录的是引擎启动闪屏**
  （包括当时挂在本 README 上的那一段）；以及一道写好的门**从没接进 CI**，而**我在转述时把作者原话里那句"它没接进 CI"压掉了**。

- **★ 而这一整节量的都不是"有没有人想玩"。** 三路评审（外部对抗 AI + 两个独立只读 agent，指令均为"REFUTE"）
  给出的判决是同一句：**"它看起来明显更好了，而且仍然没有人会玩它。"**
  上面每一个数字量的都是**可读性**，而可读性不是**吸引力**——**playability 这一波一次都没有被测到**，
  本项目也还没有任何能测它的仪器。所以这一节应当读作"我们把量具修好了并用它修了画面"，
  **不应**读作"产品变好玩了"。真正拦在前面的仍然是那条写在「还不到位的」第一行的：**没有目标、没有引导、没有单局形状。**
- **同一轮评审还证明了这套方法本身的漏洞**：本波每一条视觉验收都是**点采样或 diff-bbox**，
  **没有任何一条是"有人把整帧看一遍"**——于是三样东西进了**每一张**已发布素材：一个录屏光标、
  一片把原始数据键印在草地上的缺贴图占位块、一块写着「测试阁楼」的招牌。
  计划里给音频写了"必须有人真的戴耳机听一遍"，**却没给画面写对应的那一句**。三样都已修复并重录。

**8. 一整波只做一件事：逼每一道门回答"你在什么情况下会红？"**
"这道门绿着"从来不是证据。2026-07-30 拆了三道**长期全绿**的门，每一条都用负对照**亲眼看着它变红**之后才算数——
三条坏法各不相同，而且都不是"实现有 bug"，是**判据本身立错了**：

| 门 | 坏在哪 | 负对照 | 结果 |
|---|---|---|---|
| **#39** 产出溯源到**在班**本职 | **名字里有一半没写代码**——它从不读事件的 `tick`、从不调 `_in_shift` | 删掉 `_produce_for` 里的班次判断 | 修复前 `hard_fails: []`，修复后 `hard_fails: [39]`；两臂 `digest` 完全相同 ⇒ 改动只在观测侧 |
| **#40** 产出闭环活性 | **粒度比被守的性质粗**——判"全镇合计"，五种货死掉四种照样绿 | 删掉「教书先生→话本」这条产出 | 收紧前全绿；收紧到逐货物后报出 `【断链货物】话本(P=0,C=3)` |
| `story_test` **账本自洽** | **判据有牙，牙咬不到 CI 跑的 horizon** | 把 `closed_count()` 换成注释自己警告过的朴素写法 | **14 天全绿、150 天才红（32 vs 1085）** |

- **收紧之前先量余量。** #40 收紧前先做了 12 seed × 60 天的逐货物统计：**"任一为 0"的 seed 数是 0/12**，
  最瘦一格是豆子 `P=4` ⇒ `">0"` 有余量。**如果哪种货在某些 seed 上本来就是 0，收紧就等于制造一条随机变红的假门。**
- **`story_test` 那条最难看见，因为它一直在自首**：每次运行都打印 `账本自洽：…（裁掉 0 段不影响这条）`。
  `MAX_CLOSED = 32` 而 CI horizon 是 14 天、一局只收场 2-4 段 ⇒ **被守的那件事在 CI 里从来没有发生过**。
  修法不是把 CI 跑到 150 天（一局 3 分钟），是加一个毫秒级的合成 fixture，**且第一条断言先自证"裁剪真的发生过"**。
  ⇒ **绿字旁边的那个 0 比绿字本身信息量大**：`裁掉 0 段`、`N=12`、`backend=null` 都是"这次运行没有覆盖什么"的自白。
- **诚实边界，逐条**：#39 的负对照只顶出**两个**职位越界，不是八个——那道班次判断对多数职位是**冗余**的。
  所以它守得住"某个职位开始通宵出活"，**守不住**"全部职位同时通宵"。**这颗牙是真的，但没有名字听起来那么宽。**
- **同一族的第四个，而它的结局是【改名字，不是改代码】**：硬不变量 #1 叫「无饿穿」，
  而判据（`Harness.gd`）数的是**任何一条需求触底**，不只是饥饿。
  ⚠️ **它不是"漂移"，是生来就不符**：`git log -S` 查名字、查判据表达式、查那个循环，**三条都只回一个 commit**
  ——2026-07-03 的首个公开快照。**名字与宽判据是同一次提交里一起进来的**，此后 27 天没人动过
  ⇒ **不存在一个曾经正确的版本可以回退。**
  为什么不反过来"只数 hunger"？**这是量过的不是选的**：四格负对照里，只有 social 触底的那个世界在收窄后**由红转绿**，
  而 hunger 与 social 的触底实例数**是同一量级**，只是各自住在不同配置域里
  （零模型地板上几乎全是 social，模型路上 hunger 反而是主项——`backend=null` 的结构性盲区正好把后一半藏在统计外）。
  ⇒ 现名 **「无 need 触底（任一需求，不只饥饿）」**。**改名是零成本的，判别力不是。**
  逐格实测、114 次运行的分布表与探测包络，写在 [`game/bench/Invariants.gd`](game/bench/Invariants.gd) 的 `INV1_NAME` 处。

同一波还**新增**了两道门，补上两类此前"改了没有任何门会响"的资产：

- **美术门**（`tools/art_gate.py`，CI 步骤 2b）：出货的 `game/assets/art/pro/` 必须等于**当场从 `library/` 重建**的结果。
  刻意**不是**"校验和清单对得上"——那种门可以靠更新清单通过，而更新清单正是偷改像素的人下一步会做的事。
  **六条分支逐一见过红**（不是推理，是跑出来的）。它还每次运行都自证三件事：
  ① 重建源头读了 10 个 `library/` 文件、**0 个 `pro/` 文件** ⇒ 重建独立于出货目录；
  ② 向某张表的可达帧注入 1 px 扰动，比对器必须报「1 px 不同」**且指名该表**；
  ③ 打印实际扫过的量——本次运行 **10/10 张逐像素相同，共比对 1,966,080 像素 / 7,864,320 字节**。
  *第三条不是装饰：数字为 0 却打 ✅ 是本仓库反复出现的病。*
  （硬判据只认**解码后的 RGBA**；PNG 容器字节只打印不判红——它随 zlib/Pillow 版本走，
  而"一道在别人机器上因环境变红的门比没有门更坏，它训练所有人忽略红色"。）
- **台词覆盖门**（`game/bench/VoiceGate.gd`，CI 步骤 4f）：每一个**被 offer 的**候选动作，都必须有本人格的话可说
  （口径取"被 offer"而不是"被选中"，否则门的判别力会随机波动）。
  网格是量出来的：**1-3 seed × 60 天**，定门时读到 **293 对 / 31 个不同动作**，而 20 天的网格**漏 3 个动作**，
  漏掉的恰恰是"没人给它写过词"的高危区。（今天这棵树上同一格读 **297 对 / 34 动作**——**动作集合本来就会动**，见下一条。）
- **★ 这道门上线当天就考了一次没有排练的真题。** 它是照**当时**的动作集写的；提交之后另一棒才合进来，
  新增了 `打渔 / 授课 / 劈柴` 三个**写这道门时还不存在**的动作 ⇒ 门当场逐对报出
  `dan|劈柴 被 offer 832 次 / hai|打渔 704 次 / shu|授课 1238 次`。
  **没有人指它去看这三个。** 这是本项目第一次有门在**为它设计的负对照之外**自己抓到东西——绿勾和门的区别就在这里。
- **覆盖地板故意设成 250，而不是实测的 293、更不是"31 个动作必须全在"**：当时另一棒正在决定一个岗位的去留，
  而删掉岗位会**合法地**少掉动作与对。把地板钉在实测值，等于给一次**正当的删除**预埋一条假红。
  **宁可漏报一次缩水，不可假红一次正当删除。**
  ——**这个决定当场就被兑现了**：三个新动作合进来之后，同一格从 293/31 长到 **297/34**，地板 250 依然有余量，
  而一道钉在 293 或"31 个动作"的门会在这里**假红**。

**9. 美术：从"改了没有任何东西会响"到三道门——顺序是【先看，再上门】，而这个顺序是有理由的。**
上一节那道美术门（步骤 2b）落地时只盖住 10 张角色表，**另有 31 张出货 png 一道门都没有**
（emote 10 / decor 8 / terrain 5 / obj 5 / building 3）；G5 补上 terrain 之后**仍有 26 张**。
**补齐的做法不是"把剩下的一起钉住"**，因为那会犯下同一个错：

> **给没有人眼验过的美术上门，等于把当前状态钉成"正确"，而池塘那个 bug 正是这样活了一个月。**

所以 Wave H/I/J 走的是**先眼验、再上门、修不好的先修**：

- **先看**（H1）：在真机上把 26 张逐张调出来看，只判不改，产出一张 `OK / 读不出 / 从不出现 / 需要重画` 的分类表
  （[docs/51](docs/51-art-eyeball.md)）。**"看不出问题"是被明确接受的结论**——那正是敢上门的前提。
- **只给判为 OK 的上门**（H2，CI 步骤 2d），**拒绝其余，而且拒绝是机检的不是注释**：
  把一张"代码里到不了屏幕"的图偷偷加进上门表 ⇒ 门红并点名。**棘轮反向也成立**——
  哪天有人把死资产接上线，它同样红，而那正是"回去重新眼验、重新决定"的时刻。
- **判为"读不出/画错了"的先修**（I1、J2），修完再进上门表。

**今天的覆盖是可以数的**：`game/assets/art/` 下 **46 张**出货 png（pro 10 / terrain 13 / emote 10 / decor 8 / obj 5），
**45 张有门**（2b 角色表 10 · 2c 地形 13 · 2d emote/decor/obj 22），**刻意不守的只剩 1 张**
（`decor/tree_small`，判"从不出现"——它同时是 2d 那条"死资产必须仍然是死的"自检**唯一的活输入**）。
三道门是**同一套形状的三个实例，不是三种形状**：当场从 CC0 库重建 → **解码后 RGBA 逐像素**比对 → 每次运行都自证判别力。

沿路捞到的四件事，每一件都不是任何一份任务书点名的：

- **十张表情里九张是同一个白泡。** 两两差中位数 24 px、最近的一对只差 **6 px**（一张图共 400 px）。
  **而"换几个更好的格子"这条路是被实测堵死的**：整张 CC0 表 38 个非空格、703 对，
  贪心 + 局部搜索挑"最分得开的 10 张子集"**上限只到 14/400，且 4 对并列在那**——
  **整张表的内容就是一个白泡加 2-4 px 的换脸。** ⇒ 九张改为**手绘像素**，配方（字形表 + 纯函数重画）进门。
  判据**立在上屏尺寸上而不是源像素上**：源两两差 6 → **109**（地板 60，余量 1.82x）；
  28 device px 灰度 5.74 → **15.73**（地板 10.0，余量 1.57x）。**旧那批在两条上分别是 6 和 5.74 ⇒ 这道门在未改动的树上会红。**
  （地板与两列实测数逐行写在 [`tools/asset_gate.py`](tools/asset_gate.py) 的 `DISTINCT_SRC_FLOOR` 处。）
  > **眼验与度量各自抓到了对方抓不到的东西**，这一段最值得记：只有眼睛看得见"心形平顶像盾牌""裂心读成两只翅膀"；
  > 而只有度量看得见 `meet_fulfilled` 的玫红与 `meet_broken` 的板岩蓝**亮度 141.7 vs 143.8**——
  > 同一轮廓族**且**同亮度，颜色被压掉之后得分 5.87，**比旧白泡最差的那一对（5.74）还糟**。**眼睛永远不会发现这个。**
- **两张出货精灵画的根本不是那件东西。** `obj/bath` 画的是**一口井**，`obj/arcade` 画的是**一块告示板**——
  而 `WorldView._draw_landmarks()` 本来就在程序化地画井和告示板，`arcade_1[33,24]` 与 `board[33,26]` **同列隔两格**。
  **判别"切歪了"与"画错了"被做成了可测的**：裁剪框边界上的不透明像素数 + `bleed`（画还在往框外延伸的比例）。
  `tree_big` 边界 0/27/0/29、`bleed` 0.438 ⇒ **切歪**；`bath`/`arcade` 边界全 0、`bleed` 0.000 ⇒ **切得完美，题材错了**。
  于是多了第 3 条性质：**一条 crop 不许从连着的美术中间切过去**，地板 0.10 标在 4 个阳性与 12 个阴性上（两侧余量 3.2x / 1.9x）。
  **它判的是配方几何，所以连没上门的那张也覆盖到**——`house`/`shop`/`tree_big` 三次缺的恰好是这一条，而三次都是靠人眼在事后发现的。
  > **这道臂的 `does_not_detect` 是本节最该被读到的一行**：把 `arcade` 换回另一个**切得干净但题材仍然不对**的格子 ⇒ `bleed` 0.000 ⇒ **过**。
  > **那正是 bath/arcade 这个病本身，而新臂对它是瞎的。** 执行的棒照直写了下来。
- **一个每局玩到第 14 天就会出现的灰色占位框。** 选举通过时 spawn 的 `WorldPatch` id 是 `civic_<话题>_<日>`，
  前缀 `civic` **没有任何贴图**；而 `elections.every_days` 默认 **14** ⇒ **任何正常玩到第 14 天的一局，[22,2] 上都会出现一个占位框、底下印着数据键「扩建咖啡馆」。**
  根治不是改数据改名，是把精灵槽从 `id.split("_")[0]` 这条**隐式契约**换成显式的 `type→slot` 表，加三条 `push_error` 断言。
  > **这里我给的判断被像素证伪了**：我转告执行者"缺贴图这条失效模式在树上已经没有活实例"，它拿这个 `civic` 反驳了我。
  > 我还把两件事的轻重弄反了——**缺贴图只有一个活实例，而光 `bench` 一个槽就有五个活别名**（一张 `bench.png` 服务五种器物）。
- **三张贴图 + 一个读取器 + 一句文档承诺都在，而没有任何代码路径能把它们画到屏幕上。**
  三次独立的静态扫描都把它讲成"没接上的特性"。**`git log -S` 给出的是反的**：`Art.building_tex("hut")`
  **接上过、出过货**，2026-07-15 被有意摘掉，提交信息点名它是用户报的比例失调的头号成因
  （16×16 的 hut 放大到 48px 恰好一格 ⇒ *"a whole house the size of a person"*）。
  ⇒ **把它接回去 = 把一个修好的 bug 装回去**，处置是删。`docs/09` 那句承诺**比代码多活了 15 天**。
  > 沉淀成契约里的一条纪律：**「今天零调用点」在语义上是二义的——"从没接上"与"被有意摘掉"长得一模一样，而只有历史能区分。**
  > **`grep` 给现状，`git log -S` 给意图。**（[docs/41 §1.5](docs/41-baton-contract.md)）

**这一节诚实的另一半**（放在这里而不是脚注里）：

- 上面每一条量的都是**素材本身**。`asset_gate` 自己写着它**不查画得好不好、不查"读出来是不是那个情绪"**——
  两两地板拦得住"又变回一个样"，**拦不住"十张都很丑但互不相同"**。
- 表情那一批**没有一帧真实游戏画面里居民头上顶着它**（`--shot` 结构上拍不到），
  用的是引擎纹理渲染探针；验证了滤镜与缩放，**没验证与角色/名牌/需求条的合成**，也没上真机。
- 树的改善**在默认全镇取景下看不出来**，两张家具图标仍然太像——两条都逐字留在「还不到位的」里。

## 工程设计

1. **模型不直接改状态。** 引擎枚举合法候选，模型只返回候选 index 与可选台词。非法输出、超时或服务缺失都会回退到确定性规则。
2. **不变量作为回归门。** soak 会检查 **40 条**社会性质，包括信念来源、承诺结算、道歉流程、声誉影响、私聊秘密边界、金钱守恒和不可透支。**权威清单是代码本身**：[`game/bench/Invariants.gd`](game/bench/Invariants.gd)（每条带 id、中文名与失败详情）。方法学见 [docs/08](docs/08-测试与验证.md)。
   **但"有一条不变量"不等于"它守得住"**——同一份代码里刚有三条被证明长期没有判别力，见上文技术难点 8。
3. **事件溯源支持回放。** 随机性由 `seed + tick + salt + agent` 派生（`_rng_at` 每次新建 RNG、纯输入播种、无状态），不依赖墙钟或全局随机。同一 seed 生成逐字节一致的摘要，回放观察台可从任意 tick 重建世界——**范围限定在零模型 logic 地板 + 无玩家介入**（非 logic 后端 / 玩家在镇时，重建出的是另一段历史；实测与门见上文技术难点 1 的引注与 [docs/47 §三·七](docs/47-wave-e-plan.md)）。
4. **Godot 是权威；Node 端口是历史交叉验证。** [`tools/sim_social_port.mjs`](tools/sim_social_port.mjs) 曾镜像 M1-S3 的社交内核用于秒级迭代，自查 **33 条**断言（对应引擎的 #1-#33），并确实证过"这套逻辑对 RNG 实现是鲁棒的"（端口用 mulberry32，Godot 用 `RandomNumberGenerator`，两边数值不同而性质同时成立）。**但它已于 2026-07-26 正式退役**（[docs/39](docs/39-node-port-disposition.md)）：其逻辑冻结在 2026-07-03、两天后即被"阵容 6→12"打破，且它**从不比对状态**（两边各跑各的轨迹），今天在 12 seed 里有 7 个是红的。**现在不要把它当验证依据。**
   但**它不是当前的门**，说清楚：它**不覆盖** #34-#37（金钱守恒 / 货币非负 / 节日配对 / 选举计票），与 Godot **不逐字节可比**，**不在 `tools/ci.sh` 里**，自 2026-07-03 首次公开快照后**未再更新**，而且**部分 seed 已经跑红**（`--seed 20260626 --days 30` 退出 1；seed 1 与 42 仍 33/33 全过）。逐条核对见 [docs/08 §1](docs/08-测试与验证.md)。**回归门只有一个，在 Godot 侧。**

## 快速开始

需要 [Godot 4.6+](https://godotengine.org/)（工程声明 `config/features = 4.6`，CI 钉在 4.6.2）。

**跑整条门**——和 GitHub Actions 跑的是同一个脚本：

```bash
GODOT=/path/to/godot bash tools/ci.sh
```

**17 道关**（步骤号即 `tools/ci.sh` 里的编号，**以脚本为准**）：`0` 版权红线（整棵已跟踪树里不得有权重/二进制）、`1` 数据 lint、`1b` 地图审计、`2` markdown 链接 lint、`2b` **角色表美术门**（出货 `pro/` 10 张 == `coif_characters.py` 当场重建）、`2c` **地形门**（出货 `terrain/` 13 张 == `slice_shore.py` 当场重建）、`2d` **资产门**（上门的 **22 张** emote/decor/obj == 切图/自绘配方当场重建 + 表情两两可分 + 配方无断口）、`3` Godot 解析冒烟、`4` **S0 不变量门**（40 条 × 12 seed × 60 天 + determinism 三跑 + **已提交金标**跨进程锚 + **逐 tick 前缀链** + 套件级活性）、`4a` **宏观池尺度门**、`4b` LOD 观察无关门、`4c` **DetGate 场景确定性门**（default/faction/betray/freerider 四轨）、`4d` BackendGate 外部后端门、`4e` ModelPathGate 出货 prompt 编码门、`4f` **台词覆盖门**、`5` 9 个集成场景、`6` 视觉门（昼夜量具 + 界外重画 + 空间往返 + 池塘岸线；**无渲染环境时自动 SKIP，不假红**）。任一红即退出 1。

> **`4a` 值得单独说一句，因为它补的是这个仓库反复中招的那种洞**：第 4 步的 S0 恒跑 N=12，
> 而 N=12 时宏观池的缩放倍率**恰好是 1**（`_pool_rescale` 直接 `return raw`）⇒ **换尺度那条路，CI 一步都没走过**。
> 4a 默认在 **N=16** 上跑同一套判据（`2b4565e`；默认值后来由 `6c7c8bc` 从 24 翻成 16）。
> 它自己带**四条预检**，把"这一格会不会退化成上一格的复读"做成机检而不是注释——
> 例如 `CI_POOL_N=12` 时它**主动判红**并打印「池倍率恰为 1 ⇒ 会退化成第 4 步的复读」。
> **一道门自证"我这次真的在守我该守的东西"，比它打绿勾更有信息量。**

> 三道美术门（2b/2c/2d）**需要 Pillow，装不上就直接红、不做 SKIP**——理由写在脚本里：
> **SKIP 与 PASS 在汇总里都读作"没红"**，那会把一道门退化成一枚看不见结果的硬币。
> 而第 6 步的视觉门**反过来**：探不到渲染环境就 SKIP，因为*一道在别人机器上因环境变红的门比没有门更坏，它训练所有人忽略红色*。
> 两条规矩看着矛盾，分界线是**缺的那个依赖能不能装上**。

> ⚠️ 一处诚实边界，**已经缩小但没有消失**：金标 / LOD / DetGate 三道门都钉 `Sim.backend=null`，
> `AIBackend.decide()` 根本不进——所以它们全绿**不构成**对模型路径的任何断言。
> 步骤 `4d` BackendGate 就是为此加的：它用**确定性的 `random` 后端**（选号取自项目自有种子流、时延按 tick 计
> ⇒ 逐字节可重跑，门自己每次都机检这条）在外部后端的落地路上守硬不变量含 #01。
> **但仍然没有被覆盖的是 `slm` 本身**——它有 run-to-run 噪声，按设计永不进 CI。
> 另外 `tools/ci.sh` 在 4d 的注释里自己写清了一条**反过来的诚实**：那道门的"闭集封闭"臂在 `random`/`slm` 上
> **结构上恒为 0 escape**，所以它打出来的全绿是**恒真、不是证据**；它是守未来新后端的**回归门**，
> 不是"现有后端已被验过"的证书。全链见 [docs/45](docs/45-external-backend-invariant-gate.md)、[docs/38](docs/38-does-the-decision-path-earn-it.md)。

窗口模式：

```bash
godot --path game -- --speed 2.0
```

操作：空格暂停，`1/2/3/4` 调速，滚轮缩放，点击居民打开状态，拖动时间轴回放。选中居民后可在底部输入框对话。

单 seed 详细 headless soak（逐事件、逐不变量）：

```bash
godot --headless --path game --script res://scripts/sim_soak.gd -- --days 30
```

Node 端口（历史交叉验证，**不是门**，部分 seed 已红——见「工程设计」第 4 条）：

```bash
node tools/sim_social_port.mjs --days 30 --seed 1
```

可选本地模型后端：

- `--backend llm`：启动 LM Studio 或其他 OpenAI 兼容本地服务，默认 `localhost:1234`，并加载指令模型。
- `--backend slm`：把 [NobodyWho](https://github.com/nobodywho-ooo/nobodywho) 放到 `game/addons/nobodywho/`，把 GGUF 权重放到 `game/models/`，例如 Qwen2.5-1.5B-Instruct-Q4_K_M。

接线细节见 [docs/03-LLM集成架构.md](docs/03-LLM集成架构.md)。硬件实测见 [docs/11-LLM部署实测对比与选型.md](docs/11-LLM部署实测对比与选型.md)。安卓出包见 [docs/18](docs/18-android-apk-build.md)。

`game/assets/art/pro/` 那 10 张角色表是对 CC0 素材包的**改绘衍生**（alpha 掩膜、查表换色、从基表复制像素、写死坐标的手绘模板；**不缩放、不插值**），**生成图参与度为零**——AI 出图只能当情绪板，绝不进精灵帧。这条现在由 CI 步骤 2b 机检：出货必须等于**当场重建**。

**同一条纪律现在盖住 46 张出货 png 里的 45 张**（2b 角色表 10 · 2c 地形 13 · 2d emote/decor/obj 22）。
其中 **12 张是手绘像素**（9 张表情 + `obj/bath` + `obj/arcade` + `decor/tree_big`，字形表在切图脚本里；其余是 CC0 切片）——
**手绘同样要有配方**：字形表 → 纯函数重画 → 门 import 配方当场重建，**一张没有配方的图进不了上门表**。
生成图在这条路上是**结构性**走不通的，不只是被规矩禁止。

部分文档会提到一个上游游戏评测流水线，用于 headless 渲染、自动录屏与 LLM-as-judge 实验；本仓库运行时不依赖该流水线。
