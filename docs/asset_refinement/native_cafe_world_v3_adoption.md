# Native cafe WorldV3 adoption

This lane installs one exclusive Unreal cafe authority, controller/HUD and V4 durable-care save seam. It does **not** qualify physical eating. No reviewed eat clip/contact provider or meal-contact descriptor is supplied. At the real reachable counter, Ben's meal request must say "Eating is not available yet. You have not been charged." Native meal completion remains open.

Native120 passed the Windows Editor/UHT and Game builds plus six native automation tests: both backend selectors, the existing PropertyV2 sale/lease journey, WorldV3 counter refusal, separate-process cold restore, and actual off-counter F5 input with feedback composition. [Sanitized evidence](evidence/native_cafe_world_v3_adoption.json) records the exact source family and limits. Physical eating still requires a reviewed clip/contact provider; pixels, OS keyboard input, cooked content and performance are not qualified by those tests.

## Selection and authored sources

Opt in with `-LivingTownCafeWorldV3` and the exact `/Script/LivingTownNative.LivingTownCafeWorldV3GameMode` in a standalone game/PIE world. `-CafeWorldPersona=ben` is the default; `aria` selects the existing functional owner proxy. F1/F2 change authored personas through the GameMode. Ben retains the existing qualified cafe character.

The shared `CafeBackendV3.hpp` selector now controls legacy lease creation, PropertyV2 creation/activation, WorldV3 creation/activation and legacy projection preparation. Conflicting WorldV3/PropertyV2/explicit-legacy flags, or either new backend with worker-preview, select Invalid and create no competing ledger. Default legacy and single PropertyV2 opt-ins retain their own implementations and slot formats. The portable selector bytes are intentionally unchanged because `LivingTownNative.Build.cs` freezes their SHA256; its historical "proposed" comment predates these native callers.

WorldV3 requires the existing exact `PropertyV2PropertyRegistry.json`, `PropertyV2AuthoredAgents.json`, `CafeProjectionBinding.json`, actual qualified venue/floor/counter and matching persona capsules. It owns only `cafe_world_v3::Kernel` plus the paired Ben `ResidentUse` and one natural clock. Property offers/sale/lease/expiry run inside that same Kernel. No legacy kernel, PropertyV2 book, extra wallet or stock cache is instantiated for gameplay.

## Commands and outcomes

WASD/mouse retain the existing pawn controls. E requests a purchased meal; X cancels. O/L open sale/lease offers; B buys; K leases; R ends lease. F5 saves and F9 restores. The HUD reads cached observer fields, including current operator, exact property listing price, meal stock, Ben's hunger/fun, progress and friendly receipts. The live authority notice remains visible below the prompt. A distinct controller result appears on its own "Last action" row, so F5 save feedback also appears away from the counter and cannot replace live meal progress or outcomes.

A meal intent has request ID/site/kind/observed revision only. Actor identity comes from actual live possession. The adapter samples actual floor, hand reach, facing and first-hit counter/eye rays. It calls `begin_meal_use`, `advance_meal_use` and `cancel_meal_use`; settlement, ration decrement, grants, effects and idempotence remain portable-core decisions. Existing paid-meal policy is 2 coins to the current other operator and one ration. Own-operator stock/public-relief rules retain the core's existing behavior. Ben is the sole meal-care resident in this slice; Aria owns the existing property role.

A future accepted action needs eighteen freshly observed authority seconds. Earned effects use the existing clamped +50 hunger/+3 fun rule, alongside its existing passive decay. Grant acceptance alone changes no needs. Each live frame checks contact/session; every consumed second additionally requires a changed evaluated-bone revision and actual clip-time advancement on fresh natural frames, with only a bounded observed loop wrap accepted. At most one sample is consumed per frame. Delta above .25 seconds, multi-tick catch-up, pause, lost geometry/session/pose or changed operator interrupts; idle clock/expiry catch-up creates no contact or benefit. Persona changes cancel before releasing possession. Completion/cancel/interruption/load/partial-start-failure restores the prior SingleNode animation asset/time/loop/play/play-rate state on the exact still-installed player instance. It switches that existing player through SetAnimationAsset, retaining any custom root-corrected player class/proxy/configuration rather than recreating it. Start refuses disabled/paused/frozen animation and independently verifies actual selected asset, player identity and playing/rate/loop state before settlement. Existing Ben Tick only updates blend-space input; it does not reinstall a competing locomotion asset.

## Physical dependency (still open)

`ULivingTownCafeMealContactComponent` is an abstract native read-only recipe seam. Its default `ReviewedRecipe` refuses. There are no Blueprint/UI qualification fields and no test flag can approve it. A future asset integrator must attach a reviewed native provider to the actual Ben pawn and supply `Content/LivingTown/CafeWorldV3MealContact.json` before scenario startup. Updating authored animation revisions does not require a different provider class.

The exact descriptor keys are `format` (`LivingTown.CafeWorldV3.MealContact`), string `version` (`1`), `binding_sha256`, `clip_asset`, `mesh_asset`, `clip_sha256`, `contact_certificate_sha256`, `hand_socket`, `mouth_socket`, numeric `max_contact_distance_cm` (>0 and <=15). It must identify the actual cafe binding and Ben mesh. The provider returns those same immutable fields, actual loaded `UAnimSequence`/`USkeletalMesh` and `RecipeFileSha256` (the descriptor's SHA256). Startup validates schema/binding and binds the descriptor digest into V4 saves; beginning independently matches descriptor fields, exact clip package bytes and pawn mesh/skeleton/sockets. Natural observations require that actual sequence playing at authored rate 1, enabled/unpaused animation and global animation rate 1, fresh evaluated bones, real clip-time advancement consistent with bounded world-frame elapsed time and live hand/mouth distance, plus current floor/counter/session/reservation/operator checks. A certificate field is provenance for separately reviewed physical evidence, not proof produced by this adapter. The root must qualify an actual clip/contact journey before crediting native eating.

The current clip package SHA256 check resolves a loose `.uasset` file and is an **uncooked development binding**. Cooked/IoStore loading and positive-provider operation are unqualified; this lane adds no cooker or packaged-content framework.

Missing descriptor uses an explicit unavailable-policy fingerprint and never qualifies a provider. A malformed present descriptor refuses startup. No descriptor, assets, certificates or positive clip provider were created by this change. Native contacts intentionally remain fail-closed until the asset lane supplies and verifies them; this source alone cannot complete the eating acceptance gate.

## Persistence

`Saved/CafeWorldV3/CafeWorldMealCareV4.slot.json` is a new slot. Strict exact-field native JSON wraps the portable paired V4 document with source, payload and whole-envelope SHA256. Source binding includes frozen WorldV3/care/envelope cores, exact roster/config, current physical scene/qualification/visual/binding and reviewed recipe digest (or explicit unavailable policy). Duplicate keys, unknown fields/version, noncanonical Base64, changed source, invalid clocks or either failed replay refuse before publishing anything. The existing `LivingTownCafeSlot::WriteAtomic` replacement and final readback are reused.

Load validates both replays and reservations, then converts saved active care to AfterLoad and publishes clock/world/care together. Earned effects remain; old contact/pose/permission/reservation observations cannot resume an action. Saved persona is metadata only. Current controller, pawn and transform are retained. Saves from legacy/PropertyV2 are never silently interpreted as WorldV3.
