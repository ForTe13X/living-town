# 全镇 affinity 收支诊断 · gossip_rep 的 79% 婉拒到底在花什么

B11 诊断棒。**只测不调**：`game/scripts/**`、`game/data/**`、既有 bench、金标一行未动，CI 全绿、金标 12/12 不变。
起点是 commit `7227517` 提交信息里留下的一句悬案——"**gossip_rep 83% 被婉拒、每次双向 -3 好感**，剩下的瓶颈不是阈值而是结构"——
以及由它推出的猜想："全镇跑在净 affinity 赤字上（≈ -2200/局 vs greet 的 +1400），而这个赤字很可能正是 #15 涌现放逐的引擎"。

**两条都被本棒的实测推翻。** 赤字比传闻小一个数量级且**不是单调下沉**；它也**不可能**是 #15 的引擎——因为 #15/#15v2 量的是 `standing`，
而 `standing` 被 GTFT 宽恕漂移按住在 0 附近（docs/11、docs/13:457 早已定性，本棒给出流量比）。

## 1. 账本怎么算的（为什么可以信）

`game/bench/affinity_ledger.gd`（新增，只读）。三条纪律：

1. **realized 是真值，不是重放常数**：每个"有事件的 tick"对**全量 affinity/standing 矩阵做差分**，
   按 `(有向对, tick)` 归因到当 tick 唯一认领它的那条事件；被多条认领 → 进 `ambiguous` 桶，绝不猜。
2. **闭合自检**：日界对全镇总额对账（`初值 + realized 累计 == 实测总和`）。全网格 **偏差 0.0000**。
   standing 侧 **unattributed 0.0 / ambiguous |Δ| 2.0**（dev；held-out 12.0），占 15665 的 0.01%。
   affinity 侧有 2786 笔（held-out 2865 笔）落进 ambiguous——同一 tick 多条事件撞同一有向对，净额 -40（held-out -1340），
   占毛流量 69439（held-out 72846）的 0.06%/1.8%。**这部分不参与任何按来源的结论**，只在总额里如实计入。
3. **nominal 只用来算 clamp 损耗**，常数逐条抄自 `Sim.gd` 并注明行号；结论不依赖它。

两个坑是被自检**当场抓出来**的，不是事后想到的：

- **standing 有一条不属于任何事件的通道**：`_nightly()`（`Sim.gd:1238-1240`）每 3 天把**每一条** `standing` 向 0 挪一步。
  最初账本漏了它，2490 点变化无法归因 → 单列成 `@nightly_drift` 桶。
- **日界 tick 可能零事件**：漂移于是顺延到下一个有事件的 tick、被错记成那条事件的效果。修法是"日界 tick 无条件进块"。
  修前 `greet/ok` 白白背了 154 点、`gossip_rep/no` 背了 73 点。**未归因不许静默**——报告里保留了未归因分桶直方图。

## 3. 接受判定：谓词、输入、以及它没有的东西

`Sim.gd:2530-2535`（`gossip` 与 `gossip_rep` 共用一条）：

```
"gossip", "gossip_rep":
    if "爱八卦" in traits:  hard = true            # 无条件接受
    else: sum = aff + reserved + st + fac + jitter + extra ;  thr = _w("accept_gossip", 0.0)
accepted = hard or (sum > thr)
```

- `aff` = **听者对说话人**的 affinity（`_rel(target, actor)`，`Sim.gd:2495`）
- `st` = 听者对**说话人**的 standing × `STANDING_K=6.0`
- `reserved` = **-15**，当听者带 `寡言` 或 `温柔`（12 人里 阿本、阿菲）
- `fac` = 同派系 +8 / 跨派系 -8（`FACTION_ACCEPT_K`）
- `jitter` = 听者子流的 U(-10,+10)
- `thr` = `utility.json` 的 `accept_gossip = 0.0`

**判定式里没有任何一项关于被议论的第三方 C。** 谁被说、听者对被说者什么看法，对"接不接受"零影响。
实测把 margin 按上述分项重建，**跨 24 seed 最大误差 0.000000** —— 分项解释了判定式的全部，没有隐藏输入。

### 真正的结构不对称：缺的是 need 项，不是阈值高

`accept_gossip = 0.0` 与 `accept_greet = 0.0` **完全相同**。但 greet 的左端多一项 `(100-need)*0.4`（invite 是 `*0.35`）。
实测 gossip_rep 决策时听者 `need` 均值 ≈ 81 → greet 白拿约 **+8** 的"我正缺人说话"底分，gossip_rep **一分没有**。
于是在一个全新的中性对上（aff=st=fac=0），greet 靠 +8 基本必过，**gossip_rep 退化成 jitter>0 的抛硬币**。

再叠上正反馈：每次婉拒 → 该有向对 affinity **-3** → 下次同一说话人的 gossip_rep 更难过 → 再拒。
而 **gossip_rep 的候选打分 `urgency*0.6 + gossipy + 10.0`（`Sim.gd:1495-1496`）里没有 affinity 项**——
说话人**永远不会因为被拒过 50 次而改口**。greet 的候选分里反倒有 `aff*0.1`。**发起端没有反馈回路，这是"结构"的确切所指。**

实测剂量-反应（24 seed 合并，按听者对说话人的 affinity 分桶）：

| aff < | -60 | -40 | -25 | -15 | -5 | +5 | +15 | ≥15 |
|---|---|---|---|---|---|---|---|---|
| gossip_rep 接受率 | 0.3% | 2.2% | 4.5% | 6.8% | 9.7% | 31.6% | 68.6% | 91.7% |
| greet 接受率 | 0.0% | 0.0% | 0.0% | 2.6% | 22.0% | 68.2% | 94.1% | 99.8% |
| 平均 need | 79 | 80 | 81 | 81 | 81 | 81 | 82 | 81 |

（`need` across 分桶几乎不动，正说明 gossip_rep 对需求不敏感。注意 **greet 在 aff < -25 时接受率是 0%** ——见 §5。）

### 谁拒谁：**弥散，不是几个刺头**

- 按听者汇总（24 seed 合并拒绝次数）：铁牛 931、阿菲 926、阿本 898、阿林 878、老邓 815、苏琴 796、老海 729、小薇 659、可可 650、阿梅 635、沈书 608。**最高/最低 = 1.53**，极均匀。阿丽（爱八卦）恒 0——`hard=true`。
- 按性格分层（seeds 1-12）：普通 **80.9%**（3094/3823）、寡言/温柔 **96.6%**（851/881）、爱八卦 **0%**（0/290）。
- 按说话人：阿本 1429、阿丽 1215 …… 老海 337，差 4.2 倍（说话人差异远大于听者差异）。
- 集中度按 `(seed, 说话人, 听者)` 三元组：top-5% 承担 21.0%、top-25% 承担 65.6%、top-50% 承担 92.0%。

**结论：拒绝集中在"某些有向对"上（正反馈把个别对钉死），但在"人"这一级几乎均匀铺开。**
镇上没有"不合群的那个人"，只有"聊不下去的那些对"。

## 4. standing 账本：这条机制的主要产物是它自己的副作用

`#15/#15v2` 量的是 `standing`，不是 affinity。所以真正该看的是这张表（seeds 1-12 × 60 天）：

| 来源 | n | st_neg | st_pos |
|---|---|---|---|
| **gossip_rep 被拒** | 9118 | **-7090** | +2028 |
| **`@nightly_drift`（GTFT 宽恕）** | 12943 | -3166 | **+9782** |
| greet 被拒 | 2446 | -1958 | +488 |
| discuss 被拒 | 1935 | -1611 | +324 |
| **gossip_rep 接受**（= 本机制的**正事**：把 C 的坏名声传出去） | 1045 | **-1045** | 0 |
| endorse 接受 | 194 | -370 | 0 |
| meet 接受 / apologize 接受 | 1576 / 993 | 0 | +1576 / +1299 |
| **合计** | | **-15665** | **+15591** |

三个比值，每一个都指向同一件事：

1. **gossip_rep 婉拒贡献了全镇负向 standing 的 45.3%** —— 它是镇上最大的单一名声打击源。
2. 但这些打击**打在听者（拒绝者）身上，不是被议论的 C 身上**：`Sim.gd:1682-1685`，
   婉拒 = 听者对说话人的 defect，说话人 + 每个旁观者据 L3 Simple Standing 把**听者**的 standing 降 1
   （docs/10 §A1 的既定设计，含"教训坏人正当"的 +1 分支，故有 +2028）。
3. **副作用比正事大 6.8 倍**：婉拒造成的 -7090，对比机制本职（接受后把 C 的 standing 挪一步）的 -1045。
   **一个"传播第三方坏名声"的机制，79% 的时间在给听者刷坏名声，而不是给被议论者。**

再叠上宽恕：`@nightly_drift` 净给出 **+6616**（每局 +551）的名声修复，是 gossip_rep 正事产出（-1045，每局 -87）的 **9.4 倍**。
**遗忘的速度是传播的 9 倍多。** 这就是共识放逐形不成的流量学解释——
docs/11 §6（causal bench：standing→放逐 **ACE=1.00**，但"一次性坏名声被每 3 天向 0 漂移的 GTFT 宽恕冲掉 → 放逐是暂态的"）
与 docs/13:457 早已把这条定性；本棒补上的是**比值**。

## 5. "赤字是 #15 引擎"这个假说：不成立，但它盖住了一个真东西

### 5.1 #15v2 在本树上仍是 INCONCLUSIVE

用 `Harness.gd --shadow-dump` 现烘一份 trace（seeds 1-24 × 60 天，30134 条决策，独立文件、无并发写者，
`exile_v2.py` 未报去重告警 → 没踩 docs/32 的僵尸写者坑），冻结阈值原样跑 `tools/exile_v2.py`：

```
#15v2 跨 24 seed：FAIL 0 | PASS 0 | INCONCLUSIVE 24
```

绑定约束和 docs/31 完全一致：共识 outcast 窗口只占决策的 **3.34%**，
任一 actor 在其窗口内遇到的**中立弱关系 greet/invite 最多 5 次**（门槛 `MIN_WT = 8`）。分布 `[5,4,3,3,3,2,2,2,2,1,1,1]`。

**所以"赤字是 #15 的引擎"这个假说，在当前尺度上连被证伪的资格都没有——被解释项本身测不出来。**
而且方向上也说不通：#15v2 的 outcast 标签建在 `standing` 的零填充镇内均值上，
`standing` 被 §4 的 9.4:1 宽恕流量按在 0 附近（终局全镇 standing 总额平均只有 **-6.17**，12 人镇 132 个有向对）。
**赤字长在 affinity 上，指标长在 standing 上，两条通道被 GTFT 漂移隔开了。**

### 5.2 分化是真的，而且是涌现的

| | dev 1-12 | held-out 13-24 |
|---|---|---|
| 终局"人均收到的 affinity"极差（max-min） | 均值 **38.7** | 均值 **43.8** |
| 最低者身份 | ben ×4、fei ×2、lin ×2、aria/tie/qin/evy 各 ×1 | ben ×8、tie ×2、fei ×1、dan ×1 |
| 最低者的 standing | -0.91 … +0.64（**贴着 0**） | 同量级 |

最低者是谁**随 seed 变**（不是脚本写死的），极差 ~40 分，而他们的 `standing` 几乎全在 ±1 内。
**这正是"涌现出的被冷落者"该有的样子——只不过它长在没人测量的那条轴上。**

### 5.3 有牙齿吗？有，但只在**对**这一级

- **对级**：`greet` 在 aff < -25 时接受率 **0.0%**（504 次尝试全拒，24 seed 合并）。
  这条对已经**彻底不说话了**——玩家能看见的、货真价实的疏远。
- **人级**：本棒顺手做了一个**结构上无时间泄漏**的前瞻试点（预测量在第 50 天、结果量在 51-60 天，
  预测严格早于结果，`MIN_WT=8` 沿用冻结门槛）：

| | dev 1-12 | held-out 13-24 |
|---|---|---|
| 最低画像者 vs 镇内 LOO 接受率之差 | 均值 **-0.043**，12 个 seed 里只有 **7** 个为负，区间 -0.491…+0.189 | 均值 **-0.081**，**6/12** 为负，区间 -0.416…+0.169 |
| 池化 Spearman ρ(第 50 天 affinity 画像, 后 10 天接受率) | **0.350**（n=120） | **0.240**（n=106） |
| 接受率：画像<0 / 画像≥0 | 0.829 / 0.892 | 0.827 / 0.885 |

**弱剂量-反应存在且在 held-out 上复现（ρ≈0.24-0.35，接受率差约 6 个百分点），但"最镇内最不受欢迎的那个人"并没有被全镇一致冷落**
（一半 seed 里他反而高于镇均值）。**⚠ 这是探索性试点，不是结论**：阈值未预注册、未过对抗评审，**不得**当作 #15-affinity 的判定。

## 6. 结论与建议：**(c) 尚不可判 —— 但可判的那一半已经判了**

分成两个问题，各自有各自的答案：

**Q1「全镇跑在净 affinity 赤字上吗」→ 已判定：否。**
净额 -71/局（dev）、-392/局（held-out），对照毛流量 ±2860/局；24 seed 里 6 个终局为正；轨迹在 0 附近震荡而非单调下沉；
clamp 地板基本没碰到（0.5 个对/局）。**这条不需要修，前提就是错的。**

**Q2「79% 的婉拒是 load-bearing 的特性，还是缺陷」→ (c) 尚不可判**，但已知：

- **不是 #15 的引擎**（§5.1）——被解释项在 N=12 尺度测不出来，且长在另一条通道上。**用 #15 给它背书的路已经堵死。**
- **不是被有意设计成这样的**：`accept_gossip = 0.0` 与 `accept_greet` 相同，没人把它调高过；
  docs/10 §A2 把 gossip 率 τ 当**旋钮**，并且引证 4-10 体尺度上"gossip 驱动的间接互惠达 ~100% 合作并放逐惯犯、**无 gossip 则崩到 ~0%**"，
  设计意图明确指向**高 τ**；docs/10:131 还记着一次**反向**修复（"over-boost discuss 把 gossip_rep 挤没 → 给 gossip_rep 升示警优先级"）。
  今天的 79% 是**缺 need 项 + -3 正反馈 + 发起端无反馈**三者的涌现结果，不是谁选的 τ。
- **但它确实在支撑东西**：硬不变量 **#16 声誉传播**（`Invariants.gd:182`）要求"只要存在坏名声就必须有 gossip_rep 事件"；
  §5.2 的分化（极差 ~40、身份随 seed 变）也确实由这条正反馈造出来。**贸然压低拒绝率，等于同时动 #16 和唯一在产分化的机制。**

### 会一锤定音的实验（按顺序，都不必先改平衡常数）

1. **先补度量，别先补机制**（最高杠杆）。分化长在 affinity 上却没有指标——照 docs/30 的规矩造 **`#15-affinity`**：
   在 `Sim.gd` 加一个与 `_town_image_stats` 同构的 **affinity 画像**（同为纯读、`.has` 不 auto-create），
   由 `_shadow_record` 逐决策记同期快照；判定沿用 #15v2 的骨架（同期窗口 + 弱关系 + LOO 基线 + `MIN_WT`）。
   **阈值在 dev 1-42 上预注册后冻结，在 43-126 held-out 上确认**，并按 docs/32 一 run 一份 dump。
   §5.3 的试点（ρ≈0.24-0.35 且 held-out 复现）说明信号大概率在，但**必须**走完预注册才算数。
2. **再用 shadow 反事实量 lever，别重跑仿真。** 候选 lever 只有一个是对准病灶的：
   给 gossip_rep 的判定式补上 greet 那样的 need 项（如 `(100-need)*0.2`），或给它的**候选打分**加 affinity 项让说话人会改口。
   用 `tools/shadow_analyze.py` 在**同一批提议**上算"会翻哪些决策 / on_target vs collateral"——
   docs/28 的教训是：precision 才是信号（被否的两个 lever 是 0% 和 2%），**别拿轨迹 diff 当证据**。
3. **最后才闭环 A/B**，且必须同时盯四件事：#16 是否还活着、§5.2 的分化极差是否被抹平、
   全镇 affinity 轨迹、以及 `#15-affinity` 的判定。**行为一变就要重烘 Harness + DetGate 双份金标，
   并在同一个 commit 里写清为什么该动**（docs/13:1103 的外部评审警告：一红就重烘会把门退化成快照更新仪式）。

**先做 1，不要跳到 3。** 这个项目已经吃过一次"在没有正确指标之前就动机制"的亏（docs/31：两个 lever 都在修一个不存在的失败）。
