## 〇、这份 brief 哪里是错的（[docs/41 §4](41-baton-contract.md)）

### ① 「W3 发现 `story_test` 跑在不可能变红的配置上」——**对，但它只看见了一半，而另一半没有人认领**

W3 写的是 `story_test` 的 promise/secret/pact 三条弧在 14 天档上全 0/0。**逐位复现，是真的。**
但**同一个 14 天档下面还挂着 `goals_test`**（`CI_GOALS_DAYS` 默认同样是 14），而它的 11 条目标里
**`kept_promise` / `confided` / `pact_formed` 三条结构上不可达**——它们要的正是 `invite`/`meet`、`confide`、`pact`
这三类在 14 天里一次都不发生的事件。CI 里那行 `至少达成 1 条（实际 8/11）` 里的 **8** 不是一个成绩，
**是一个上限**，而且它从来没有被人算过分母。

**还有第三样，就在 `story_test` 自己身上**：14 天档上 **12/12 个 seed 的裁剪列全是 `0`**
⇒ 那两条"进行中 + 终身收场 == 开过"的**逐 seed** 账本断言，跑在一个裁剪从不发生的世界上。

> ⚠ **但我第一版把这一条写过头了，是我自己的变异体把我打回来的。**
> 我原本写的是「为『裁剪咬人』写的那两条断言跑在裁剪从不发生的配置上」，然后去跑负对照：
> 隔离副本里把 `Story._trim()` 的 `_dropped += 1` 删掉（**M1**），seeds 1-2，14 天与 60 天各跑一次 ⇒
> **两格都 `rc=1` 红。** 一看输出就明白了——`story_test` 里有一组**合成** fixture `F-trim`：
> 它手工喂 40 条弧、把它们全部收场，**并且自带一条夹具有效性自证**：
> ```

> 正确的说法收窄成：**空转的是逐 seed 那两条真世界臂，不是"裁剪"这条性质。**
> 这是本棒最该被读到的一条：**"这一格是空的"与"这条性质没人守"是两件事，而我差点把前者讲成后者。**

⇒ 一个默认天数，让 `story_test` 的三条弧、`goals_test` 的三条目标、以及逐 seed 的账本臂**同时**失去输入。
W3 只报了第一样，因为它只 own `Story.gd`。

## 一、方法：**"这道门要判的那件事"要先被定义成一个可以数的东西**

判据的形态决定了问法。逐条读完 41 条不变量与 `ci.sh` 每一步之后，分成四类（分类写进量具，不是写在纸上）：

| 记号 | 形态 | 这一格空洞的定义 |
|---|---|---|
| **C** | 条件式「若 X 发生则 X 良构」 | **X 的实例数 = 0** ⇒ 判据对空输入恒真 |
| **G** | 带显式豁免（`or not harmony` / `agents<=12` / `aid_accepted<8` / `days<60` / off 开关） | **豁免这一格恒放行** |
| **A** | 活性断言（"必须 >0"） | **结构上不可能空洞**——X 归零它就红了 |
| **D** | 诊断档（`DIAG_IDS`） | 永不成门（设计如此） |

**分母收窄两次**，否则这个比例会虚高（[docs/41 §5](41-baton-contract.md)「注意分母」）：
① 只对 **C+G** 问；② 只算这一格**真的当判据用**的那些——我读过源码：
`DetGate` 与 `BackendGate` 只收 `c["hard"]`（26 条），`Harness` 收全部（41 条），
`lod_verify` / `VoiceGate` / `story_test` / `goals_test` **一条不变量都不调**。

量具：`tools/gate_fixture_audit.py` + `tools/gate_fixture_probe.gd`（新，**不进 `ci.sh`**，理由见 §五）。
探针**原样调 `Invariants.check_all`**（不复刻判据——W3 的第一版量具就是复刻出的错），
把 41 条的 `detail` **全文**打出来，另只读地补算一批前件计数。
> **为什么非补这一步不可**：`Harness` **只在失败时**打 `detail`。
> 于是 `aid总=%d`、`背叛=%d`、`派系=%d ingroup对=%d` 这些**已经写在判据里的活输入，绿的时候谁都看不见**。
> 这与 S2 §二·3 的统一结论是同一件事的另一面：**不打印的数没人看得见，看不见的就不会被复核。**

## 三、`story_test` 那一格：修法与代价

### 3.1 先量：14 天档下**四类事件在 12/12 个 seed 上合计 0 次**

隔离副本，12 seed × 14 天 × N=12（= `story_test` / `goals_test` 的默认档），逐类合计（覆盖 seed 数）：

```
invite 0 (0/12)   meet 0 (0/12)   confide 0 (0/12)   pact 0 (0/12)   betray 0 (0/12)   leak 0 (0/12)   aid 0 (0/12)
（同一格里活着的：conflict 345 · apologize 53 · gossip_rep 1302 · produce 249 · election 12 · endorse 24(9/12)）
```

`story_test` 这一跑自己打印的矩阵（**12/12 个 seed 逐行相同的形状**）：

```
seed  grudge   promise  secret   pact     craft     合计(开/收) 裁剪
   1  27/3     0/0      0/0      0/0      5/0       32/3      0
   …（12 行，promise / secret / pact 三列全 0/0，裁剪列全 0）…
结局分布：grudge 进行中 293  mended=52 ｜ promise 0 ｜ secret 0 ｜ pact 0 ｜ craft 进行中 64（**无收场**）
```

⇒ 三件事，一个原因：

### 3.3 改法与理由

**改法**（`tools/ci.sh` 第 5 步，**没有碰 `game/**` 一个字节**）：

```bash
CI_STORY_SEEDS="${CI_STORY_SEEDS:-1-12}"; CI_STORY_DAYS="${CI_STORY_DAYS:-40}"
CI_GOALS_SEEDS="${CI_GOALS_SEEDS:-1-12}"; CI_GOALS_DAYS="${CI_GOALS_DAYS:-14}"
export CI_STORY_SEEDS CI_STORY_DAYS CI_GOALS_SEEDS CI_GOALS_DAYS
```

**代价，两个口径都给**（同一台机器，忙闲不同 ⇒ [docs/41](41-baton-contract.md) 那条"给区间不给单点"在这里是必须的）：

| 口径 | 14 天（旧） | 40 天（新） | 差 |
|---|---:|---:|---:|
| **单跑**（§三·2 那一轮，机器上还有 3 个并行棒的 godot） | 171 s | 491 s | +320 s |
| **在 CI 里**（基线那一跑 vs 收尾那一跑，后者机器已经安静） | ≈156 s | **300 s** | **+144 s** |

⇒ **诚实的说法是「+150..320 s，取决于机器忙不忙」，而不是任何一个单点。**
全量 CI 的前后总墙钟见 §七——**那两个数同样只能这么读**。

**为什么是 40，不是 60**：40 是这条曲线的**膝盖**——五条弧全部拿到真输入、裁剪 12/12、
`craft` 的两个结局都出现；而 40→60 多买到的只有「`pact` 收场」这一件（60 天上 12 个 seed 里也只有 **2** 次）
与更满的覆盖，代价再加 **201 s**。**60 天那一档的代价已经量好了，买不买是用户的决定，不是我的。**

⚠ **为什么没有减 seed 去换天数**（`1-6 × 60 天` 成本相近，是个很诱人的选项）：
60 天上仅有的两次 `pact` 收场落在 **seed 8 与 seed 9**，砍到 `1-6` 恰好把它们砍掉。
**那就是"把 fixture 朝最容易过的方向选"，正是本棒在查的那个病。** 不做。

⚠ **`goals_test` 保持 14 天不动**，并且我把这个"不动"**显式写进了 `ci.sh`**，
好让它是一个看得见的决定而不是一个躺在场景里的默认值。理由：抬它同样要约 +300 s，
而它的判据只查「至少达成 1 条」⇒ **修好夹具也换不来判别力**；真正该改的是那条判据，
而它住在 `game/scripts/goals_test.gd`——**不在本棒的行里**。列进 §四·3 交给用户。
