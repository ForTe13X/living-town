## 一、STEP 1 · 宿主可行性 + 为什么必须用 E4a 多货

玩耍 由 `arcade_1`（type 游戏机、area plaza、pos[33,24]）广告 `{action:玩耍, need:fun, amount:55, duration:22}`——全镇 **fun 吸引力最高**的一条（55 > 逛灯会 62 是节日专属；日常动作里玩耍最高，实测选中 182-234 次/seed/60天 N=12）。
- **玩耍 恒是 object-kind**：arcade_1 是普通 town 对象，agent 选中走 travel→use（Sim.gd `_advance_object`）→ use 相位调 `_consume_for(ag,"玩耍")`。
- **它已有一件 consume 货（整洁）**：改前 `consume.玩耍={good:整洁,amount:1}`（cleanliness 反馈货，与 社交 共享）。所以**不能像 E3b/E3c 那样加裸 dict**——单货结构一个动作只挂一件。这正是 E4a（docs/166）多货机器要解的封顶：改成 `consume.玩耍=[{整洁,1},{风筝,1}]`（Array），E4a 双形状读者自动逐货扣件、逐货记 #40 需求、AND-fold 缺任一件不阻断动作。**零 Sim.gd 改动**（机器 E4a 已落）。
- **no-dilution 保证成立**：缺风筝时 `_consume_for` 返回 false 只喂加价+社会后果，need 照在 use 分支补满；玩耍选中频率不随风筝库存变 ⇒ 不新增决策槽。
- **整洁不受影响（★本片专门验的一格）**：整洁需求 = 玩耍+社交 次数 × 1，**一字未变**（E4a 逐货累加、按列表著者序遍历，风筝是独立的第二件）。实测整洁留出锚中位 **+0.0000**、mean −0.003 ⇒ **平**，证多货机器不碰第一件货的需求。

### 5.4 ★根因：玩耍需求超线性 ×1.72（干净基线实测，与本片改动无关）——scoping 的『玩耍=平滑』被证伪
逐动作需求 N=12→N=16 倍率（人口倍率 ×1.333；干净 pre-E4b 树，seeds 1-12 中位）：

| 动作 | N12 | N16 | 倍率 | 类 |
|---|---|---|---|---|
| **玩耍** | 198 | 340 | **×1.72** | ★**超线性**（唯一） |
| 闲聊（E3b 宿主） | 166 | 179 | ×1.08 | 亚线性——**正是 E3b 糕点过 4a 的原因** |
| 社交 | 54 | 60 | ×1.12 | 亚线性 |
| 喝咖啡 | 108 | 122 | ×1.13 | 亚线性 |
| 歇着 | 65 | 60 | ×0.92 | 持平 |
| 吃饭 | 892 | 1156 | ×1.30 | ≈人口（生存） |
| 睡觉 | 706 | 940 | ×1.33 | =人口（生存） |
| 洗澡 | 540 | 710 | ×1.32 | =人口（生存） |

**玩耍 是唯一超线性的 fun 动作**：高 N 下，池化把生存货产量按人口放大 ⇒ agent 省下的时间灌进 fun，而**全镇 fun 的汇水口是这条吸引力最高（55）的玩耍**——其余 fun 动作（闲聊/社交/喝咖啡/歇着）需求几乎不涨（×0.9-1.13），多出来的 fun 空闲**几乎全被玩耍吸走** ⇒ 玩耍 ×1.72。而单个池化产者（qin）批量只随人口 ×1.333。**供给 ×1.333 追不上需求 ×1.72**（缺口 ~29%）——这与 E3c 那条节日宿主（逛灯会 ×1.7、单产者跟不上）**结构上是同一个失败**。

⇒ **『玩耍 town 平面 + 恒可选 ⇒ 平滑』是错的**：town-plane 不蕴含平滑；玩耍恰因是【最高吸引力的 fun 汇水口】而超线性，是所有 fun 宿主里跨-N 最差的一个。

## 六、★结构规则（本片交给下一棒的最有价值一课）——比 E3c 更锋利

E3c（docs/165）的规则是「挂到需求【随人口平滑涨】的既有动作，而非节日」。本片把它**证伪并精炼**：

> **pivot 的跨-N 稳健性取决于宿主动作的【实测需求-规模斜率】，这条斜率必须【量】、不能从『town 平面 vs 节日』推。** 平滑宿主 = 需求斜率 ≤ 人口（亚线性或 ≈线性）：**闲聊 ×1.08（E3b 的范例，糕点过 4a）**、社交/喝咖啡/歇着 ×0.9-1.13、生存动作 ×1.30-1.33。**玩耍 ×1.72 是 town 平面却超线性**——因为它是全镇 fun 的汇水口，是最差的 fun 宿主。⇒ **E4a 多货机器的下一货应挂到一个【亚线性】宿主**：给闲聊加第二件货（闲聊已挂糕点、E4a Array `[{糕点,1},{新货,1}]`），或挂社交/喝咖啡/歇着（这三条持平、且社交已挂整洁=另一个多货宿主机会）。**别挂玩耍。**
