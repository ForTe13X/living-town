# 218 · P4b 镇长选举与任期

> 接 [217](217-current-p4c-baseline-audit.md)：糕点的旧红已经不成立，P4 的下一块先补治理的可观察底座。
> 本片不开放救济、税率或补贴旋钮；它只让「谁有权在镇公所作决定」成为确定性的游戏事实。

## 做了什么

- 每 28 天举行一次镇长直选。候选是选举日已有镇内名声最高的三名非玩家居民；同名声按 id 排序。
- 每位居民投一票，优先选择自己已有 `standing` 更高的候选；完全相同才按 `(seed, day, voter, candidate)` 的稳定哈希破平。
- 模拟保存 `mayor_log`（候选、票箱、当选人、任期）及 `mayor_state`（现任和截止日）；状态栏和事件流显示当选结果。
- 议题表决和镇长选举共用 `election` 事件类型，但以 `note=mayor_term` 区分。#37 现在分别核对两种事件与各自账本，防止无来源的镇长状态成为后续政策授权。

这条路径不修改关系、钱、岗位或行程，所以它不会把「选举」偷偷变成一条影响生存或供给的政策。P4c 的公务时段、政绩读数和救济窗口只能读取此处的当选/任期记录，再另行测量它们的作用面。

## 验收

`governance_test` 覆盖：配置缺失时治理关闭、第 28 日产生一届任期、三名可见候选中必有当选人、全体非玩家恰好一票、同 seed 完整记录一致、以及第 56 日的下一届边界。`save_load_test` 在已有镇长任期的第 160 tick 存档后继续 60 tick，逐 tick digest 与事件摘要一致。

本地短跑（seed 1，30 天）已过所有硬不变量，#37 显示为「议题 2 场 / 镇长 1 届」。完整 S0 已通过：硬不变量 12/12、#37 12/12、#40 12/12，det 3/3。Harness、DetGate 和 ModelPath 三份锚均已按本片状态重烘；不能沿用 P4c 的摘要。
