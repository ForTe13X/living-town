## 〇、这一波的起点是一句判决

Wave C 把画面从"调试视图"修成了"能看清的小镇"，并把**量具本身**修好了（`--shot` 此前永远渲不出夜）。
三路独立评审（外部对抗 AI + 两个只读 agent，指令均为 REFUTE）给出的判决是同一句：

> **"它看起来明显更好了，而且仍然没有人会玩它。"**

**Wave C 量的全是【可读性】，而可读性不是【吸引力】。** 本项目至今**没有任何能测 playability 的仪器**，
所以 Wave D 的第一条纪律是：

> **★ R9 · 不许再用画面指标替代玩法证据。** 一个视觉数字（接缝跃变、占屏比、亮度比值）只能证明"看得清"。
> 凡是声称"更好玩 / 更想玩 / 更有吸引力"的结论，**必须指出它靠什么证据**；如果没有证据，就写"未测"。
> 这条是 docs/41 §5「数字要有零假设」的下一级：**先问这个数字回答的是不是你正在声称的那个问题。**

> **★ R10 · 每一波必须有一次"有人把整帧看一遍"。** Wave C 的每一条视觉验收都是点采样或 diff-bbox，
> 于是**三样东西进了每一张已发布素材**（录屏光标、印着原始数据键的缺贴图占位块、一块写着「测试阁楼」的招牌）。
> 计划给音频写了"必须有人真的戴耳机听一遍"，**却没给画面写对应那一句**。现在写上：
> **收尾前必须有一次全帧眼验，且必须覆盖"已发布素材"本身，不只是渲染出来的中间帧。**

四项都做了，但**第三条臂换成「闭集封闭」时撞出一个此前没人守的红线缺口**：

一个**凭空捏造**的 intent 只要不违反生存否决就会被 `agent_apply` 原样落地。这是红线 #2 的后半句，此前零覆盖。

`ModelPathGate §C` 选了"烘锚"而不是"删掉门字"，理由是量出来的：`_instant_random` 拿 `capped.size()` 当 RNG 模数，
而 **112/2615 个决策点 |C|>26**（max 57；旧上限 36 只有 14/2615）⇒ 这条臂的轨迹**确实是 cap 的函数**，
而金标看不见这条路。断言 17→23。`--max-starve` 这个死旋钮已删（现场演示：调到 999999 时"无饿穿 4/4 ✅"与"硬 0/4 ❌"同时成立）。

**它纠正了我两处机制**：①"`ubuntu-latest` 带 docker ⇒ 走 native"——docker **无关**，`have_docker()` 还要求

②我预测的是"在未 pin 的 mesa 上假红"，而两份 runner 镜像清单里**根本没有 mesa** ⇒ 更可能的是**拿不到 GL context → 静默 77 SKIP**。
**而 SKIP 与 PASS 都读作"不是红的"** ⇒ 那是比假红更坏的形态。它据此（第三个理由，不是我给的那个）选了显式 skip-on-`$GITHUB_ACTIONS`。

### D3 · 点灯的夜——先证明了"按原路根本不可能"

**机制发现**：在普通绘制路径上，**夜里"一个明亮的暖色像素"在算术上不可能存在**。
tick 488 的 `CanvasModulate` 乘子实测 `(0.4242, 0.4714, 0.7972)` ⇒ 每个通道被钳在 R=108/G=120/B=203，
**纯白的亮度天花板是 123.6**；而未改动的夜帧最亮世界像素已经是 max-ch 187 / luma 113.7 —— **贴着天花板**。
所以必须走**加色混合**（`BLEND_MODE_ADD` 子节点），在已经乘暗之后再加暖色。

| | 改前 | 改后 |
|---|---|---|
| 世界区暖光像素（R>G>B, R−B≥25, max≥110） | **0** | **3220**（91 处光源格） |
| max-channel > 190 的像素 | **0** | **406** |
| 最亮世界像素 | max-ch 187 / luma 113.7 | max-ch 240 / luma **181.5**（越过 123.6 的普通路天花板） |
| 夜间池塘绝对彩度 (max−min) | 127 | **46（−64%）**，草地是 25 |
| 夜间池塘亮度 | 67.2（草地 75.3，**比草地亮**） | **36.6**（终于比草地暗） |
| 玩家金色圆盘（连通块） | **2104 px**（52×52，填充 0.785） | **0** |

> **★ 第九、第十条被证伪的判据（还是我写的）**：
> ⑨「亮度>190 的像素 0 → >0」——**按 luma 讲在夜里按构造不可达**（天花板 123.6）；
> **按 max-channel 讲则可以靠画一个【冷白】像素满足**，即**做与这条缺口要求相反的事也能通过**。
> ⑩「正午帧 diff bbox 必须是 `None`」——**对本棒出货的树不可能成立**，因为派系环与玩家精灵按设计就在白天可见。
> D3 的处置是对的：**把对照分解**——从**最终源码**里只回滚那两处白天可见的 hunk、夜间改动全留，正午渲染 → **bbox `None`**；
> 同一棵树夜里 → 非 `None`。全量 D3 的正午差异 **193 px**，逐簇归因（102 px 在瓦片 (3,3)，7×13 px 是七个派系环）。

**它纠正了我两处**：①「派系环盖住了柔和椭圆影」——**绘制顺序是反的**，环在 agent 循环**之前**画 ⇒ 环在影**之下**。
真正的缺陷是几何的：环是**屏幕平面**的圆（±9.6px），而影是**地平面**压扁到 0.40 的椭圆（±4.8px），两个平面
——而且环长到**穿过了邻居的名牌**。改成同平面椭圆后垂直足迹 ±9.6 → **±5.8px**。
②`sprite:""` ⇒ `draw_circle(#ffd700)` **混淆了两件事**：回退圆盘画的是 `persona.color`（碰巧是金色），
而金**环**是另一条恒开的 `is_player` 标记，两条独立代码路径。

> **★ 又一件东西一直在已发布素材里，而我上一轮的修复是不完整的。**
> `1b20071` 只删了测试空间的**招牌**，**门本身**（门框/门板/门楣暖光/门把/落地阴影）还立在西北角 `[3,3]` 的空草地上。
