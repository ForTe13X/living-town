## 一、A：那个分母

### 1.1 先把问题问准：这里有**三个**分母，而它们的可测性完全不同

| # | 分母 | 定义 | 可测吗 |
|---|---|---|---|
| D1 | **可证伪断言数** | 一份 brief 里有多少句话在原则上能被判真假 | 可数，但很贵；且大量句子（"这条路可能更贵"）根本无真假 |
| D2 | **其中为假的那些** | 上面那些里实际是假的 | **只在被检查过的那些里可观测**——没被检查的，"假"这件事不产生痕迹 |
| D3 | **被抓住的** | 回执 §4 里真的写下来的 | 树上就有，我数过：**100 条 / 16 份回执** |

**"抓住率"= D3 / D2。而 D2 结构上不可枚举**：一条从没被人检查过的假断言，
与一条真断言在文件里长得**一模一样**。⇒ 任何回溯法能给出的都是

```
p_field  =  C / (C + L + U)   ≤   C / (C + L)
             C = 当场抓住     L = 事后才被抓住     U = 至今没人抓住（不可观测，≥0）
```

**⇒ 回溯法给的是上界，不是估计。** 这一点必须写在数字前面，否则下一个人会把上界当点估计用
——[docs/67 §〇](67-wave-r-plan.md) 记着本 session 已经这么栽过一次（把 Wilson 下界 1.3% 当点估计）。

### 2.5 点名：**我认为是纸的那几道**

先分清两种"纸"，否则这一节会被读成一句骂人的话：

- **甲类·结构上不可能红**：判据在它跑的配置里恒真。P3 / P5 / P6 属于这一类。
- **乙类·判据的覆盖远窄于它名字承诺的**：它红起来是真的，但它守的范围比读者以为的小一个数量级。
  P1 / P2 / P4 / P7 属于这一类。**乙类更危险**，因为甲类会被人怀疑，乙类会被人引用。

**P1 · 红线 #4 的版权门（`ci.sh` 第 0 步）——守一条红线，判据是一张手写清单。**
逐字：`grep -iE '\.(gguf|so|dll|bin|safetensors|pt)$'`。
红线 #4 的原文是「**任何**模型权重/预编译二进制」。**实测**（把 11 个样本文件名喂给那条正则）：

```
抓到 3 个：  x.gguf   x.pt   x.safetensors
放行 8 个：  x.onnx   x.tflite   x.pth   x.dlc   x.npz   x.ckpt   y.so.1   y.dylib
```

⇒ **`.pth` 被放行而 `.pt` 被抓**（PyTorch 最常见的那个后缀恰好在清单外）；
**`.dlc`（高通 SNPE 的容器）被放行**；**`libfoo.so.1` 与 `.dylib` 也被放行**，
而它们是字面意义上的"预编译二进制"。
**为什么这不是吹毛求疵**：本仓库的旗舰方向是**端上 NPU 决策**，而 NPU 工具链的产物**正好就是**
`.onnx` / `.tflite` / `.dlc`。⇒ **这道门守得住昨天的 llama.cpp，守不住这个项目自己写在路线图里的明天。**
它是 CI 里唯一一道**判据是枚举、而被守的性质是全称**的门。

**P2 · `lint_links` 检查 (2) 的 `docs/NN@branch` 逃生门——零验证，且它已经放过了一次真事故。**
`tools/lint_links.py:52` 逐字：

```python
if branch:                                      # docs/NN@branch — deliberately off-tree
    continue
```

**不查那条分支存不存在，不查那份文档在那条分支上存不存在。**
实证：`docs/50 §四` 用这个形式引用 `docs/52@worktree-agent-a0c76a3f96ae5dbcf`；
我逐个查过——**那条分支在树上（停在 G5 那一波），而那份 52 号文档不在它上面，任何分支上都没有。**

> **顺带，这道门刚刚在我身上证明了它另一半是有牙的**：本文第一稿把上面这句里的编号写成了裸文本，
> `lint_links` **当场红了三处**并逐行点名。⇒ **同一道门，非 `@branch` 的那一半判别力很强，
> `@branch` 的那一半是零。** 这不是"门弱"，是**门上开了一扇没有锁的窗**。
⇒ 从 Wave H 到今天，**唯一**可能提醒"H4 那个分母实验没交付"的机器，一直在打 `OK`。
**这条逃生门是本波这根棒存在的直接原因。**

**P3 · `BackendGate` 的 C 臂在出货路径上恒真。** 仓库已自认（`ci.sh:361-363`、`BackendGate.gd:25-31`）。
我复述它是因为**它是"自认"这件事做得最好的一次**：`8 个 seed 的『闭集 1332/1332 ✅』是恒真，不是证据`。
本棒这次 CI 的实测四行逐字：`闭集=1328/1328 · 1296/1296 · 1346/1346 · 1292/1292 ✅`
——**四个不同的分母，四个恒等的比值**。分母在变（候选数随轨迹变），分子永远等于它。
今天它有牙**只**因为门内那条 `inject:fabricate` 自检臂——**去掉自检臂，这一臂就是一行装饰。**

**P4 · `#40` 上限臂在 N≤24 是棘轮不是判决**——R1 自认。**而我实测到一格比自认更糟的**：
在 `6c7c8bc`（上限臂标定**之前** 20 小时的树）上，N=16 的"全年零缺货货数"最大值是 **4**（seeds 2, 6），
阈值是 `4×2 > 6` ⇒ **两个 seed 会红 ⇒ 软门（≥11/12）当场破。**
今天是 3，余量恰好一种货。
⇒ **"余量 1 种货"是在一棵刚刚从 4 掉到 3 的树上量的。** 这一步的成因我**没有隔离出来**
（删掉 gossip 两个键之后它仍然是 3）——**没测就是没测**。
但结论不需要成因：**一个阈值的余量在两天内翻过符号，而它的标定只取了后面那一天。**

**P5 · `lod_verify` 作为"值"的门**——`ci.sh:220-221` 自认「它比的是自己跟自己一致，
