# 220 · P4c-2 换届成绩单

> 接 [219](219-p4c-mayor-duty.md)：公务已经真实发生，但上一任离任后，玩家看不到一张固定的任期总结。
> 本片只把已经发生的事实结算成可见成绩单，不让它影响新一届选票，也不开放财政政策。

## 做了什么

- 第 56 日及以后每次换届时，新选举开始前先结清上一届 `mayor_log`。
- 成绩单冻结五项事实：应办公周期、实际办公次数、出勤率、期末镇库、任内镇库净变化。
- 结算同时写一条 `mayor_review` 事件，事件 id 回填到任期记录。大事栏显示“上届镇长、办公完成/应到、任内镇库变化”，所以回看时间线与实时观看得到同一句话。
- 当前届不提前生成成绩单；每个结束任期恰好一条，重复调用不会重结。

这是一片纯观测变更。它不修改投票、关系、需求、钱包、镇库或居民候选，只从换届时多写一条事件。下一步若要让选民按政绩投票，需要单独定义选民权重并重新量完整行为网格。

## 守卫

硬不变量 #37 现在逐字段重算成绩单：执行者必须是该届当选人，目标必须是镇公所，`duties_done/duties_due/attendance_pct/treasury_delta` 必须与任期账本一致，事件 id 必须与 `review_event_id` 双向对应。每个非当前任期必须恰好一条 review，当前任期必须没有。

`governance_test` 覆盖四个七天周期的应到数、25% 出勤、镇库差额和事件绑定。Harness 把 `mayor_review` 加入 60 天活性门；在所有三张网格上，每个 seed 都于第一次换届产生一条。
