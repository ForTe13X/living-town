## 二、AD2 · 事件结果模型设计（**只设计、不实现；产出规格与代价**）

**owns**：**只写**编号 116 的设计文档。**除此之外一个字节都不改**（读代码可以，改代码不行）。
**你的编号文档**：**116**（正文别写 `docs/`+数字纯文本指向 115）

### 要回答的（这是一次 §0.8 立项前设计，不是实现）

问题（Codex red #3 + AA2 实测）：**Sim 的状态转移是权威语义，而表现层把 rejected event 叙述成 happened。**
AA2 量到 3565 条引用里 976 条（27.4%）如此；根因是 `discuss`/`gossip`/`gossip_rep` 那族匹配器不筛 `accepted`，
且 `Sim` 记忆文案说"被婉拒"而 `Main._event_prose` 对同类型不分岔——**两路打架，AA2 按 §0.8 没动。**

⇒ 提议的模型（用户/Codex 给的形状）：事件显式携带 **`attempted` / `accepted` / `effect_applied` / `rejection_reason`**，
Sim 为唯一权威；表现层只在 `effect_applied=true` 时叙述结果，否则叙述"尝试"或"被拒"。

**设计文档要给出**：
1. **现状盘点（读码，给行号）**：今天 `event_log` 的事件字典**已经有哪些字段**？`accepted` 现在谁写、谁读、
   覆盖哪些事件类型？哪些类型**根本没有** accepted 概念（如 `produce`/`pay`）？——**先量，别假设。**
2. **三种（或更多）实现路各自的**：schema 改动、**金标影响**（会动多少 seed 的 digest/chain——给推断依据）、
   迁移成本、对现有 40+ 不变量的冲击、对 AA2 短语锁 / narrative 层的下游影响。
   候选至少含：(a) 在现有 event dict 上加字段；(b) 单独的 outcome 事件；(c) 每次 attempt 一条记录。
3. **推荐一条 + 理由**，并**明写它需要走完整 R12**（几乎必然移动金标）。
4. **分阶段迁移方案**：别一次全改——按事件类型的"被拒可观测性"排序，第一阶段先覆盖哪几类。
5. **风险与未知**：哪些是设计阶段答不了、必须实现后实测的（照实列，别装作都想清楚了）。

⚠️ **不许在本波实现任何一行。** 这是给用户的立项材料。**红数不是判据、改判据/schema 是用户的决定**——
你的产出是让用户能拍板，不是替他拍。

### 验收（AD2）

1. 现状盘点表（字段 × 谁写谁读 × 覆盖的事件类型，**给行号**）。
2. 三条实现路的代价对照（**金标影响给推断依据，不是"应该不大"**）。
3. 推荐 + 分阶段方案 + 风险清单。
4. **零代码改动**（`git diff` 只应有 116 号那份设计文档）。
