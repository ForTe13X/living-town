**已接线**（[WorldView.gd](../game/scripts/WorldView.gd) + [Art.gd](../game/scripts/Art.gd)）：
- **地面**：逐格在草地变体间确定性选择（`grass_a/grass_b/grass_flowers`，hash 加权），不再单图平铺（`Art.terrain_tex`）。
- **装饰散布**：区域外草地上确定性撒开花灌木/草丛/石/树桩/蘑菇（`Art.decor_tex`，~22% 密度，避开区域与物件）。
  **树不在散布池里**（`WorldView.DECOR_POOL` 实测只有 bush / flower_red / flower_yellow / rock / stump / mushroom 六项）——
  会挡路的树是 `map.json` 的 authored `trees` 层，另走 `decor_tex("tree_big")`。
- **区域即建筑**（`WorldView._draw_area_floors` / `_draw_facades` / `_draw_building_dressing` / `_draw_sign`，
  外墙那一层没有独立函数、直接写在 `_draw_body` 的 `walls` 分支里，按 `_wall_type` 查 `BLD_PAL` 上色；
  **全部纯程序化，一张贴图都不用**）：
  分类型地板（木板/石板/铺装）+ 三段式有厚度外墙（顶棱高光/主面/墙脚暗边）+ 等距开窗
  （夜里分「点灯 = 暖玻璃 + 外溢光池」「熄灯 = 冷暗玻璃」两档）+ 悬挑屋檐与脊线高光
  + 住宅/工坊的冒烟烟囱 + 按 type 各一款招牌（咖啡杯 / ♨ / 烟囱 / 山墙小屋剪影）。
- **居民**：按 `personas.json` 的 `sprite` 取 Puny 角色表，**4 向行走动画**（`_agent_frame` 按移动选帧：down/横向=row1、上=row3，cols0–3 循环；静止=正面 idle）。
  - 映射：阿丽=Mage-Red · 阿本=Warrior-Blue · 可可=Mage-Cyan · 老邓=Soldier-Yellow · 小薇=Archer-Green · 阿菲=Archer-Purple。
- **物件**（`Art.object_tex(slot)`，**slot 来自 `WorldView.OBJ_SLOT_BY_TYPE` 这张显式表、key 是数据的 `type` 字段**——
  H3 2026-07-30 把旧的 `id.split("_")[0]` 隐式约定换掉了）：bath=井、counter=货摊、bench=木桌、desk=工作台、arcade=招牌
  （来自 overworld tileset，CC0）；**bed/stove 保留程序化**（该 pack 无室内家具，如实）；表里没有的 type ⇒ 品红占位 + `push_error`，不静默兜底。
  ⚠️ 这 5 张贴图今天被 **16 个** 镇上物件共用（bench 一张服务长椅/清扫车/渔台/砖垛/柴垛五种），别名预算见 `WorldView.OBJ_SLOT_ALIAS_BUDGET`。
- **emote 气泡**（`Art.emote_tex(event)`）：社交事件触发，actor/target 头顶短暂显示对应表情；10 事件→cell 映射见下。**注**：emotes 表无 angry/heart，conflict 用"忧虑"脸代替。

**这些 atlas 规格由一次并行 Workflow 产出**（3 个 agent 并行只读分析 emotes/角色表/overworld 三张网格图→返回精确 (col,row) 规格；主流程据规格 `tools/slice.py`/`slice_all.py` 切图 + 接代码）。emote 事件映射（col,row @20px）：greet(3,1) give(0,3) gossip(0,1) invite(2,5) meet✓(2,3) meet✗(5,3) conflict(6,1) confront(3,2) apologize✓(5,5) apologize✗(0,4)。

### 1.1 已删除：`building/{house,hut,shop}.png` 与 `Art.building_tex()`（I2，2026-07-30）

上面这份"已接线"清单里曾有一条 **`- 区域地标：每个区角放一座小屋 hut（Art.building_tex），分区像"街区"`**。
**那句话在 2026-07-15 就已经不成立了，而它在文档里又活了 15 天。**

- **它不是"没接线"，是接过线又被当成 bug 拆掉的。** 拆它的 commit 是 `841d4c4`
  *"art: buildings with real mass + interior decoration + lamp light"*，其正文把它列为用户报的**「比例失调」的头号成因**：
  > "a decorative 1-tile `hut` icon was drawn at each area corner (hut.png is 16x16 -> 48px = **exactly ONE tile**),
  > i.e. **a whole house the size of a person**. … **Removed the hut lie** and made rooms render as actual buildings"
- **替代品更宽，不是更窄**：hut 只有一张，全镇 9 个区共用同一个图标；今天的程序化建筑按 **4 种 type** 各画一款招牌与配色。
- **剩下两张贴图本来也不能用**（I2 10× 眼验，`house.png` 16×64 / `shop.png` 32×64）：它们是从图集上**竖着切下来的多格条带**，
  四边都是断口——`shop.png` 里挤着**六个**橙顶石屋的残片。与 H1 判 `decor/tree_big`「需要重切」的是**同一种病**：
  切的是图集区域，不是一个精灵。接线只会把那个病复制到建筑上。
  证据图（H1 出的，我独立复核逐张一致）：[`media/h1_building_sheet_10x.png`](media/h1_building_sheet_10x.png)。

⇒ 三张 png、`Art.building_tex()`、`tools/slice_visual.py` 里的三行配方、`tools/asset_gate.py` 的三条 `NOT_GATED`
**同批删除**。棘轮没有随之消失：`asset_gate.check_deleted()` 现在守的是**"删干净了"**——
这三个名字在出货目录 / 切图配方 / `.gd` 引用**三处都不许回来**（详见该文件）。
