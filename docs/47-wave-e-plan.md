## 一、为什么是"社会产出"——先说清现状，别在推断上盖楼

**实测（以代码为准，不是设计文档）**：`game/data/jobs.json` 给每个居民一个 `{title, action, wage, shift}`，
`Sim.gd:1281-1300` 在有薪动作完成时由**镇库**发工资，`_wage_for` 让本职在班拿职位工资、其余人拿零工价。
经济闭环是 `吃饭付费 → 镇库 → 做活发薪`，由硬不变量 **#34（金钱守恒）** 与 **#35（余额非负）** 守着。

> **★ 所以现在的分工只有【行为】没有【产出】：木匠"做活"什么也没造出来，面点师"做活"没有面包被谁吃掉。**
> **把全镇的工作行为全部删掉，除了钱包数字，世界逐格相同。** 劳动是**装饰性**的。
> 这正是本波要改的那一件事——也是"商贩/环卫/建筑各有 behavior 和社会产出"这句话的落点。

**必须一起说清的边界**：钱在本项目里的设计意图是**造分化与戏剧，不造饿死**（`economy.json` 的 `_doc` 明写：
付不起照吃 `meals_free`）。**产出系统必须继承这条**——缺货可以让人不满、可以造成八卦与冲突，
**不得**成为新的饿死通道。硬不变量 #01 是硬的。

### E1 · 劳动产出与消耗闭环（**本波核心，会移动金标**）

**独占 `Sim.gd` + 新 `game/data/production.json` + `Invariants.gd` + `golden_digests.json`。不得动 `Main.gd`/`WorldView.gd`（E2/E3 在用）。**

**做什么**：让"做活/看摊"产出**具体的东西**，让别人**消耗**它，让**缺货有后果**。最小闭环建议：

- **产出**：本职在班完成一次工作 → 往一个**镇级库存**里加一件（面点师→面包、木匠→木料、商贩→货、环卫→"整洁度"）。
- **消耗**：既有动作去扣它（吃饭优先扣面包；修缮/建造扣木料；整洁度随时间衰减、环卫补）。
- **后果**：缺货**不造成饿死**（红线：`meals_free` 那条设计意图继承下来），而是造成**可观测的社会后果**
  ——不满、议论、声誉变化、或某个动作变贵/变慢。**后果必须写进 `event_log`**，否则 E2 讲不出故事、编年史也看不见。

**数据驱动 + 缺文件即零扰动**（照抄 `jobs.json`/`economy.json` 已经验证好用的那套）：
`production.json` 缺失 ⇒ 产出系统整个关闭 ⇒ **逐字节回到今天的轨迹**。这条本身要有一个断言。

**验收（R12 全套，一条都不能省）**
- **零扰动对照**：删掉 `production.json` ⇒ 金标**逐字节等于今天**。**这是最重要的一条**，它证明新机制是可 ablate 的。
- **开启后**：`Harness --bake-golden` + `DetGate --bake-golden` 都跑；`_meta.rebake_history` 补一条。
- **留出种子**：改前/改后各跑 `--seeds 13-30 --days 60`，**两侧数字都报**。硬不变量必须 18/18 全绿。
- **硬不变量 #01 不许破**：报**逐 seed 的饿穿计数**，不是"没看到饿穿"。
- **#34 金钱守恒不许破**：如果产出涉及买卖，`transfer` 仍是唯一通道。
- **新增至少一条不变量**守着新机制（例如"库存非负"、"产出/消耗账本可溯源"），并给它一个**负对照**证明它会红。
- **R9**：能证明的是"劳动现在改变世界状态"，**不是**"游戏更好玩了"。

### E2 · 把事件链讲成故事（View 侧，零仿真风险）

**独占新 `game/scripts/Story.gd` 与 `game/scripts/Main.gd`。不得动 `Sim.gd`。**

D2 的 `Goals.gd` 已经证明了这条路走得通：**对 `event_log` 的纯 fold，回放等价 30/30 seed**。
E2 是它的下一步——**目标是"还差几件"，故事是"发生了什么"**：把因果链
（邀约 → 爽约 → 积怨 → 对质 → 道歉 → 和解 / 或 → 冷战 → 泄密 → 背叛）识别出来，
**按人**讲成一段有开头结尾的短叙事，而不是按时间倒序刷屏。

**必须复用而不是重写**：`Sim._verb` 与编年史已有的中文措辞（docs/43 记过"用中文讲出来而不是打印枚举名"），
`Goals.gd` 的 fold 结构与 `chain` 见证做法。**红线同 D2**：只读派生，**绝不写世界状态**。

**验收**
- **回放等价**：`goto_tick(T)` 与 `goto_tick(T/2)` 之后从 `event_log` 重算的故事状态逐字段相同 + `chain` 见证。
  **12 调参 seed + 18 留出 seed**（D2 的做法，别自己发明）。
- **判别力**：给一个**故事必然为空**的对照（例如只喂 greet 的 fixture），证明这条断言不是平凡通过的
  ——D2 报告里明写"一个什么都不记录的 tracker 也能通过 `live == replay`"。
- 金标逐字节不动；`probe_digest_test.sh` 与改动前同值（**自己跑基线**）。
- **R10** 全帧眼验 + 多缩放档。

### E3 · 角色去道具 pass（原 D8）

**独占 `game/assets/art/` 与 `tools/` 下你新建的脚本。不得动 `game/scripts/*`。**

裁决与许可分析在 [docs/44 §一](44-art-direction.md)：现用 CC0 素材包是**奇幻 RPG 原型**（尖帽/法杖/弓箭/盔甲），
与咖啡馆-澡堂-工坊的现代小镇题材打架。**CC0 允许修改** ⇒ 这是一次**去道具 pass**（自绘衍生），
**不是**重做整套，也**不是** AI 出图（docs/43 R2：生成图只能当情绪板，绝不进精灵帧）。

**验收**
- **逐帧对照**：改前/改后精灵表并排 4× 放大，**每个居民每个朝向每一帧都要看**（R10；D3 的教训是"只看一个缩放档"）。
- **不许把轮廓改糊**：报**改动像素数**与**剪影（alpha 通道）变化率**——去掉尖帽会改剪影，这是有意的；
  但身体轮廓不该动。
- **在游戏里看**：`--shot` 一张跟随相机帧眼验（`shot1.sh` 默认会走 1.8× 特写，正好适合看人）。
- **许可**：产物是对 CC0 的修改 ⇒ 仍是 CC0/自绘。在 `game/assets/art/` 下留一份说明写清改了什么、源是什么。
- 金标逐字节不动（纯资产替换）。
