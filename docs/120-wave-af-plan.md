### 背景（我已复核，给你坐标）

当前"逐字节一致"的真实含义很窄：`Inv.digest`（`Invariants.gd:1280`）**只折 `event_log`**；

AC1（wip 分支 `origin/wip/ac1-state-projection`）已建只读探针 `game/bench/ac1_state_coverage.gd`（607 行，**未验证**）。

### 要做的（这是设计，不是实现）

1. **验证/重测 AC1 的形状**：把 AC1 的探针从 wip 分支取出（`git show origin/wip/ac1-state-projection:game/bench/ac1_state_coverage.gd`），
   在**隔离副本**里跑，核对它的"哪些状态驱动未来、哪些进/不进 digest/chain"结论。
   ⚠️ **判据要可执行**：一个字段"驱动未来" = **存在一条从它到某个决策/事件的读路径**（`grep` + `git log -S` 证，别读注释）。
   ⚠️ **别用"一天前后变没变"代替"未来读不读"**（Codex 对 AC1 的原话批评）——要覆盖**静态、晚触发、中途恢复**。
2. **干预实证**（AC1 未验证，你来坐实一条）：挑 1-2 个"不进 digest 但驱动未来"的字段（如 `beliefs`/`stock`/`space·floor`），
   造一个**只改它**的干预，跑两件事：① digest/chain 变不变（预期不变=问题）；② **后续行为**变不变（=驱动未来的证据）。
   **两件都要跑**（红数不是判据；只有①没有②说明字段其实死了，那也是结果）。
3. **三种（或更多）实现路的代价对照**：`state_projection_v1` 怎么建——
   (a) 扩现有 `Inv.digest` 折进更多字段；(b) **并行新增**一个 `state_projection`（Codex 推荐，不重写旧 digest）；
   (c) 对高维状态（关系/信念）用**确定性增量子摘要**避免每 tick 全量扫。
   逐条给：**金标影响**（几乎必然全动，给推断依据）、迁移成本、对 40+ 不变量与存档/LOD 的下游影响、性能（每 tick 成本）。
4. **推荐一条 + 分阶段方案**：按"驱动未来的证据强度"排序先覆盖哪些字段；明写走完整 R12。
5. **风险与未知**：`space·floor` 的盲窗、0-1784 tick 盲窗、性能预算（N=60/100+）、与存档/换页的接口——**照实列，别装作想清楚了**。
