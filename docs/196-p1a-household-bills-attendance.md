## 一、做了什么

全部在 `economy.json` 三个新段里，缺段即关（agent 不长新字段、逐字节回到 P0）：

| 段 | 机制 | 钱路 |
|---|---|---|
| `bills` | 每 2 夜，每位核心居民（非外来码头工、非玩家）付 **水电 1 币**；冬季再加 **炭火 1 币**。付不起不阻断任何事，只记 **欠费 `arrears`**；每夜先尽量还旧欠。 | `transfer(居民→镇库, "bill:水电/炭火/欠费")` |
| `hardship` | **困顿不挨饿**（用户定）：欠着水电费时洗澡只补 **60%**（热水停了），打折后不低于 30，只动【这一次】option 的补给量，从不改 need 上限、从不阻断。付不起饭钱仍照吃照补满（= master 的 meals_free）；"饭钱记进欠费（赊账）"的开关 `unpaid_to_arrears` 保留、**默认关**（§二·2 的负结果）。 | 无 |
| `attendance` | 岗位持有人当天在班内完成过一次本职 ⇒ 出勤，否则记一次缺勤；连续 5 天出勤 ⇒ 镇库发 **全勤奖 2 币**。`work.rep`（−10..10）只进语音/HUD。 | `transfer(镇库→居民, "bonus:全勤")` |
| `bills.arrears_work_urgency` | 欠着账 ⇒ 不在班时零工加分。**机制保留、默认 0**（§四：6.0 时 N=16 丢一个 seed）。欠账的上工动机仍由既有 `poor_line` 的 `work_urgency` 承担。 | 无 |

- **账本**：`Ledger.gd` 加 `bill`（镇库收）与 `bonus`（镇库支）两类；面板多一行「欠水电费 N 人，共 X 币」。
- **记忆**（语音 grounding）：交不起账、还清欠费、凉水澡、全勤奖、一趟工没上。
- **守住的规则**：钱只经 `transfer`（#34 与 P0 账本核对不改）；欠费/出勤/`work.rep` 不进 `_acceptance_margin`、不进任何满足度路径（docs/175 核心规则）；困顿只打折不阻断（#01）。

### 2. 付不起饭钱该怎么"疼"——三个负结果，最后选了"不疼"

| 版本 | 做法 | 实测 | 判决 |
|---|---|---|---|
| A | 这顿只补 75-80% | N=12 seed 9：打折的饭要多吃几顿 ⇒ 口粮缺货 187 → **375**，#40 **11/12**；N=16 #40 **10/12**（master 11/12）。另一半原因：欠账拉力当时也拉本职 ⇒ 柴薪/屋瓦全年零缺货（#40 上限臂「多数不缺」） | 丢 |
| B | 照补满，扣 fun −8（不压到 46 以下） | N=12 #40 **12/12**；N=16 #40 **5/12**：口粮缺货 600 → **1039**，面点师本职 41 → **24** 次——**本镇的劳动是 fun 需求驱动的**，烤点的 fun 只有 20（全部工位最低），fun 一低面点师就去玩耍 | 丢 |
| C | 照补满，饭钱记进欠费（赊账，封顶 20） | N=16：口粮缺货 707（P0 600）、面点师 36 次，接近；但 **16 人里 13-14 人常年欠到封顶**、零工 845 → 1400、洗澡 +40%（凉水澡要多洗）——困顿成了人人都有，不再分化 | 机制保留、默认关 |
| **出货** | 照吃照补满，不另加代价；困顿只从欠账单来 | 见 §四 | ✅ |

**共同根因**是同一个：镇库只进不出（§三）。钱从居民流向镇库、只在有人做完工时流回来，
于是任何"没钱就疼"的机制，疼的都是几乎所有人。真正的解是 P4 的财政环；在那之前，饭钱这一刀不砍。

### 3. 第一版的另一个负结果：每夜收账每夜收账只是把钱从居民兜里搬进镇库——付不起的饭翻倍、因为打折的饭要多吃几顿，
**上工反而少了**（饿得勤、吃得勤，占掉的正是上工的时间），而 `poor_line` 那条动机环早就对所有穷人都开着了、没有余量再拉。
⇒ 两处改动：账单隔夜收（压力减半）、欠着账时给有薪动作一条**额外**的拉力（让"欠钱"本身成为出门做工的理由）。

## 三、已知的、留给后面相位的

- **镇库只进不出地攒钱**（146-169 vs 74）：账单是一条新的居民→镇库流，而镇库只在有人做完工时才付出钱。
  这是 194 §二·4 的**财政环**要解决的事（镇库补贴、公共开支、税）——P4 的活。本片不在这里造一个临时的回流。
- **缺勤率约 20%/天**（每 seed 60 天约 490 次缺勤 / 13 个岗位）：P0 上没有记录所以没有对照，但本职完成数本来就是这个量级；
  本片只记录、不惩罚（除了断掉全勤连胜）。迟到扣薪没做：要先有作息表（P1b）才谈得上"迟到"。
- 期末有的 seed 某种货见底（柴薪/屋瓦/豆子各在一个 seed 上为 0）：见 §四 #40 的判决。

## 五、为什么 P1b（家当/采买、作息表/休息日）分出去

- **全部 12 位居民住同一个"住宅区"**（agents.json 的 home 全在 y=14/15 两行）⇒ "每户一个家当"在今天的数据上就是"每人一个"，
  而家里的厨房在 docs/193 之后是**不能用**的（"家里什么都有 ⇒ 不出门"那个陷阱）。家当要重新打开家里的厨房、再用"会用完、要出门买"把人推出去——
  这是一次和 193 同类的平衡实验，值得单独一片、单独量"出门次数"。
- **休息日**要按人轮换班次，而 `_in_shift(job)` 今天只拿到岗位、不知道是谁 ⇒ 要改签名、牵动三处"本职在班"口径（`_produce_for` / `_wage_for` / 技能）。
  跟作息表一起做。
