# 187 · 欲望 v0：模仿中介的、不终结的欲望（步骤 1-4 已实现，缺省关闭）

> 触发：用户 2026-09-12——给居民加"欲望"（libidinal / eros，随当前状态变化；得不到满足则与"他者"冲突；可延宕但有代价）。
> 初稿先过了一轮对抗评审（见 §一），本稿只写**评审后幸存的 v0**。另应用户要求：全程盯"行为/社交花样变多"本身的影响（§六）。

## 〇、一句话

need 是稳态的（掉、补到 100、停）；欲望**永不终结**（满足只让它换对象），且**经由他人成形**（我想要别人显得想要的东西）。
v0 只做这两件事，其余（空虚态、升华、压抑爆发、占有物对象）一概不做。

## 一、对抗评审结论（为什么是 v0 而不是初稿）

| # | 初稿问题 | v0 的处理 |
|---|---|---|
| 1 | 张力 debuff 乘在【所有】need 的补充量上 ⇒ 新饿穿通道；且 `_survival_pull` 只管 social，初稿"生存会压住欲望"的说法不成立 | 欲望**不碰任何 need 数值**；只给社交候选加分；强度在 `min_need < SURVIVAL_GATE` 时**结构性**不增长 |
| 2 | "空虚态"只能靠他人认可才出来 ⇒ 不受欢迎/寡言者进去就出不来（吸收态） | v0 无空虚态；另有**内生出口**：屡被拒 → 放弃对象（§三·5） |
| 3 | 另起"对手边"与现有冲突弧（simmering→confront→repaired，`resentment`/`standing`）重复计账 | 对手关系**只作为 `_bump_resentment` 的一个新来源**接入现有弧 |
| 4 | 模仿项读"别人想要什么" ⇒ 越过知识边界 | 只用**亲眼所见**的事件（`event_log` 的 `witnesses`）作证据 |
| 5 | 升华产出 ⇒ 向闭环 coin 注水 | v0 无升华；对象类型不含钱/物 |
| 6 | 很可能只是"第二个 fun 条" | 验收以**消融**为准（§五）：数值机制关掉若行为无可测差异 ⇒ 砍 |
| 7 | "滑向邻近对象"没有度量 | 对象只有两类、候选表显式枚举（§三·2） |
| 8 | 新常数约 10 个 | 压到 6 个，全走数据文件，每个都要平台论证 |
| 9 | 人作对象 + 不回应的追求 ⇒ 执念/尾随剧情 | 满足需对方 affinity；不回应 ⇒ 换对象，不升级 |
| 10 | 理论上：水压标量是早期弗洛伊德、s² 是马斯洛、"空虚"误读拉康 | 本稿**不声称理论忠实**；可保留的是两条结构性洞见：不终结 + 他者中介（Girard） |

## 二、门控与确定性（沿用本仓纪律）

- 数据门：`data/desire.json` 缺失 ⇒ `desire_on=false` ⇒ 不建状态、不加分、不消耗 RNG ⇒ **event_digest 逐字节不变**。
  判据写成 fail-closed（参照 F5：空数组/缺键不得翻转为"全开"）。
- 生存门：强度增长乘 `mods_ok`（= `_min_need(ag) >= SURVIVAL_GATE`），与节律/天气/季节/整洁度同一道门。
  另外社交候选本身在 `min_need < SURVIVAL_GATE` 时就返回空（[Sim.gd:3557](../game/scripts/Sim.gd)）⇒ 加分在危机时**无处可加**。双保险。
- 随机：只在对象重选的平局抖动处用 `_rng_at(<新盐>, _aid(ag))`；`_rng_at` 每次新建子流 ⇒ 不扰动现有流。新盐实现时须 grep 确认未被占用。
- 规模：证据只扫"本 agent 作为 witness 的近期事件"，不做 Σ_j 全量两两 ⇒ 不重新引入 `_social_candidates` 已消掉的 O(N²)。

## 三、机制

### 1. 状态

```
ag["desire"] = {
  kind:      "person" | "status",   # v0 仅两类
  target:    agent_id | "",         # person：想亲近的人；status：想被认可（target 留空）
  intensity: 0..100,
  since:     tick,
  rebuffs:   int,                   # 对 target 的主动示好被拒次数（本对象周期内）
  recent:    [agent_id × K],        # 近 K 个已换掉的对象（新鲜度，防回锅）
}
```

### 2. 对象候选（显式枚举，只用亲眼所见）

- **person**：窗口 `W` 内，本 agent 作为 witness 看到的、第三方 j 对 X 发起且**被接受**的亲近动作（give / invite / confide / endorse）。
  权重 = Σ 该类事件 × (1 + 我对 j 的 affinity/100)⁺ ——"我欣赏的人在追的人"更有吸引力（模仿中介）。
  排除：自己、`recent` 里的人、对我 affinity < `A_MIN` 的人（对方明显不待见 ⇒ 不入选，从源头挡执念）。
- **status**：窗口内看到 endorse 事件 ≥1 且我自己的平均 standing 低于镇中位数 ⇒ 候选"想被认可"。
- 权重 cap 为 `MIMETIC_CAP`，防全镇同时盯上一个人（见 §六 集中度指标）。
- 无候选 ⇒ `target=""`、强度不增长。

### 3. 强度

```
intensity += GAIN × mods_ok × (1 − intensity/100)      # 有界、生存门内才长
```

v0 **不**让强度随 need 满足度的平方增长（那是初稿的马斯洛项，已砍）；它只受生存门开关。

### 4. 作用点（唯一的行为效应）

在 `_social_candidates` 里，对 `partner == target` 的**深层**动作（give / invite / confide）加
`BONUS_K × intensity/100`；status 欲望则加给能换来认可的动作（aid / endorse 他人以求回报）。

**不加给 greet**。理由（实测于 [Sim.gd:3590-3597](../game/scripts/Sim.gd)）：greet 对同一对象无条件发起、已严格支配 gossip；
把欲望加到 greet 上只会产出"对目标多打几次招呼"，花样**不增反减**。

局限（有意为之）：social ≥ `SOCIAL_FULL` 时社交候选为空 ⇒ 欲望只改变"社交时找谁、做什么"，不改变"要不要社交"。

### 5. 满足、换对象、放弃

- **部分满足**：与 target 的深层动作被接受 ⇒ `intensity *= (1 − RHO)`，并**强制重选对象**（旧 target 入 `recent`）。永不归零 = 不终结。
- **放弃（内生出口）**：对 target 的示好被拒 `rebuffs ≥ R_MAX` ⇒ 放弃该对象、入 `recent`、强度减半。不回应 ⇒ 转移，不升级。
- 重选：候选权重 argmax，平局用 `_rng_at` 抖动。

### 6. 与他者的冲突（接入现有弧）

A 目睹 B 与 A 的 target 发生被接受的深层动作，且 A 的 `rebuffs > 0`（A 求而不得、B 得到了）⇒
`_bump_resentment(A, B, RIVAL_AMT)`。每对 (A,B) 每日至多一次。之后 simmering → confront → repaired/escalated 全走现有代码、现有 `standing` 账。

### 7. LLM 叙事

有 backend 时，decide prompt 追加一行自然语言，不给数字（如「你最近总想着和美多待一会儿；可豆好像跟她更近」）。
只陈述 agent 自己的欲望 + 亲眼所见，不泄露他人内心。

## 四、常数（全部进 `data/desire.json`，缺键 = 缺文件 = 关）

| 键 | 含义 | 初值（待平台标定） |
|---|---|---|
| `gain` | 每 tick 强度增长 | 0.15 |
| `bonus_k` | 满强度时对深层动作的加分 | 8.0 |
| `rho` | 一次满足削掉的比例 | 0.6 |
| `rival_amt` | 目睹"情敌得手"的怨气 | 3.0 |
| `mimetic_cap` | 单一候选权重上限 | 5.0 |
| `r_max` | 放弃前允许的被拒次数 | 3 |

`W`、`K`、`A_MIN` 先写死为代码常数，不开放调参。每个开放常数上线前按本仓惯例给出平台区间，取中点而非边缘。

## 五、验收：消融（先于任何"好不好玩"的判断）

四档，logic backend（`backend=null`）为主，seed 1-12 × 45 天 × N=12 / N=40：

| 档 | desire.json | prompt 行 | 回答的问题 |
|---|---|---|---|
| A | 无 | 无 | 基线；须与 master 的 event_digest 逐字节一致 |
| B | 有 | 无 | 数值机制本身改变了行为吗？ |
| C | 无 | 有（LLM 档） | 叙事行单独能做到多少？ |
| D | 有 | 有（LLM 档） | 两者叠加 |

**砍掉条件**：B 相对 A 在 §六 的花样指标上无显著差异（12 seed 的差值区间跨 0）⇒ 数值机制是装饰，只保留 C 的叙事行或整体放弃。
**硬红**：任一档 need_floor ≤ `STARVE_NEED`，或 n40 hard-red 任何一格变红 ⇒ 不合并。

新增不变量（进 `Invariants.gd`）：
- **D1** 缺 `desire.json` ⇒ digest 与关时一致。
- **D2** `min_need < SURVIVAL_GATE` 的 agent-tick，强度增量恒为 0。
- **D3** 欲望加分只出现在 social 候选上（hunger/energy/物件候选上恒 0，结构性，不靠门）。
- **D4** 无 agent 在 `rebuffs ≥ r_max` 后仍持有同一 target（反执念）。

## 六、盯住"花样变多"本身的影响

花样不是免费的，也不是越多越好——均匀随机的熵最大。以下每一项在 A/B 两档都要报，B−A 给差值区间。

### 1. 花样（想要它涨）

| 指标 | 来源 | 说明 |
|---|---|---|
| 动作分布香农熵 | `BackendBench._entropy` | 全镇层面 |
| 人均动作种类数 | `BackendBench._variety` | 个体层面；与熵可背离（每人各做一件不同的事也能熵高） |
| 事件类型数 / 事件熵 | `ab_metrics` `event_types`, `entropy` | 事件层面 |
| greet 占社交动作比 | 新增 | 当前 greet 支配；期望 B 档下降 |
| 深层动作（give/invite/confide）占比 | 新增 | 欲望的直接产物 |

### 2. 代价（要它不坏）

| 指标 | 来源 | 风险 |
|---|---|---|
| need_floor / 饿穿 | `ab_metrics` | 社交更"有吸引力" ⇒ 候选挤占生存（docs/12 R5 的老问题） |
| 冲突数、完成率、悬空弧 `dangling` | `ab_metrics` | 情敌怨气让冲突变多，但弧收不完 ⇒ 镇上积怨，#15 社会分层被冲 |
| `drama_per_day` | `ab_metrics` | 戏剧节拍过密 ⇒ 稀缺性没了，每场戏都不值钱 |
| 目标集中度（被欲望指向次数的 Gini） | 新增 | 模仿滚雪球：全镇盯一个人 |
| 对象换手率（每人每周换对象次数） | 新增 | 太高 = 注意力像噪声，太低 = 执念 |
| 叙事连贯度：同一 (A,target) 的连续深层动作链长度 | 新增 | 熵涨但链长掉 ⇒ 花样是乱不是戏 |
| tick 耗时、LLM prompt token | Harness | N=40/62 下的成本 |

### 3. 判读规则

- 熵涨 **且** 链长不掉 **且** completion 不掉 ⇒ 真花样。
- 熵涨但链长掉 ⇒ 噪声，调低 `bonus_k` 或放宽 `rho`。
- 深层动作涨但 greet 占比不动 ⇒ 欲望只是叠在原有社交之上，挤占的是别的东西——查挤掉了什么（很可能是 gossip ⇒ 谣言传播又变差，对照 O1）。
- 冲突数涨但 dangling 也涨 ⇒ `rival_amt` 过大或每日上限没生效。

## 七、不做（留给 v1 之后，且各自需要独立评审）

空虚态、升华（任何进 coin 的通道）、压抑/爆发事件、占有物/地点对象、玩家可见的欲望图标（会破坏"他者不可读"）、跨对象"邻近滑移"。

## 七·五、步骤 1-2 实现记录（与上文设计的偏差，据实）

- **配置不入档**：`desire_cfg` 进 `SAVE_LOAD_DENY`。存档按反射收全部 script var 且 fail-closed，
  新增一个入档 var 会改 schema-2 形状、让旧档全被拒。每人状态住 `agent["desire"]`，随 agents 深拷贝入档。
- **开关必须显式布尔 `"enabled": true`**；`1` / `"true"` / 缺键一律关。
- **平局不用 `_rng_at`，用 `_hash01`**（纯函数）：本步零 RNG 消耗，比"新盐"更干净。§二那条随之作废。
- **"对方不待见"改读我自己的 affinity**（`DESIRE_AFF_MIN=-10`，我对 X 的感受），不读 X 对我的——后者是对方内心，越过知识边界。
  不回应的处理完全交给步骤 4 的 `rebuffs`。
- **status 权重** = 窗口内目睹的 endorse 次数（同 cap）；与 person 最高权重直接比，平手取 person。
- **玩家不作对象、不持欲望**（v0）：玩家交互门不该被 NPC 内部机制扰动。
- **只用 `relationships.has`，不用 `_rel`**：`_rel` 会顺手建关系 = 有行为效应的写。
- 证据挂在 `_log_event` 尾部（O(witnesses)），不扫全量 event_log。
- **D1 暂为强形式**：本步无行为效应 ⇒ 开着跑的前缀链 / digest 也必须与关时逐字节相同（`desire_test`）。
  步骤 3 起行为分叉，D1 降回"缺文件时与 master 相同"。
- 出货**不带** `data/desire.json`：步骤 1-2 只由 `desire_test` 注入配置。

## 七·七、步骤 4 规格（实现前写定）

- 挂点：同一个 `_log_event` 尾钩，**行动方视角**——actor 的 desire 是 person 且 `ev.target == target`、`ev.type ∈ give/invite/confide`：
  - 被接受 ⇒ `intensity *= (1 − rho)`，旧 target 入 `recent`（留最近 `K=3`），`kind/target` 清空 ⇒ 下一 tick 重选（`recent` 排除回锅）。
  - 被拒 ⇒ `rebuffs += 1`；`rebuffs ≥ r_max` ⇒ `intensity *= 0.5`，同样入 `recent` 并清空（反执念 + 内生出口）。
- 门：**缺 `rho` 键 ⇒ 满足逻辑整段不跑**；缺 `r_max` 键 ⇒ 放弃逻辑整段不跑。
  这样步骤 3 的配置（只有 `bonus_k`）逐字节复现，A/B 可以只加一个键做增量对照。
- status 对象 v0 **不设满足**：它只给 aid/endorse 加分，而这两类候选本就稀少（需结盟/派系）。若 A/B 显示 status 持有者长期不换，再议。
- D4（进 `desire_test`）：逐 tick 检查每人 `rebuffs < r_max` 且当前 target ∉ `recent`；另要求至少一次满足或放弃真的发生（活性）。
- A/B：在步骤 3 的 on 配置上加 `rho=0.6, r_max=3`，与 off 对拍，**重点复测集中度**（步骤 3：N=12 29%、N=40 42%）。

## 七·八、步骤 4 A/B —— 按 §七·七 规格实现，**不通过**

`rho=0.6, r_max=3`，其余同步骤 3；seed 1-12 × 45 天。off 臂在新 base（c313a9a）上与旧 base 逐位相同（N=12/N=40 皆然）。

|---|---|---|
| 社交动作熵（off 基线） | 2.55 → 2.32（2.32） | 1.95 → 1.88（1.85） |
| 人均动作种类（off） | 8.27 → 7.89（7.81） | 7.77 → 7.56（7.38） |
| 深层动作占比（off） | 14.2% → 7.3%（6.4%） | 5.3% → 3.6%（3.3%） |

| 冲突完成率 | 39.4% → 38.4% | 27.8% → 26.3% * |
| **集中度** | 28.9% → 30.6%（不显著） | 42.3% → 39.7%（不显著） |
| 持对象者占比 | 99.7% → **76%** | — |
| 每周换对象 | — → 0.12 | — → 0.04 |

结论：步骤 4 把步骤 3 的花样收益**几乎全部抹掉**，且**没解决集中度**。两个原因：
1. **满足即强制换对象 ⇒ 链被一刀切断**：一次深层动作被接受就换人，链长跌到 off 基线以下——"满足"成了"关系结束"。
2. **释放后找不到新对象**：3 天证据窗 + 排除近 3 个旧对象，N=12 下约 1/4 居民长期无对象、无加分。

集中度不是换手能解决的：换手率很低（0.04–0.12/周），而且换出去的人在 3 天证据窗里仍被同一个热门对象吸引。需要单独的拥挤项（§七·六）。

## 七·九、步骤 4 修订 ①：满足不换对象 + 拥挤项

- 满足：`intensity *= (1−rho)`、`rebuffs=0`，**对象不换**。放弃仍只由 `r_max` 次连续被拒触发。
- 拥挤项 `crowd_k`：候选权重 ÷ `(1 + crowd_k × (目睹的不同示好者数 − 1))`。只读自己的 seen 证据；缺键 ⇒ 不降权。
  意图：偏向"经由某个具体榜样"的内中介，而非全镇各自看到同一热门人物的外中介雪崩。

结果（crowd_k=0.5）：花样收益回来了（N=12 熵 +0.14*、链长 2.47；N=40 熵 +0.11*、链长 2.00），但**集中度纹丝不动**（29.5% / 42.4%），
换手 ≈0。探针（`bench/desire_pick_probe.gd`）查明原因：**12/13 人在第 1 天 tick≈11 凭 1–4 条、且只有 1 个示好者的证据定下对象，此后再不重选**
⇒ 拥挤项的 `(distinct−1)` 恒为 0，数学上不起作用。

## 七·十、步骤 4 修订 ②：首选前攒证据 + 满足后重估（**选定**）

- `min_seen`：窗口内 seen 条数 < 此值 ⇒ 暂不选（强度也不长）。缺键 ⇒ 不设门。
- `switch_margin`：每次满足后重估；另一候选权重 > 当前 × (1+margin) 才换，旧对象入 `recent`，**强度带过去**（驱力挪位）。缺键 ⇒ 从不重估。
- 首选与重估共用 `_desire_weights`（含拥挤项）/ `_desire_best`（`_hash01` 平局）。

变体对照（seed 1-12 × 45 天，差值均相对 off；`*` = 95% 区间不跨 0；集中度 = 被指向最多的一人 / 持对象者）：

`{"enabled":true, "gain":0.15, "mimetic_cap":5, "bonus_k":8}` 之上。`desire_test` 的 `S4_CFG` 即此配置。

据实的代价：
- **小镇里约 1/5 居民长期无欲望**（N=12 持对象 79.6%）：证据门在 12 人镇里攒不够 8 条。N=40 无此问题（99.0%）。
- **花样收益比步骤 3 弱**：N=12 种类/链长、N=40 熵不再显著；仍无一项显著变坏。
- **集中度的改善主要在大镇**（42% → 16%）；小镇 29% → 24%，且小镇各变体结果非单调（crowd 1.0 < 2.0 < 0.5），12 seed 下有噪声。
- 对象仍很少换（重估只在满足后发生，且要过 50% 门槛）。
