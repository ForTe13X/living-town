The native HISM observer lets an owned scene consumer read actual component identity, readiness and pool counts without registering, rebuilding or editing its instances. It adds two files to the Runtime module; the qualified 87-input baseline, Build.cs, existing fixed-scene readers, gameplay and rendering behavior are unchanged.

Call `unreal.LivingTownHismInspection.read_hism_component(component)` on the game thread. The C++ entrypoint is `ULivingTownHismInspection::ReadHismComponent`. It returns JSON with schema `LivingTown.BoundedHismInspection.v1`, status `READ_ONLY_BOUNDED_NATIVE_HISM_SNAPSHOT` or an explicit `ERROR`. It accepts live native HISM subclasses only when their inherited reflected field identities/types match the native parent. Nulls, templates, Blueprint component classes, invalid owner/outer/world, inactive/preview worlds and nonfinite LOD distance scales are refused. Supported worlds are Editor, Game and PIE; this requires no GEditor or fixed map/label namespace.

The snapshot returns actual component/class/world/map/owner identity, editor label availability, mesh and ordered effective material paths, owner/root/instance membership, creation method, registration/tree/async state, public/render/built counts, sorted instance indices, density/translated-space flags, culls, forced LOD, distance scale, visibility, collision/navigation flags and before/after dirty flags. Pending state is returned as observed. The caller must bind its declared source, world/map, groups, full mesh/material paths and transforms; this utility does not confer that authority.

Fixed limits are 20,000 instances/sorted entries, 256 actor instance members and 64 effective material slots. There are no asset loads, creation, register/build/rebuild/repair, flush, wait, saves, command-line rewrites or automatic calls each frame. Use inspection outside retained performance samples. Counts describe pool state; they do not measure visible/drawn instances, selected rendered LODs or GPU work.

