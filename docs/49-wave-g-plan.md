## 〇、这一波的由来：**Wave F 收尾时做的三次拆门，把同一个问题指到了美术**

Wave F 末尾我拆了三道长期全绿的门（#39 名字里少查一半、#40 粒度太粗、`story_test`
在一个裁剪从不发生的 horizon 上跑），每一条都用负对照亲眼看着变红了才算数（docs/48 §四/§五/§六）。
拆完之后一个更大的洞露出来了：

**`tools/ci.sh` 里没有任何一处提到 `assets` / `art` / `png` / `palette` / `coif` / `deprop`。**
（grep 实测，0 命中。）

⇒ **十张角色表、整个 `game/assets/art/pro/` 是这个仓库唯一一类"改了没有任何门会响"的资产。**
而它同时是玩家**唯一直接看见**的东西。

## 一、G1 · 给美术资产一道门（**本波最高杠杆**）

**owns**：`tools/art_gate.py`（新文件）、`tools/ci.sh`
**不得触碰**：`tools/coif_characters.py`、`tools/deprop_characters.py`、`game/assets/art/**`（那是 G2 的行）

### 要守的性质

**出货的 `pro/` 必须等于 `coif_characters.py` 现在能重建出来的东西。**
不是"有个校验和文件对得上"——那种门可以靠更新校验和文件通过；是**当场重新生成、逐字节比对**。
`coif_characters.py --metrics` 已经证明重建管线是可复跑的（它的"改前"基线就是这么算的，见该文件 :444 注释）。

### 验收（每一条都要有回执，且**先证明它会红**）

1. **负对照①（已知的静默回退路径，必须红）**：单独跑 `python tools/deprop_characters.py`
   —— 已知它会把 F2 的成果在多数表上悄悄覆盖掉。**跑之前先确认现在所有门都是绿的**，
   跑之后新门必须 **RED**。⚠️ 在**隔离副本**里做，不要污染工作区。
2. **负对照②（单像素，必须红）**：把某一张出货表里**改一个像素**，新门必须 RED，且**报得出是哪一张**。
3. **未改动的树必须绿**（不许假红）。
4. **门必须自证它扫过东西**：输出里要打印**实际比对了几张表、几个字节**——
   数字为 0 却打 ✅ 是本仓库反复出现的病（docs/41 §2 第三个盲区）。
5. `bash tools/ci.sh` 全量 **PASS**，且**新门确实在 CI 里被执行到**（不是加了个从不运行的函数）。

### 明确不做

**不要**把描边规则塞进这道门——那 132 个像素是 G2 的活，两棒同时改会撞。
G1 只守"出货 == 可重建"。

## 二、G2 · **F2 自己写下的描边规则，在 5/10 张表上没有成立**

**owns**：`tools/coif_characters.py`、`game/assets/art/pro/**`
**不得触碰**：`tools/ci.sh`、`tools/art_gate.py`（G1 的行）

### 规则在哪

`coif_characters.py` 模块 docstring 第 3 条白纸黑字：**"新加的像素必须自带描边"**（描边色 `OUTLINE = #040404`）。
**而文件里没有任何一条断言在查它**——`--metrics` 只有断言 A（alpha 外扩 > 0）和 B（剪影两两可分度）。

### 实测（2026-07-30，主 session 量的；**口径是 12 个可达帧**，`ROWS_USED=(0,1,3) × COLS_USED=(0,1,2,3)`，`FRAME=32`）

裸边 = **在本帧剪影外沿（四邻中有透明/出帧）却不是描边色**的新增像素。

| 表 | 可达帧新增 px | 裸边 px | |
|---|---|---|---|
| Mage-Cyan（可可·贝雷帽） | 240 | **72** | ❌ 占新增的 30% |
| Archer-Green（小薇·双马尾） | 408 | 24 | ❌ |
| Mage-Red（阿丽·侧马尾） | 276 | 12 | ❌ |
| Warrior-Blue（阿本·鸭舌帽） | 264 | 12 | ❌ |
| **Character-Base（阿梅）** | 192 | **12** | ❌ **它同时是 `WorldView.FALLBACK_SPRITE`** |
| Archer-Purple / Warrior-Red / Soldier-Blue / Soldier-Red / Soldier-Yellow | — | 0 | ✅ |
| **合计** | | **132** | |

> ⚠️ **这个数字我自己先量错过一次，写在这里当警告**：第一版扫的是**整张 768×256 的表**，
> 得到 9/10 张违规、合计 **2066** px。但整张表有 **192 帧**（768÷32 = 24 列 × 256÷32 = 8 行），
> 出货只用 **12 帧**，其余 **180 帧**永远不上屏。
>
> **（二次更正，G2 抓到）**：这段原本写的是"整张表有 **768** 帧"——**也是错的**。
> 768 是**像素宽度**，不是帧数。一句用来警告别人「量错了对象」的话，
> 自己把对象的数量算错了。2066 那个故事是对的，故事里的算术不是。
> 换成可达帧口径才是 5/10、132。**量错的不是算法，是对象。**
> 你接手时**先复现 132 这个数**；复现不出来就先停下来查口径，不要直接开始改像素。

### 验收

1. **先让判据红**：把上面的裸边检查写成 `coif_characters.py` 的**断言 C**，在**未修的树**上跑，
   必须报出 **5 张表 / 132 px**（与上表逐行相同）。这一步是判别力证明，**不能跳**。
2. 修这 5 张表 ⇒ 断言 C 归 **0**。
3. **不许拆东墙补西墙**：断言 B（剪影两两可分度）的**最小值不得低于 120**，
   且**并列在最小值上的对数要一起报**（docs/44 §一·五 的教训：报单个极值会让读者以为其余都更宽松）。
4. `Character-Base` 必须归 0——它是玩家 sprite 缺失时的回退皮，脸上没描边会直接出现在屏幕上。
5. 断言 A（alpha 外扩 > 0）继续成立。
6. `bash tools/ci.sh` 全量 PASS。
7. **眼验**（R10）：修完之后至少出一张 2× 的对照图，人能看出"多了一圈描边"而不是"看不出差别"。
   看不出差别是一个**需要写进回执**的结果，不是失败。
