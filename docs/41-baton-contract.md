# 41 · 分棒契约（Baton Contract）——所有并行子任务的共同约束

本文是**给执行子任务（"棒"）的 agent 看的共同契约**。派棒的 brief 只写"这一棒特有的东西"，其余一律引本文。
写它的原因很实际：2026-07-25/26 连着派了 13 棒，每份 brief 都在重抄同一套约束——**抄第 N 遍就会漏第 N 条**，
而漏掉的那条往往正是后来出事的那条。

## 0. 红线（违反即作废，没有例外）

1. **确定性 + 逐字节重放**：headless "logic 地板"的仿真必须逐字节可复现。
   - 仿真侧的随机**只能**来自 `Sim._rng_at(salt, who)`（由 `(seed, tick, salt, who)` 纯播种、**无状态**）。
   - 仿真决策逻辑里**不得**出现 `randi()/randf()/randomize()` 或任何 `Time.*` 墙钟。
   - 平局抖动的盐**必须**取自候选的**稳定身份**（`_cand_key`），**不得**取数组下标——否则枚举顺序一变，全部历史被静默改写。
   - 哈希用项目自有 `Sim.fnv1a32`（带已提交测试向量 + 启动自检），**不得**用引擎内建 `String.hash()`。
2. **无模型也能玩**：logic 地板在零模型下必须完整可玩。模型只能在**引擎枚举出的合法候选**里挑一个下标 + 可选台词，**永远不能写世界状态**。
3. **消费级硬件（含手机）**：出货目标是最多 60 居民、骁龙 8 Elite 级手机。
4. **不碰版权**：**任何**模型权重/预编译二进制都不得入库（`*.gguf/*.so/*.dll/*.bin/*.safetensors/*.pt`）；CI step 0 对整棵已跟踪树把关。美术资产须 CC0 或自绘。
5. **复用优先**：先找现成的 bench/工具，再考虑新建。

## 0.5 规模能力契约（**未定，本节就是那个空缺**）——2026-07-31 外部评审逼出来的

红线 #3 逐字是"**出货目标是最多 60 居民**"。而 I3 实测（docs/54）：

我当时的处置倾向是"承认产出是 12 人规模的特性、改红线"。**外部对抗评审否掉了它**，理由我接受：

> **"你不是发现『60 不是功能目标』。你是发现：当初没有写清 60 是哪一种 capacity。"**

红线 #3 那句话同时可以读成两件完全不同的事，而它们的验收标准差很远：

| 读法 | 含义 | 60 人时要保证什么 |
|---|---|---|
| **Entity capacity** | 最多 60 个对象能存在并渲染 | 帧率、内存、绘制 |
| **Simulation capacity** | 最多 60 个**完整**居民 | 上面这些 **+ 他们参与的每个系统仍然成立** |

**我一直在混用这两种读法**，于是"经济在 60 人时退化"既像 bug 又像超范围——**因为范围从来没被写下来**。

| | 单镇 | 区域（多镇） |
|---|---|---|
| 居民数目标 | ≤60 | **>100** |
| 出处 | 红线 #3 | 本行，用户 2026-07-31 定 |

⇒ **这一行就是为了不让 §0.5 那个歧义再来一次**：外部评审教过我们，
"60"没写清是 entity capacity 还是 simulation capacity，是那两波返工的根因。
现在写清楚了：**60 是一个镇，区域另算，目标 100+。**

⚠️ **它立刻产生两条待测**（都还没有任何数据）：
- **性能**：M2 明写 **N>24 一格都没测过**，而现在目标是 100+。红线 #3 的手机目标要重量。
- **`#01`**：若区域 100+ 由若干个 20 人左右的镇组成，**每个镇正好落在 M2 刚修的 #01 高发区间 N∈[18,24]**。

### 旅行作为【换页机制】——用户 2026-07-31 提，而本仓库已有它的先例与红线

用户的想法：**用"人在哪个镇"来做性能的换页**（lazy loading / 后台异步），
只有"热"的镇需要全保真模拟。

**这与本仓库已有的 aggregate LOD 是同一个形状**，而那条路上**已经有一条永久红线机器化了**：
`tools/ci.sh` 第 4b 步的 `lod_verify` **V2 相机路径无关**——
**五个不同的 `lod_focus` 必须给出同一个 digest**，且 `ci.sh` 的注释写着：
"若日后有人把 cohort 从相机取回，V2 立即变红。"

⇒ **换页可以做，但正确性条件是现成的，照抄即可**：
**换页的决定必须只由【已提交的仿真态】得出（谁在哪个镇），绝不能由【玩家在看哪里】得出。**
幸运的是这两者天然一致——"谁在哪个镇"本来就是世界状态，不是观察。

⚠️ **而"后台异步"是这条里唯一真正危险的部分**：红线 #1 要求逐字节可回放、
且仿真里不得出现墙钟。**异步 = 完成顺序不确定**，除非：
（a）异步做的是**纯预计算**，其结果与它何时落地无关；或
（b）在一个**确定的 tick 边界**上 join，且 join 顺序由仿真态而非完成先后决定。
**任何"谁先算完就先用谁"的设计直接违反红线 #1。**

### 决定：**双尺度**（评审给的第四种答案，用户 2026-07-31 选定）

**微观（60 个 agent 逐个真算，一个都不降级）**：需求、消耗、关系、涌现、缺货的社会后果。
**宏观（换尺度）**：**产出侧**。居民不需要知道"今天三个伐木工各砍了多少"，只需要知道"柴薪紧不紧张"。

**为什么是这条**：本项目的卖点是**社会涌现**，不是经济精确模拟。
改动集中在产出这一层，**不动已经手工标定过三波（E1/F1/G3）的社交底座与消耗侧**。

⚠️ **它不是"放弃 60 人的经济"**：供给仍然必须跟得上人口，缺货仍然必须有社会后果。
降的是**记账粒度**，不是**保证本身**。若实现之后 60 人仍然屋瓦全年断供，那就是没做到，不是"已降级"。

> 满足率是一个**比率**，对记账单位不变；而分母会自动跟着缩放，因为 `#40` 读的是 `S.production`，

> detail 末尾追加"；产出契约=宏观池 ×16/12"。

### 评审给的第四种答案（我原本只想到三种，记在这里备选）

**双尺度模拟**：微观仍是 60 个 agent（需求、关系、涌现逐个真算），
而**产业改成宏观池**——居民不需要知道"今天三个伐木工砍了多少"，只需要知道"木材紧不紧张"。
评审的理由：这与本项目的定位（**社会涌现 > 经济精确模拟**）一致，
且不需要把 E1/F1/G3 手工标定过三波的经济重新打散。

### 另外两条它纠正我的

- **"按人口缩放会打散三波标定"被我夸大了。** 全局倍率确实危险（一个铁匠在 60 人里产 60 把剑），
  但**岗位容量模型**（`worker_count × work_capacity_factor(population)`）或加学徒位是小改动。
  **我把它讲成了二选一，而中间空间很大。**
- **"把 `#40` 按 N 分档"确有制造废门的风险**，而修法是**别按人口分档，按模拟契约分档**：
  不是 `if N>16: 放过`，而是 `if mode == economy_full: 要求供给 / if mode == social_only: 只要求活性`。
  **前者是给出货配置预埋一条永不变红的门——正是本项目反复中招的那个病。**

## 0.7 【待批】红线 #2 的读侧补充——Q2 提，**尚未采纳，需用户拍板**

红线 #2 现在只管**写**（模型只能挑下标 + 可选台词，永不写世界状态）。
Q2 实测后指出：**"能读多少"从来没写过**，而真正的通道不在字段值里，在**候选表的成员资格**里。

**它测出来的东西**（22,693 个决策点）：
- `build_prompt` **从不渲染 `subject`**（候选行命中 0/16715 @N=12、0/60741 @N=20），也不渲染 partner id（0/33694）。
  ⇒ **"别把 subject 递给模型"是一条今天等于没做的修法**（P1 的那句话在这一点上是错的，我复核确认）。
- **真正的通道是"这个选项存在"本身**：13 个社交动作里有 8 个的**存在条件读的是对方的私有状态**。
  看见 `说八卦→阿本(老友)` 就是一个**可靠且完备的判据**："阿本 缺少某条我持有的信念"。
  实测 **52.4% 的决策点**至少带一条这样的选项（N=20 是 62.7%）；对单个具名邻居，
  同时暴露的独立私有谓词**众数是 2-3 条**。

**它提的那句话（原文）**：
> 读侧同受本条约束：递给模型的 prompt 里，每一个**值**都必须是该 agent 自己的状态、公共事实、
> 或他经事务/观察合法获知的东西。而**候选表的成员资格本身也是一次读**——一个选项存在，
> 就等于告诉模型它的枚举条件成立了。**因此候选枚举的门就是 prompt 的知识门，二者不得分离**：
> 能进这个 agent 候选表的对象，必须是他本来就能感知的对象。

**为什么值得考虑**：它便宜（今天已经近似成立——枚举几乎都在 `for o in _nearby_agents` 里），
它让 `Sim.gd:8/:10` 的自我描述**变成有约束力的**，而且多镇是免费继承的。
⚠️ **它第一个会绊倒的正是 `endorse`（读缺席第三方的 `faction`）与 faction 本身——也就是 Q1 正在处理的东西。**
⇒ **建议与 Q1 的结论一起评审，别分开拍板。**

**为什么我没有直接写进红线**：扩红线是架构级改动，§0.8 要求先评审；而且这是**用户的决定**，不是我的。

## 0.8 大设计 / 架构改动之前，必过【外部对抗评审 + 多棒】（用户 2026-07-31 定为常规）

**规则**：凡是"大阶段设计"或"架构改动"，动手之前先过两道独立评审：
① **Codex desktop 的已有 repo session**（它已经 familiar 本仓库、能真读代码、能自己跑 bench）；
② **多棒并行**（各自独立执行 + 各自的 `does_not_detect`）。
**两路独立收敛 = 强信号；两路打架 = 先别动手。**

### 这条规则不是新的——它已经在本仓库还过一次本，而且证据就在源码里

Codex 对 aggregate LOD / remote-actor liveness 那一轮评审提的 P1，**已经被吸收，且注释直接引用了评审**：

- `Sim.gd:745`：`_near_set = {}` — 注释原文 **「评审 P1：LOD 近端集 per-run 清
  （否则复用实例 restart/goto 会带旧 near id → 回放不一致）」**。
  ⇒ 对应 P1「Aggregate replay keeps stale near IDs」。**已修。**
- `Sim.gd:207`：`far_drift_enabled := false` — 注释原文 **「远端 liveness 漂移：独立【实验】开关
  （评审建议：别只挂 lod_aggregate 门）。原型/有已知 bug(卡墙/多平面)，未出货」**。
  ⇒ 对应 P1「Greedy drift cannot route around buildings」。**承认、单独下闸、明写未出货，
  且采纳了评审"别只挂一个门"的具体建议。**

⇒ **值得记住的是它当时的处理方式**：不是"修好了"也不是"忽略"，而是
**"承认 + 独立开关 + 明写已知 bug + 不出货"**——一个原型可以留在树上，只要它的状态被写清楚。

### 用哪一路、什么时候

| 场景 | 走哪路 |
|---|---|
| **大设计 / 架构改动**（多镇、换页、跨镇贸易、红线口径变更…） | **两路都走**，动手前 |
| 单点结论、判据设计、负结果 | Chrome → chatgpt.com（见 [[feedback-adversarial-external-review]]） |
| 需要真读代码 / 自己跑 bench 的评审 | **Codex desktop 的 repo session**（它有完全访问） |

⚠️ **送评审的【摘要】本身就是一次转述**：凡引用自己已有的结论，**逐字引原句，别压缩重写**
（2026-07-26 实证：压缩过的摘要被正确地判为过度外推，而打中的是摘要、不是文档）。

## 1. 工作方式

- **先自查基线**：`git log --oneline -3` + `git fetch origin` 对比 `origin/master`；落后就先 ff（确认是祖先再 ff）。
  **踩过的坑**：有棒的 worktree checkout 在 20 个 commit 之前，于是它"验证"的是一棵早已过期的树。
- **只动 brief 列出的文件**。其余一律不碰——并行棒之间就靠这个不打架。确实需要越界时：**先在报告里说明**，
  给出证据，并说清可否回滚（越界本身不是罪，**闷声越界**才是）。
- **验证通过后在本 worktree 分支上 `git commit`**（一个 commit，信息里写清证据）。**不 push、不 merge、不碰别的分支。**
- Godot：`C:/Users/yp/.local/bin/godot`。Bash 超时给足（单次上限 600000ms）；**宁可 inline 阻塞等待，也别后台跑完就交卷**
  （后台跑会让你的回合结束，白白多一次往返）。
- **杀任务不等于杀进程**：`godot.exe` 子进程会游离存活。跑矩阵前先清场，并断言"每个输出文件只有一段汇总"，
  否则你会静默分析到三次并发运行交织出来的数据。
  **⚠️ 但"清场"在并行期要反过来读（2026-07-26 被违反两次）**：
  `docker ps -q | xargs docker kill` 与 `Get-Process -Name "Godot*" | Stop-Process -Force` **都是禁止的**——
  前者实测杀掉 5 个容器、其中最多 4 个属于并行棒；后者按名字通配，等于杀掉本机**所有仓库**的所有 Godot
  （实测同一时刻本机还跑着另一个项目的测试）。**只能杀你自己启动并记下 PID / `--name` 的那些。**
  看到别人的进程在跑 ⇒ **不杀**，改用唯一输出路径 + 断言每个输出文件只有一段汇总。
- **⚠️ bench 场景里的 parse error 会让 `tools/ci.sh` 永远挂住，而不是变红**（D1 实测踩到）：
  场景实例化失败 ⇒ `quit()` 永不执行 ⇒ 进程不退出（实测 600s 还活着）。
  **step 3 的 `--import` grep 抓不到它。** 「一直在跑」是门最坏的一种形态——比红更难发现。
  在有 pre-flight parse 检查之前：**改完 bench 场景先单独跑一次那个场景，别直接跑全量 CI。**

## 1.5 读仓库的两条纪律（2026-07-30 I2 交的学费，三个人先后读错同一件事）

### ①「今天零调用点」是二义的：`grep` 给现状，`git log -S` 给意图

H1、H2、我，三次**独立**的静态扫描都发现 `Art.building_tex()` 全仓零调用，
并都把它讲成**「一个没接上的特性」**——顺理成章的下一步就是"把它接上"。
**实际是反的**：`ebac5a3` 接过，**`841d4c4`（2026-07-15）把它删了**，
提交信息里点名它是用户报的**比例失调**的头号成因（16×16 的 hut 画成整整一格 = 一间跟人一样大的房子，
原话 "Removed the hut lie"）。⇒ **把它接回去 = 把一个修好的 bug 装回去。**

> **"从没接上" 与 "被有意摘掉" 在静态扫描下长得一模一样，而只有历史能区分。**
> ⇒ **看到"零引用/零调用"，在给出处置建议之前先跑一次 `git log -S "<符号>"`。**

confidence:     （在 N 个变异体上量过；N=1 就写 N=1，不要含糊）

## 3. 会移动 digest 的改动

有些改动**理应**改变仿真轨迹（调平衡、改加盐、换社会阈值）。这类改动是**受控动作**，不是违规：

1. 先确认这是**蓄意**的行为变更，且能说清**为什么**。若 digest 动了而你解释不了 → **停下来报告**，不要重烘。
2. `Harness.gd --bake-golden`（seeds 段）**与** `DetGate.gd --bake-golden`（scenarios 段）**都要跑**。
3. 在 `_meta.rebake_history` 里补一条：日期 + 一句原因（该键会被两个 bake 保留；标准 `note` 字段每次烘都会被覆盖）。
4. **必须跑留出种子**证明不是对基准过拟合：改前/改后都跑 `--seeds 13-30 --days 60`，报告两侧数字。
5. **绝不为了让门变绿而放松硬不变量**。硬不变量变红 = 真发现 → 报告，不要削它。

## 4. 报告契约（最有价值的一条）

最后的报告里**必须**包含一节：**"这份 brief 哪里是错的"**。

brief 里的行号、数字、机制描述大多是**二手的**（上一棒的产出、或派棒者的推断），**很可能已经漂移或本来就错**。
**以代码为准**，并明说哪里对不上。实测：连续 13 棒里 13 棒都在这一节交出了东西，其中不止一次纠正的是
**派棒者写给用户的结论**（例如"全镇净亲密赤字"其实不存在、Node 端口断言数是 33 不是 10、区名不是低对比而是完全不可见）。

报告还应包含：关键数字（带逐 seed 展布，不要只给均值）、你**证伪过的自己的假设**、commit SHA、CI 结果、
以及**你没能测到什么**（"没测"要明写，不要用推断填空）。

## 5. 统计与度量纪律

- **数字要有零假设才可解读**。"模型改变了 55% 的决策"本身无意义——要配**同配置的均匀随机零假设**，
  外加一个**已知答案的校准点**（如 mock 鹦鹉），才知道落在哪一侧。
- **注意分母**。`landed/fired` 不是"决策占比"；`calls − waits` 也可能虚高。**在 commit 边界数**，并写清口径。
- **对照要等量而非等时**。比较两个后端时先做**剂量配平**，否则量到的是"哪个更慢"。
- **A≠B 的口径追问**：`landed`(按时返回) ≠ `drove`(真的改变了决策)。前者只是影响力上界。
- **相关症状 ≠ 独立证据**。"14 处失败跨 6 条不变量"很可能是**同一个缺陷的多个投影**——
  报**逐 seed 效应量 + 首次因果分歧点**，别报阈值越界计数。
- **观测 vs 行为**：指标塌陷可能是采样口径变了而非行为变了。判别法：把**全保真**结果按被质疑那档的
  **完全相同的采样节奏**降采样，再算同一指标。
- **n 很小时，"ns" 读作"这个网格分辨不出"**，不是"零"。

  采集路径：`game/bench/SpaceShot.gd` + `tools/space_roundtrip.sh`（已接进 `visual_gate.sh`，`rc=3`）。
  > **⚠️ 并且这条盲区证明了"计数器不是像素"**：E6 的第二个负对照——让界外层**照常重画但什么都不画**——
  > `--void-gate` **依然 PASS**（它只数重画次数，结构上看不见画了什么），而像素断言四条带全红。
  > **凡是用计数器守视觉性质的门，都要问一句：画成一块纯色它会不会照样绿？**
  ⑧**Docker 软渲染跑不出插值类改动**（C1 实测）——容器里实测只有 **5.3-10.8 帧/秒**（即便降到 640×384），
  **低于 12.5 ticks/s 的仿真速率** ⇒ 根本不存在"两个 tick 之间的帧"，插值在那条路上按构造是 no-op。
  **录屏永远证明不了它**，只能用单元探针（C1 的做法：量偏离格心的样本比例 + 冻结后是否精确吸附）。
- **★ 视觉验收判据必须先在【未改动的树】上跑一遍。若它在那里也通过，它就没有判别力——那不是判据，是装饰。**
  这是 docs/41 §5「数字要有零假设才可解读」在视觉上的同一条纪律，而 2026-07-26 的 Wave C **一波里踩了四次**，
  四条全是派棒者写的：

> ### ⚠️ `getbbox()` 陷阱（2026-07-30 G5 报，我独立复核）——**本文与 docs/43 / docs/46 里多处都在用它**
>
> **Pillow 11.3.0 起 `Image.getbbox()` 默认 `alpha_only=True`** ⇒ 对 RGBA 图**只看 alpha 通道**。
> 本项目的美术**全不透明** ⇒ `ImageChops.difference(a, b).getbbox() is None` 这条断言
> **在 RGBA 上是空真的**：颜色随便怎么变，它都说"完全相同"。
>
> 我自己跑的复核（`grass_a.png` vs `grass_b.png`，两张肉眼可见不同的瓦片）：
> ```
> RGB 上真正不同的像素        = 36
> getbbox()                  → None          ← 判成「完全相同」
> getbbox(alpha_only=False)  → (2, 3, 14, 15)
> ```
> **正确写法**（二选一，别只写第一种）：
> ```python
> ImageChops.difference(a.convert("RGB"), b.convert("RGB")).getbbox() is None
> ImageChops.difference(a, b).getbbox(alpha_only=False) is None
> ```
> **现状**：没有**活门**踩到它（`assert_daynight.py` 先 `convert("RGB")`）⇒ 这是文档隐患，不是现行假绿。
> **但凡是历史回执里写着"`getbbox()` is None ⇒ 逐像素未变"而当时喂的是 RGBA 的，那条证据是空的**，
> 需要重跑才能算数。这正是本文 §2.5 要求写 `does_not_detect` 的理由：
> **一条断言可以因为库的默认参数而恒真，而它读起来和真断言一模一样。**

  ①「四季两两 `getbbox() is not None`」——未改动的树上 6 对全过（agent 每天都在移动）；有判别力的是**主色**。
  ②「`y=10` 整行每点亮度 < 40%」——**字面不可能**，状态栏文字本身就是 91.4% 亮度且就在那一行。
  ③「插值走录屏验」——**不可达成**，容器 5-10fps < 12.5 ticks/s，两 tick 之间没有帧（盲区⑧）。
  ④「界外新层必须跟着昼夜走」——**未改动的树逐条通过**（背板本来就是 CanvasItem）。
  ⑤ 同一波里还有一条**量错了对象**：「16px 剖线的最大相邻跃变」有 8px 落在**界内**，
  而界内像素画本身就有 ~130 的跃变 ⇒ 该指标有地板、**永远报不出成功**（实测修好后它只从 131.54 动到 129.93）。
  正确的做法是把它拆成 `cross`(跨界)/`outband`(界外)/`win16`(保真度)，头条数字用 `cross`（131.54 → **2.92**）。
  **⇒ 写下任何视觉判据之后，先问一句："一个什么都不做的改动能不能通过它？"**
  **⇒ 还要问它的孪生问题："一台更快（或更慢）的机器会不会让它变红？"**（2026-07-28 实测）
  新加的界外层重画门按**帧数**计、按写死的 **0** 判：同一棵树单独跑推进 189 tick、0 次重画、PASS；
  在 `visual_gate.sh` 里跑推进 **445** tick、1 次重画、**FAIL**。根因是缓存键里有 season/weather，
  而它们**在日边界会合法地变** ⇒ **写死 0 的门不是在守那条性质，是在守"你的机器别太快"**。
  凡是判据里出现**写死的绝对次数/时长/帧数**，都要先想清楚它在别的机器上是什么。
  > **⚠️ 但"六条"这个数字本身要打折——外部对抗评审 2026-07-26 用本文 §5 的规矩反打了回来，说得对：**
  > 「六条判据被证伪」**很可能不是六份独立的方法论证据，而是同一个上游错误被复制了六次**。
  > 那个上游错误是：**没有先定义「干预 → 观测 → 归因」的链条，就直接跑到最终截图上找一个数**。
  > ①②④⑥ 都是"没设基线/背景没冻结/动态对象没屏蔽"，⑤ 是 ROI 选错——本质上全是 **measurement contamination**。
  > **相关症状 ≠ 独立证据**（§5 原话）。所以正确的措辞是"**一个错误模板被复制了六次**"，
  > 不是"六种彼此不同的判据设计失败"。前者是一条可修的规矩，后者是一份虚增的统计重量。
- **★ 界外/边缘装饰有一个特有的失败模式：等距连续 = 相框。**（C7 实测）
  沿边界**等距且连续**的任何东西都会从"延续"退化成"相框"——**比原来那条硬边更糟**，
  因为它把你正想藏起来的那个矩形又描了一遍。判别法：`outband` 指标会同时报警（26.5 → 68.8）。
  解法是抖动距离与长度、把覆盖率压到约 1/3。
- **数值 diff 比肉眼强，且要用它守"不该变"的那一半**：改视图时对**未受影响的分辨率**做逐像素 diff
  （PIL `ImageChops.difference` 的 bbox 应为 `None`）。B15 靠它抓到一个纯肉眼绝对看不见的 1px 回归：
  `LineEdit.size` 在 `add_child` **之前**赋值不走主题最小尺寸钳制（高 30），入树后再赋同一常量会被钳到 31、
  连带 placeholder 基线偏移。**"看起来一样"不是证据，bbox=None 才是。**
- 纯视图层改动**不应**移动 digest。若动了 → 你改到仿真了，回滚并查因。
