### 1.2 逐 tick 追：**"候选数为 0"的原因，27/27 与 125/125 都是 `GATED`**

量具 `game/bench/x1_starve_trace.gd`（本棒新写；**纯只读**，见下面那条 ORACLE）。
它不调 `_social_candidates()`——那个函数内部的 `_rel(ag, o["id"])`（`Sim.gd:3608`）
**在关系不存在时会 auto-create**，从探针里调它就等于往世界里写东西。
替代做法是把那段控制流逐条读出来，**等价而且更强**：

> `_social_candidates` 的前两道门是 ①`_min_need < SURVIVAL_GATE` → `[]`；②`social >= SOCIAL_FULL` → `[]`。
> 过了这两道之后，对**每一个** `talking == 0` 的同区在场者都会**无条件**产出一条 `greet`（`Sim.gd:2022`）
> ⇒ **候选数 == 0 ⟺ ①GATED ∨ ②FULL ∨ ③同区可搭话的人数 = 0**，三者互斥地记账。

| | seed 8 · `npc_21`（无岗位克隆） | seed 56 · `ben`（木匠） |
|---|---|---|
| 触底 need·tick | 27 | 125 |
| **触底那些 tick 里 `GATED`** | **27** | **125** |
| 同上 `FULL` | 0 | 0 |
| 同上 `ALONE`（周围没人） | **0** | **0** |
| 同上 候选数 > 0 | 0 | 0 |
| 全程 `GATED` / `FULL` / `ALONE` / 候选>0 | 1129 / 2455 / 2906 / 7910 | 2974 / 1157 / 3307 / 6962 |

> ⚠️ **这张表里的「触底 tick 100% GATED」有一半是【同义反复】，我自己先说破**：
> `social ≤ 0.5` ⇒ `_min_need ≤ 0.5 < 36` ⇒ `GATED` **按定义恒成立**。
> **真正有判别力的不是这一行，是它下面那两栏**：`FULL=0` 与 **`ALONE=0`**
> ——**触底的每一个 tick，身边都有可搭话的人。** 一个"周围真的没人"的世界会在 `ALONE` 那一栏出现，
> 而它是 0/27 与 0/125。
> **以及下面那段【下坠期】的逐 tick**——那里 `social` 还在 35 到 1 之间，`GATED` **不是**同义反复，
> 而它仍然恒成立，因为 `social` 自己就是 argmin。**那一段才是机制证据。**

**逐 tick 的下坠段（原始输出在 `analysis/x1/trace_n40_s*.txt`）：**

  t=11735 soc=32.5  min=32.5 GATED near=0 free=0

⇒ **这不是"没人可社交"，是"被禁止社交"。** 从 social 跌破 36 那一刻起，
到它触底，两例分别走了 **236 tick（≈1.0 天）** 与 **252 tick（≈1.05 天）**，

### 1.3 那条"物件出路"到底在不在（**这是 §〇① 那条更正的量化版**）

同一探针在 `social < 36` 的**每一个** tick 上调 `_object_candidates(ag)`（纯读，ORACLE 见下），
数里面 `need == "social"` 的候选：

| | `social<36` 的 tick | 枚举里**有** social 物件候选 | **一条都没有** | 这些候选的最高分 | **他真的在做**的 tick |
|---|---|---|---|---|---|
| seed 8 · `npc_21` | 490 | **490（100%）** | 0 | 67.08 | **54（11%）** |
| seed 56 · `ben` | 1182 | **853（72%）** | **329（28%）** | 69.60 | **143（12%）** |

**两件事一起读：**

1. **出路存在且被枚举到，但它赢不下 argmax。** 打分是 `benefit − dist × obj_dist_penalty(0.4)`，
   而 `benefit = urgency × amount/60`；长椅 `amount=40` ⇒ 满 urgency 也只有 66.7，
   要跟"吃饭/睡觉/洗澡"在同一个池子里抢，而那三样在被锁住的这一天里的 urgency 同样在涨。
2. **室内那 28% 是【结构性的零】。** `_journey_candidates`（`Sim.gd:1636`）里那一行
   `if nid == "social" or covered.has(nid): continue` **显式把 social 从跨平面行程里摘掉了**
   ⇒ **一个人进了屋，就再也不可能为了社交而计划出门**。
   `ben` 的 329 个 tick 就是他待在 `home` / `home2` 里的那些 tick。

> **ORACLE（每次运行都重跑，不是一次性推断）**：探针第二遍比第一遍多调了 `_object_candidates`。
> 若它其实不是纯读，两遍的 `Inv.digest` 立刻分叉。实测两例都是
> `pass1 == pass2`（`1966159113` / `1384910042`）⇒ **探针没有扰动仿真。**

### 1.4 燃料：**被拒的那一侧没有"他很缺人"这一项**

`_acceptance_margin`（`Sim.gd:3528`）逐分支看，**只有 `greet` 与 `invite` 带 `(100−need)×0.4 / ×0.35`**
（`need` 读的是 **target 的 social**）。`gossip` / `gossip_rep` / `discuss` / `give` / `confide` /
`leak` / `endorse` / `aid` **一个都没有**。而被拒的代价是双向的：
`affinity −3`、`resentment +3`、双方各记一条负面记忆（`Sim.gd:2364-2372`）。

两例作为**被动方**的分账（本棒探针，60 天全程）：

| | `gossip_rep` 接 / 拒 | `greet` 接 / 拒 | `invite` 接 / 拒 |
|---|---|---|---|
| seed 8 · `npc_21` | **11 / 149** | 18 / 2 | 18 / 0 |
| seed 56 · `ben` | **0 / 145** | 3 / 4 | 0 / 0 |

⇒ **迎面来的搭话里，压倒性多数是他会拒掉的那一种**，而每一次拒绝都让下一次更难被接受。

### 1.5 **N 依赖：带补偿的通道对人口是平的，不带补偿的 ×2.7**

三格都是我自己跑的 `Harness --seeds 1-12 --days 60`，读它自己打印的活性表（分母 = seed×人数×天）：

| 事件类 | N=12 计数 → 每人每天 | N=16 | N=40 | 有无 need 补偿 |
|---|---|---|---|---|
| **`gossip_rep`** | 6795 → **0.786** | 16448 → **1.428** | 60462 → **2.100** | **无** |
| `greet` | 5816 → 0.673 | 6721 → 0.583 | 17943 → 0.623 | 有 |
| `invite` | 1091 → 0.126 | 1277 → 0.111 | 3461 → 0.120 | 有 |
| `discuss` | 1151 → 0.133 | 1017 → 0.088 | 2623 → 0.091 | 无 |
| `conflict` | 1129 → 0.131 | 2266 → 0.197 | 7854 → 0.273 | — |

**为什么只有 `gossip_rep` 涨**：它的枚举前提是 `bad_targets`
（`_social_candidates:2012` —— "我对其有坏名声(≤`REP_GOSSIP_TH`)的第三方"），
**这个集合随人口线性长**；而 `greet` 是"对每个在场者一条"，人均看不出来。
⇒ 大 N 下一个人每天被搭话的次数在涨，**但涨的全是他拒的那一种**。

**这就是"为什么硬红只在 N=40"的机制答案**，而它比"大 N 更容易抽到坏 seed"具体得多。

## 二、`#01` 与 `#40` 的口粮红**不是同一件事**（派单问题 2）

### 2.1 结构：口粮断供**在构造上够不着 `hunger`**

`Sim.gd:1471-1476`，注释是显式的：

> ★缺货【不阻断】：这里既不 return 也不清 option，need 照在 use 分支补满 ——
> 与 `meals_free` 同一条设计红线：缺货绝不成为新的饿死通道(硬不变量 #01)。

`_consume_for` 返回 `false` 只做两件事：①缺货加价 ②记社会后果（`_shortage_fallout`）。
⇒ **一个断供 43 天的镇子，`hunger` 该补满照样补满。**

⚠️ **诚实边界**：`_shortage_fallout` 会**小挫责任岗位的 `standing`**，而 `standing` 进
`_acceptance_margin` 的 `st` 项 ⇒ 口粮长期断供**理论上**能经"面点师/渔夫被记恨 → 更难被接受"
绕回社交。**本棒没有做这条链的隔离干预**，只能给两条反证（下面 2.2 / 2.3）说明它今天不是主因：
两颗红的当事人一个是**无岗位克隆**（不是 blame 的对象），另一个是**木匠**（口粮跟他没关系）。

### 2.2 两颗硬红的 `#40` 都是**绿**的

`seed 8`：`#40` 绿；`seed 56`：整格 `#40` **12/12 全绿**（判决行见 §1.1）。

## 五、修法：**试了，量了，这一档【没有把红修掉】**

### 5.1 干预是什么

`_acceptance_margin` 的 `gossip` / `gossip_rep` 分支加一项，**只对已经掉进锁里的 target 生效**：

```gdscript
func _lonely_relief(need: float) -> float:
	var k := _w("accept_lonely_relief", 0.0)
	if k == 0.0:
		return 0.0
	return maxf(0.0, SURVIVAL_GATE - need) * k
```

选它的三条理由（都不是审美）：
1. **它打在量到的那一格上**：§1.4 的分账说锁里的人被 `gossip_rep` 淹没并全数拒掉，
   而这条动作恰好是八条"没有 need 补偿"里频次最高的。
2. **形状是抄来的，不是发明的**：`(100−need)×K` 是 `greet`/`invite` 已经在用的那一项；
   门槛复用 `SURVIVAL_GATE`，**没有引入新的魔法数字**。
3. **缺键即零扰动**，可 ablate，回滚成本 = 删一个 JSON 键。

### 5.2 零扰动对照（**先证明尺子没有偷偷动世界**）

`scripts/Sim.gd` 的这一处与 `data/utility.json` 的这一个键外与 `game/` 相同）
⇒ **仓库里全程没有出现过隔离副本**，也不存在"收工前忘了删"这条风险（沿用 W2 的做法）。

⇒ **处置：不出货，不落地到本 worktree 的 `game/scripts/Sim.gd`。**
本棒收工的树上 **`game/scripts/**` 与 `game/data/**` 一个字节没改**（`git status` 只有四个新文件）；

### 5.5 干预 B（**推向物件那条出路**）——本棒新开，只跑了部分网格

   ⇒ **加 seed 比加 N 更快找到下一颗红。**

   ⇒ 全镇 `gossip_rep` 接受率四档都是 18.4%，它翻的是个别几次拒绝。
