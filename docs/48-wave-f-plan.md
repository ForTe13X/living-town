### F1 · 分工要有地方发生（还 E1 的债 + 用户点名的"建筑/商贩/环卫"）

**独占 `Sim.gd` + `game/data/` 里那五个 JSON + `tools/audit_map.py`。
不得动 `WorldView.gd` / `Main.gd` / `Goals.gd` / `Story.gd` / `game/bench/*`。**

**现状（先自己复核，别信我的转述）**：E1 的产出闭环已经在跑，但**产地是借来的**——
柴薪挂在"洗澡"上、话本挂在"歇着"上。没有工坊、没有学堂、没有摊位、没有环卫的作业面。

**做什么**：给新分工**真正的空间落点**，并让它们各自有**不同的行为**，而不是同一个"做活"换个名字。
最小集建议（**你可以改，但要说清为什么**）：

- **工坊**：木匠在工坊做活 → 产柴薪/木料。工坊是一个**已有建筑**的室内平面（`interiors.json`），不必新建楼。
- **摊位（商贩）**：白天在广场支摊 → 把**镇级库存**转成**个人可买**；这是唯一一个让货**在人之间流动**的角色，
  也因此是唯一会碰 `transfer` 的（**#34 金钱守恒仍然是唯一通道**）。
- **环卫**：整洁度**随时间衰减**、环卫工作业则回补；低整洁度**不阻断任何动作**（红线，见下），
  但可以进效用乘子、可以被议论。

**红线，逐条继承，不许重新讨论**：
① **缺货/脏乱不得成为新的饿死通道**——`economy.json` 的 `_doc` 明写"付不起照吃"，E1 的负对照已经证明
把稀缺做成生存门会让硬 #01 立刻红（饿穿 670010）。**你的新机制同样要过这一关。**
② **确定性**：无墙钟、无 `randi/randf`，随机只走 `Sim._rng_at`，平局加盐取候选**稳定身份**。
③ **缺文件即零扰动**：新数据缺失 ⇒ 新机制整个关闭 ⇒ 逐字节回到今天。**这条要有断言。**

**验收（R12 全套 + 地图门）**
- **零扰动对照**：把新数据摘掉 ⇒ 金标**逐字节等于今天**。
- **三份提交锚都要重烘**：`Harness --bake-golden`、`DetGate --bake-golden`、`ModelPathGate --bake-anchor`
  （**第三份是 E1 实测踩到的**，只烘前两份 CI 必红），并在各自 `_meta.rebake_history` 补一条原因。
- **留出种子 13-30 × 60 天**，改前/改后两侧数字都报；**逐 seed 饿穿计数**（不是"没看到饿穿"）；硬不变量 18/18。
- **`tools/audit_map.py` 要跟着长**：新的工位/摊位/作业面必须有**可达的交互格**——
  这道门此前抓不到"合法但语义不对"（docs/43 §1.2b 记过），**如果你的新对象需要区域归属，就把那条规则补上**。
- **R9**：能证明的是"这些角色现在各自改变世界状态的不同部分"，**不是**"小镇更有趣了"。

### F2 · 十张脸要有各自的轮廓（还 E3 的债）

**独占 `game/assets/art/` 与你新建的 `tools/` 脚本。不得动 `game/scripts/*`。**

E3 的遮罩把**全部**行头去掉了，代价是十张脸的 alpha **全部等于 `Character-Base`**。
现在要**加回轮廓**，但加的是**现代小镇的**轮廓而不是奇幻道具：发型（刘海/发髻/短发/卷发）、
围裙/围巾/帽檐、体型微差。**docs/44 §一 的裁决不变**：现代日常小镇居民。

**这一棒的风险与 E3 相反**：E3 的风险是"糊"，**F2 的风险是"丑"**——
32px 下新画的头发很容易变成一坨色块。所以：
- **先做一个，量完再做第二个。** 一次画十个然后一起验，是这一棒最可能的失败方式。
- **允许放弃**：某个居民实在做不出干净的轮廓，**保留 E3 的版本并说明**——
  九个好轮廓 + 一个诚实的"没做"，好过十个色块。

**验收**
- **轮廓可分度**：报改后**两两之间的 alpha 差异像素数**（E3 的基线：遮罩后同族只差 73-91 px）。
  目标是让**任意两张脸的剪影**都明显可分，给出最小值。
- **不许把脸弄糊**：报**面部皮肤边界像素数**改前/改后（E3 的基线：袍装 106、Warrior/Soldier 51）。
- **在游戏里看**：`shot1.sh` 默认走 1.8× 特写，正好；**R10 全帧眼验，且至少两个缩放档**
  （D3 的教训：第一版辉光在全镇取景下很好、在 1.8× 下是六圈硬同心环）。
- **许可**：仍是对 CC0 的修改 ⇒ 仍是 CC0/自绘；**绝不用 AI 出图进精灵帧**（docs/43 R2）。
  更新 `game/assets/art/pro/README.md` 的对照表。
- 金标逐字节不动（纯资产替换）。

### 二·一 真机复验第一轮结果（NX789J，Wave C+D+E 全栈第一次一起跑）

**帧时通过**：第 48 天 · **冬 雨** · ×1 · NPC 12 · 事件 2033 · 冲突 87(活 44) · 绘制 2903 · 节点 97 · 内存 85MB
→ **FPS 83 · 12.0ms**。（对照：D7 之前同类深度是 11 FPS。此读数仍压在 ~90Hz 刷新率天花板下，见 docs/46 §二·九-⑤。）
四季与天气在真机上**看得见**：冬天的草是淡青灰、雨丝可见、选举结果在顶栏。

**两条待查（R10 全帧眼验捞出来的，都还不是结论）**：

1. **★ C7 的接缝修复可能是【季节相关】的，而它从没在春天以外验过。**
   C7 报的 131.54 → **2.92** 是 seed 3 / tick 600 = 第 3 天 / **春**。它自己在"未测"里写了
   「**春季以外的季节没渲染过——季节耦合是按构造推理的，冬天与雨天要眼验**」，**而没有人去做**。
   我在这张冬雨真机帧上按 4px 采样先看到一条平滑斜坡、**据此差点判定"没问题"**；
   改成**逐像素**扫同一条带后读到**最大相邻跃变 57.37**。
   ⚠️ **但这还不能算数**：那条带在某些行上会压到界内美术（建筑边/田垄），
   而 C7 的教训正是"16px 剖线有 8px 落在界内 ⇒ 指标有地板"。
   **正确的做法是用 C7 自己写的 `scratchpad/wave_c/C7/seam.py`（跨界/界外/保真度三分）在冬雨条件下重跑**，
   而不是我这种粗扫。**记为 F3。**
2. **地图西南角有一片明显更暗的区域**：均亮 **50.0**，而同帧开阔草地是 **129.9 / 146.1**。
   可能是合法的区块地板或阴影，也可能不是。**同样需要按条件复核，不是结论。**

> **这一条本身就是 R10 的用法示范**：眼验负责**提出候选**，测量负责**判定**——
> 而我这次的第一轮测量**分辨率不够、差点把候选判死**。**采样间隔也是判据的一部分。**
