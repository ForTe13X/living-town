## 一、STEP 1 · 宿主可行性 + 为什么必须用 E4a 多货

闲聊 由 `counter_1`（吧台·cafe·[42,16]）与 `cafe1f_counter`（interiors）广告 `{action:闲聊, need:social}`——全镇亚线性最强的 fun/social 宿主（实测选中 150-215 次/seed/60天 N=12，×1.08 随人口，见 §五）。
- **闲聊 恒是 object-kind**：counter_1 是普通 town 对象，agent 选中走 travel→use（Sim.gd `_advance_object`）→ use 相位调 `_consume_for(ag,"闲聊")`；`_social_candidates` 从不吐「闲聊」（它吐 greet/give/gossip/…），故每次闲聊必走 object 派发。
- **它已有一件 consume 货（糕点）**：改前 `consume.闲聊={good:糕点,amount:1}`（E3b 挂的第一件工业货）。所以**不能像 E3b 那样加裸 dict**——单货结构一个动作只挂一件。这正是 E4a（docs/166）多货机器要解的封顶：改成 `consume.闲聊=[{糕点,1},{茶,1}]`（Array），E4a 双形状读者自动逐货扣件、逐货记 #40 需求、AND-fold 缺任一件不阻断动作。**零 Sim.gd 改动**（机器 E4a 已落）。
- **no-dilution 保证成立**：缺茶时 `_consume_for` 返回 false 只喂加价+社会后果，need 照在 use 分支补满；闲聊选中频率不随茶库存变 ⇒ 不新增决策槽。
- **糕点不受影响（★本片专门验的一格）**：糕点需求 = 闲聊次数 × 1，**一字未变**（E4a 逐货累加、按列表著者序遍历，茶是独立的第二件）。实测糕点留出锚中位 **+0.0050**（WITH）/ +0.0121（NULL）/ +0.0174（fei）⇒ **平/微升**，证多货机器不碰第一件货的满足率。

## 六、★结构规则（本片交给下一棒的最有价值一课）——比 E4b 更进一层
