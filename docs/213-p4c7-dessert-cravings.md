# 213 · P4c-7 嘴馋：隔天下午，有人想吃点甜的

> 触发：用户 2026-09-17「merge 73, then add dessert cravings」。
> [212](212-p4c6-creperie-to-the-center.md) 把可丽饼店搬到了镇中心、把甜点改成了消遣，可一个月还是只有几次客——
> 那一片的结论是：**位置不是瓶颈，【想吃】才是**（全镇平均 fun 常年 ~80，几乎没人闲到为了乐子出门）。本片补的就是"想吃"。

## 一、出货

`economy.cravings`（缺本段 ⇒ 不馋，逐字节回到 212 的树）：

```
{ "actions": ["吃点心"], "window": [0.55, 0.80], "every_days": 2, "pull": 20.0 }
```

- **哪天轮到谁**：`(day + fnv1a32(id)) % every_days == 0` —— 错开，不是全镇同一天馋；纯函数、不抽 RNG、不写状态。
- **两半，缺一不可**：
  - ① **开门槛**（`Sim._craving_on`）：平时"为 fun 出门"要 fun 掉到 55 以下（`VENUE_URGE` 45）才会生成候选；馋的时候这道门对他打开。
  - ② **加分**（`Sim._craving_pull`）：甜点候选 +pull（同平面与跨平面两处打分都认）。只加不减 ⇒ 不与生存打分争。

## 二、量出来的

### 1 · ① 是承重的那一半

只有 ② 时甜点根本进不了候选：fun ~80 ⇒ 缺口 20 < VENUE_URGE 45 ⇒ 一条"为 fun 出门"的行程都不生成。
这也是 212 §二·3 那句"要有人馋"的机检形式。

### 4 · CI 抓到的一处：出港在短跑里消失了

`scenes` lane 的 `ledger_test`（seeds 1-3 × **8 天**）红：「进口与出口在全体 run 里都出现过」缺 export。
根因在 211 的豆子 24→8：豆子库存要很久才爬过出港地板 36，60 天里还剩 0-5 次出港，**8 天的短跑里一次都没有**。
⇒ 豆子回到 **16**（两门仍 12/12 · 12/12、留出 17/18、BackendGate 0 红，ledger_test 全绿）。
⚠ 另一条教训：三份变体【并行】跑 ledger_test 会互相踩同一个 user:// 存档目录，B20 因此报了三条假的 `LR load_game` 失败；串行重跑全绿。
