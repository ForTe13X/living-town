### 2 · 用户那条"离店片刻店照开"：规则对，但**不是瓶颈**

- 第一版读出勤账 `work.done > 0`，下馆子 12-16% → 12-16%，**纹丝不动**。
  原因：`done` 只在【一整趟本职在班内干完】才 +1 ⇒ 它量的是"干完"，不是"来了"。跑堂 30 天 26 个班日里只有 12 天干完过一趟。
- 改成记【最后一次人在店里】（`post_seen`），grace 24 / 60 / 240 三档：**仍然几乎不动**。
- 逐日看跑堂的在店/在班（seed 1）：`16/125 36/125 0/125 53/125 … 0/125 0/125 0/125 …` —— **一半的班日一次都没进过店**，
  进了店的日子是【晚到、待到收工】。grace 只能续上"来过之后"的空档，续不上"根本没来"。
- 逐 tick 追一个没来的班日：fei 在 hunger 64 时去咖啡馆吃（50 tick）、hygiene 72 时去洗（53 tick）⇒ 班没了。
  **守岗规矩放行的是"照顾自己"这个类别，不管需不需要。**

⇒ 规则按用户的意思出货（它在"来过、出去吃口饭"的那些日子里确实承重），但真正拉开营业时长的是下面这条。

### 5 · BackendGate：CI 看得见的那个红，追到了两条引擎漏洞

候选版（上表"半职"那行）第一次跑 BackendGate：4 红 / 68 tick，其中 **seed 1 random(full) 23 tick** —— 落在 CI 的 seeds 1-4 里。
docs/206 §五记过的"CI 只看 1-4"这回直接撞上了。逐 tick 追：

- **seed 1 · dan**（理发师，**不在班**，守岗规矩与他无关）：夜里 hunger 15 时后端挑了【回家睡 40 tick】，一个跨平面 journey。
  `_horizon_ok` 对 journey **一律放行**（原注释：「跨平面 journey 没有同平面曼哈顿距离可言 → 不判」）。醒来走回灶台时触底 23 tick。
  与 docs/206 的 coco 同一种死法，入口在后端这一侧。
  ⇒ 修：journey 按【到本层 portal 口 + portal 成本×3 + dur】这个**下界**判（与 `_best_satisfier_journey` 打分用同一个估算），只驳回连下界都付不起的。
- **seed 4 · aria**（也不在班）：hunger 28、fun 26 时去集市逛店（跨平面 ~40 格），逛完 hunger 11.5 才被 pre-empt 抢回，走回灶台路上触底。
  这一步**后端的否决管不到**：她已在危机中 ⇒ 否决驳回一切 ⇒ 交给 `_logic_decide` 兜底，而兜底按"最低 need"挑了 fun。
  但 hunger 以 0.28/tick 掉、fun 只 0.16 ⇒ **hunger 100 tick 触底、fun 162 tick**。
  ⇒ 修：`_backend_floor` —— 危机中兜底只从【余量/衰减最小】那条 need 的候选里挑。

两处都**只在 `backend != null` 分支**被调用 ⇒ 金标路逐字节不变（§二·1 已机检）。

| 臂 | seeds 1-12 红 / tick | seeds 13-24 红 / tick |
|---|---|---|
| master | 2 / 5 | 2 / 31 |
| master + journey 判据 | 0 / 0 | — |
| master + 两处 | 0 / 0 | 0 / 0 |
| 候选 | 4 / 68 | — |
| 候选 + journey 判据 | 2 / 15 | — |
| **候选 + 两处（出货）** | **0 / 0** | **0 / 0** |

⚠ 零假设臂在 BackendGate 上**不可用**：`random` 后端均匀挑候选、不看分数，0.400→0.401 在 master 上一个 digest 都没动（24/24 同）。
所以这里靠的是 **seeds 13-24 这组没追过的 seed**：master 2 红、修复后 0 红，48 局里 4 → 0。
