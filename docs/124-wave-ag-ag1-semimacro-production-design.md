## 〇、一句话与四条会改变立项判断的事实

问题（[docs/113](113-macro-roadmap.md) §二最后一行 + Codex red）：**产出侧的【批量】已宏观池化（K1 `_pool_rescale`），但产出的【触发/到达过程】仍绑在少数具名工人身上。**
一次"本职在班完成"仍是**一个** NPC 的离散动作；克隆居民不入岗位表，所以任何 N 下每种货仍只有一两个生产者。批量宏观了，**到达过程没宏观**——一个 baker 是否及时到岗决定整条产业的节奏。

**本棒实读代码后，四条会直接改变立项判断的事实**（详见 §一—§四）：

1. **brief/S1 给的坐标 `:702` 已腐烂。** 克隆扩容的真身是 **`Sim.gd:780-787`**（`:787` 才是给 `npc_<i>` 只发 `{id,persona,spawn,home}` 的那一行）；`:702` 现在是 `_merge_prod_jobs`（把 `production.json` 的岗位并进 jobs 表）。**内容对**（克隆确实只拿那四个键、不入岗位表），坐标漂了约 85 行。岗位持有人**恒为 9**（`jobs.json` 6 + `production.json.jobs` 3），覆盖 **8 个产出职位**；其中**只有口粮有两个生产者**（面点师 90 + 渔夫 85），其余货各一个（§一.3）。

2. **"具名工人 → N=60 口粮左尾"目前只是【相关性候选】，不是已证因果**（外审 Codex 2026-08-06 §三.12）。仓库里唯一的量化根据是一条 **Spearman 相关** `ρ(口粮满足率, 面点师+渔夫在班完成) = 0.618`（`Invariants.gd:755`），外加 5/60 个红 seed 的展布。**相关不是因果**——本 session 反复栽在"观察→机制"的升格上（[docs/41](41-baton-contract.md) §4）。⇒ **§四的干预实证必须按"证伪"来写**：反事实**保持总产能不变、只解耦"完成时刻/具名工人到达"**；只有当"总产能不变、仅解耦到达"的干预**确实收窄了 N=60 左尾**，才谈得上按某条路建模。左尾不动 = "到达不是根因"的阴性结果，照实写。

3. **三条路都能被门控成"在 N=base 逐字节等同今天"，所以"零金标影响"对三条都可达——但那个"零"是金标的【盲】，不是【验证】。** 金标锚在 **N=12** 上烘（`Harness --agents` 缺省 0 = 数据原样 12 条；`_bake_golden` 不传 `--agents`），而 K1 的池在 `num==base` 时直接 `return raw`（`Sim.gd:3284-3285`）⇒ 任何"只在 `pop>base` 才生效"的改动在 N=12 一条指令都不跑 ⇒ 四个金标量逐字节不变（法则 A，§三）。**但**：CI 的 S0 金标恒跑 N=12（池倍率 =1、`backend=null`），4a 宏观池门跑 N=16/24 且**不比锚只跑判据**（`tools/ci.sh:385-386`），而 **N=60 那一端根本没有门**（`tools/ci.sh:423`）。⇒ 真正的修复发生在 CI 看不见的地方，**必须靠 N>12 的离线干预来证，不能靠"金标没动"来证**。

4. **社会痕迹（#41/#43）是被【具名工人的在场】生成的，不只是被存下来的。** 它读的是 `produce`/`pay` 事件的 `actor`（具名工人 id）+ `witnesses`（`_nearby_agents(工人)` 数出来的在场者）+ `CR:<职位>`/`TR:<职位>` 信念（`subject=工人 id`）。这些信念/关系/standing 的**存储**侧，`Sim.save_game` 的反射式快照**今天就已经持久化了**（[docs/121](121-wave-af-af1-state-projection-design.md) §2.1 实测：beliefs/attitudes/relationships/standing 都在权威面里）⇒ **风险不在存储，在生成**：解耦一旦把"谁在工位上"抽掉，`actor`/`witnesses`/`subject` 三样一起失去锚点。**并且** `_holder_of_title` 只返回**单个**持有人（`Sim.gd:3335-3339`、`Invariants.gd:1024`）——**给同名职位加第二个持有人会直接打中 #41 的反向臂**（`Invariants.gd:1068-1072`，把非首位持有人的带证产出判成"外溢"→红），这条对路 (a)/(b) 是硬约束。

⚠️ **本文不替用户拍板**（[docs/113](113-macro-roadmap.md) §六：改产业模型是用户的决定）。本文给的是让用户能拍板的材料：现状（给行号）、社会痕迹从哪来、三路代价（金标影响给结构性推断依据）、一条**以证伪为前置**的干预设计、一条推荐、分阶段、以及设计阶段答不了的清单。

## 一、现状盘点（**读码，给行号**）

### 1.1 `_produce_for` 的触发条件（`Sim.gd:3356-3363`）

```gdscript
# Sim.gd:3356-3359
func _produce_for(ag: Dictionary, action: String) -> void:
    var job := _job_of(String(ag["id"]))
    if job.is_empty() or _job_action(job) != action or not _in_shift(job):
        return
```

三段合取守卫，缺一即空手返回：**① 这个 agent 有本职**（`_job_of` 从 jobs 表按 id 查，`:3018-3019`，无岗位 → `{}`）；**② 这条动作 == 他的本职动作**（`_job_action`，`:3041-3046`，`production.job_action` 按职位覆盖，是"这个人的本职动作"的单一真相源）；**③ 他在班**（`_in_shift`，`:3022-3027`，看当前相位是否落在 `job.shift`）。三条全过，才去取 `production.produce[title]` 那条记录（`:3361`）；记录空（该职位无产物）也返回（`:3362-3363`）。

⇒ **产出的触发是一次具名 NPC 的离散事件**：只有当那一个持有人**在班、且这一 tick 恰好完成了本职动作**时，镇库才 +1 批。

### 1.2 "到达过程"具体是哪几步（`Sim.gd:1471-1557`）

一批货落进镇库，要走完一条**单 NPC 串行流水线**，每一步都可能岔出去：

| # | 步骤 | 行号 | 岔出去会怎样 |
|---|---|---|---|
| ① | **决策 / 候选枚举**：该 NPC 枚举物件广告，工作候选 = 广告动作 == 他本职动作的那条工位 | `_object_candidates`（枚举在 `:1940+`） | 枚举不出工作候选（不在工位区/不在班）⇒ 这一 tick 不可能去干活 |
| ② | **argmax / 后端挑选**：工作候选要在打分上赢过吃/睡/社交等 | 打分公式 `:1806` 注释、施加在 `:1980-2035` | 更急的需求夺魁 ⇒ 他去吃饭/睡觉，不去工位 |
| ③ | **导航**：不在工位时，每 tick 朝工位走一格 | `_move_agent(ag, _nav_step(...))` `:1523` | 路远 ⇒ 到岗要好几 tick；中途重决策可能改主意 |
| ④ | **占位 + 时长**：到岗后走 `use` 分支，每 tick 把 `amount/dur_total` 回补进 need、`remaining` 倒数 | `:1525-1530` | 未走完 `dur_total` 个 tick ⇒ 这一趟不产货 |
| ⑤ | **完成 → 产出**：`remaining<=0` 才调 `_produce_for`（再查一遍 §1.1 守卫） | `:1530-1535` | 完成一次 = **一批**（池尺度批量，§1.3） |

⇒ **每天的产业吞吐 = 那一个持有人当天"在班完成本职动作"的次数 × 池尺度批量**。第一个乘子（完成次数）是一条**高方差、下沿贴地**的单 NPC 到达过程；池只放大了第二个乘子。这就是"半宏观"的确切含义。

### 1.3 产出量算法（宏观池那一段，`Sim.gd:3267-3307` + `production.json`）

批量来自 `production.produce[title].amount`，而 `production` 是**派生值**：`start_new` 里 `production = _pool_rescale(_production_raw, agents.size())`（`:813`）。`_pool_rescale`（`:3267`）按 `num/base` 整数有理数缩放 `amount/inputs/cap/spoil_per_day/start_stock`（`pool` 列表，`production.json:21`），其中：

- `base_population=12`、`quantum=0`（连续）⇒ **N=12 上 `num==base` 直接 `return raw`**（`:3284-3285`），一个整数都不算 ⇒ **N=12 逐字节等同逐笔**。
- 产出表 8 个职位（`production.json:61-69`）：**面点师 口粮/90、渔夫 口粮/85**（口粮唯一的两个生产者）、杂役 柴薪/65、木匠 柴薪/50、咖啡师 豆子/36、教书先生 话本/6、环卫工 整洁/16、泥瓦匠 屋瓦/30（`inputs:{柴薪:3}`，全镇唯一有原料的工种）。

⇒ 池把"一次完成"的语义从"一个人的产量"换成"这一行在这么大的镇上的产量"（`:3400-3404` 的记忆措辞也跟着换，避免"一个泥瓦匠一天烧 150 片瓦"）。**但池不碰"一天完成几次"**——那仍由 §1.2 的单 NPC 到达过程决定。

### 1.4 克隆体为什么不进岗位表（`Sim.gd:780-787` + `:3018`）

扩 N 时（`spawn_count > defs.size()`，`:781`，仅当 N>12 触发；N=12 默认 `spawn_count=0` ⇒ 无克隆）：

```gdscript
# Sim.gd:787
defs.append({"id": "npc_%d" % i, "persona": base["persona"], "spawn": [sp.x, sp.y], "home": [sp.x, sp.y]})
```

克隆只拿 `{id, persona, spawn, home}` 四个键——**没有 `title/action/wage/shift`**。而岗位查表 `_job_of(id) = jobs.jobs.get(id, {})`（`:3018-3019`）对不在 jobs 表里的 id 返回 `{}` ⇒ §1.1 守卫第一段 `job.is_empty()` 即真 ⇒ 克隆**永远产不出货**。岗位表本身来自 `jobs.json`（6 人）+ `_merge_prod_jobs`（`production.json.jobs`，3 人，`:696-703`），两处都是**手写的具名 id**，克隆的 `npc_<i>` 不在其中。

⇒ **岗位数恒为 9、每种货的生产者数与 N 无关**（`Sim.gd:3245` 自己的注释："任何 N 下恒为 9"）。人口 ×5，而"面点师/渔夫仍各一个"。

### 1.5 人口感知的吸引力乘子只帮【具名持有人】，招不动克隆（`Sim.gd:1772-1860, 1999-2035`）

评审曾提"`worker_count × work_capacity_factor(population)`"。仓库**已实现了 `capacity_factor` 那一半**，但它只作用于持有人自己：

- `work_pull_mult`（L2，`:1772`；R1 的饱和型 `1+kn(pop−base)/(kd(pop−base)+kc)`，`:1786+`）：镇越大、本班越重。但施加处 `:1999-2001` 三道门——`adv["job"]!="" 且 _in_shift(_job_of(ag))`——**只有在班的岗位持有人**才乘得到。
- `_stock_pull_mult`（T1，`:1848`；空仓加劲、满仓歇脚）：施加门 `:2007-2015` 用 `_job_action(job)==action`，**与 `_produce_for` 开头那道守卫在构造上重合**。

⇒ 这两条乘子让**那一个** baker 更急着去烤面包，但**克隆没有岗位 ⇒ 乘子恒 1.0 ⇒ 招不动他们去干活**。`worker_count`（生产者头数）这一半在现有结构下**够不着**（`Sim.gd:318-321` 自己写了这条）。

### 1.6 "根因"目前是相关，不是因果（`Invariants.gd:709-805`）

#40（软·产出闭环活性与供给充足，`:985-993`）读的是**满足率 = 到手件数/想要件数**，对记账单位免疫、分母读 `S.production`（池，`:770-774`），阈值 `SUPPLY_FLOOR=0.5`（`:60`）。左尾的量化根据（`Invariants.gd:748-761`，S1 实测）：

- **60 seed 里 5 个跌破**（合计 5/60）；其中 4 个是口粮。
- **Spearman `ρ(口粮满足率, 面点师+渔夫在班完成) = 0.618`**（`:755`）。红 seed 的"面点师+渔夫 60 天在班完成之和"是 5/6/7/8（全 60 seed 展布 5..30）；第五个红 seed 是咖啡师 60 天只上工 1 次（豆子 0.369）。
- **逐岗位在班完成是高方差贴地量**（`:760-761`）：咖啡师 1..17、杂役 1..10、渔夫 2..14、面点师 2..19（60 seed）。

⇒ **这是一条相关（ρ=0.618）+ 一个机制上说得通的故事**（单 NPC 到达方差大 → 联合低抽样 → 供给塌），**但没有一个干预证明过"把方差按住、左尾就收窄"**。`Invariants.gd:795-801` 已经给了反例警告：**"把产量放大"不是单调干预**（灌满 `cap` 不动 ⇒ 满仓丢货；灌满整洁 ⇒ `_clean_mult`≡1 ⇒ 全镇反而少干活）。⇒ 因果必须用**保持总产能不变、只解耦到达**的干预来证（§四）。

## 二、`IndustryState` 的形状 & 社会痕迹从哪来（要回答的核心问题）

### 2.1 社会痕迹（#41/#43）到底读什么——这决定了"能丢什么、不能丢什么"

- **#41（V1/Z2 手艺痕迹，`Invariants.gd:995-1075`）** 读三样：① `produce` 事件真的带了 `witnesses`（`pr_w`，`:1017`）；② 有人**亲眼**形成 `CR:<职位>` 信念（`subject=持有人 id`、`via∈{seen,gossip}`、至少一条 seen，`:1042-1062`）；③ **反向臂**：没开本机制的产者的 `produce` 事件 `witnesses` 必须恒空（`:1066-1072`）。这三样的生成点全在 `_produce_for`：`wits=_nearby_agents(ag)`（`:3394`）→ `_stock_move(..., wits)` 写进事件（`:3331`）→ `_craft_fallout` 形成信念（`:3534+`）。
- **#43（AA3/AA3-FIX 买卖痕迹，`Invariants.gd:1079-1130`）** 同构：读商贩那条 `pay(note=buy:…)` 事件的 `witnesses`（滤掉商贩本人）+ `TR:<职位>` 信念 + "其余 pay 事件 witnesses 恒空"的反向臂。生成点在消费侧 `:1510-1519` + `_trade_fallout`（`:3594+`）。
- **两条都经 `_holder_of_title`**（单个持有人，`:3335-3339`）定位那个具名工人。

### 2.2 存储 ≠ 生成（外审 §三.11 的提醒，落到本设计上）

`Sim.save_game` 的反射式全量快照**已经持久化了**社会痕迹的**底物**：beliefs（含 `CR:*`/`TR:*`/`SH:*`）、attitudes、relationships（affinity/standing）都在权威面里（[docs/121](121-wave-af-af1-state-projection-design.md) §2.1/§三.2 实测）。⇒ **"社会痕迹如何保住"不是一个存储问题**——痕迹一旦生成，save_game 就存得住（AF1 另证它甚至存得"太松"，那是另一条账）。**风险全在生成侧**：解耦一旦让"没有具名工人在工位上"也能产货，`produce`/`pay` 事件就失去 `actor`、`_nearby_agents` 无锚点、`CR/TR` 信念失去 `subject` ⇒ #41/#43 的判据**读到空**，社会痕迹这一层**从源头断供**。

### 2.3 核心问题的回答：到达怎么从"离散动作"变"连续过程"而不丢 WHO

> **把产业拆成两个可分离的量**：**"产多少/何时产"（RATE）** 与 **"谁产的/谁看见"（ATTRIBUTION）**。

今天两者**捆死在同一次离散动作上**（`_produce_for` 一次调用同时决定 RATE 和 ATTRIBUTION）。`IndustryState` 的形状 = **把 RATE 上移到镇级连续过程，把 ATTRIBUTION 留在具名 NPC 上**：

- **镇级 `IndustryState`（每产业一条）**：`labor_capacity`（在班具名工人贡献的连续产能率）、`backlog`（累积的未完成工时/欠产）、`inputs`（原料账，接 `_stock_take`）、`output_rate`（每 tick 或每日交货率）。节奏由**累积产能**决定，不再由某一个 NPC 的一次动作触发。
- **ATTRIBUTION 仍走具名 NPC**：当累积器跨过一个批量阈值、要落一条 `produce` 事件时，**把它归因给一个确定选出的在班持有人**（多人在班时按稳定身份 `_cand_key` 定序取，红线 #1，**不得取数组下标**），`witnesses=_nearby_agents(该持有人)`，`CR:<职位>` 信念照 `_craft_fallout` 原样形成。

⇒ 这样 RATE 被镇级化（方差被产能累积摊平），而 #41/#43 读到的 `actor`/`witnesses`/`subject` 三样**逐字段照旧**。关键推论：连续率下批量交货会**更规律** ⇒ 带证 `produce` 事件**变多** ⇒ #41 的"被看见"余量**变宽**而非变窄（这是正向副作用，§五末）。

## 三、三条实现路的代价对照（**金标影响一律给结构性推断依据，不写"应该不大"**）

**金标推断的地基（按人口尺度改写 [docs/116](116-wave-ad-ad2-event-outcome-model.md)/[docs/121](121-wave-af-af1-state-projection-design.md) 的法则框架）**：S0 门每 CI 比对四个量——`digest`/`event_digest`/`chain`/`events`——对**在 N=12 上烘的**金标锚。

- **法则 A（在 N=base 恒等 ⇒ 零锚动）**：改动若门控成"仅 `pop>base` 才生效"，则 N=12 上一条指令不跑（同 `_pool_rescale` 的 `num==base` 短路）⇒ 四量逐字节不变 ⇒ **不触发 R12 的锚重烘**。**推断依据**：金标锚 `Harness --agents` 缺省 =12（`Harness.gd:107`），产出表在 N=12 未换尺度（`:3284-3285`）。这正是 K1 池已经在用的模式。
- **法则 B（动 N=12 的产出事件 ⇒ 全动锚，完整 R12）**：任何在 N=12 就改 `produce`/`pay` 事件的 `actor`/批量（进 `note`）/条数/顺序的改动 ⇒ 四量全变 ⇒ 每个受影响 seed 移金标 ⇒ 三份锚重烘 + 留出 13-30 双侧（[docs/47](47-wave-e-plan.md) §〇）。例：在**手写的 12 人**里塞第二个面点师。
- **法则 C（只在 N>12 可见 ⇒ 不动锚，但改判据门 + N=60 无门）**：只在 N≥16 生效的改动**不动 N=12 锚**（不重烘），但**改 4a（N=16/24）跑的 #40 判据**（`tools/ci.sh:385` 只比判据不比锚），而 **N=60 无门**（`:423`）。真正的修复住在这一档 ⇒ **金标"没动"是盲、不是验证，必须靠 §四离线证。**

### 路 (a)：让克隆体可就业（进岗位表）

- **schema/机制**：`:787` 克隆扩容时给 `npc_<i>` 补 `title/action/wage/shift`（或造一个把克隆映射到岗位的表）。仅 `pop>12` 触发。
- **金标影响**：**N=12 逐字节不变（法则 A）**——N=12 无克隆，`:781` 分支不进。但这个"零"是 §〇.3 的盲：真正的行为改变全在 N>12，而那里只有 4a 判据门、N=60 无门。
- **与 K1 池【双重计数】——最硬的一条下游**：池已经把**一次完成**缩放成"整行的产量"（×N/base）。再让 N/base 个在职克隆**每人**产一份**池尺度**批量 ⇒ **(N/base)² 过产**（N=60：25×）。⇒ **路 (a) 与现有池不相容**，必须为可就业产业**撤掉或重标定池**（把 `amount` 除回单人量）。这是对 K1 双尺度的**大手术**，不是加法。
- **对 #41/#43 的下游——第二条硬约束**：同名克隆 ⇒ `_holder_of_title` 只返回首位（`:1024`）⇒ #41 反向臂（`:1068-1072`）把**非首位持有人的带证产出判成"外溢"→ 直接红**。必须把 `_holder_of_title` 泛化成 `_holders_of_title`（复数），并同步改 #41/#43/vendor/`_merge_prod_jobs` 的唯一性假设。
- **社会痕迹**：**保住且更丰富**（每个克隆是具名的，产自己的事件/witnesses/信念）——**前提是**上面那条复数化改对。
- **迁移成本**：**高**（撤池 + 复数化 + 岗位分配的确定性）。
- **对 N=60 左尾的预期效果（推断，需 §四证）**：更多生产者 ⇒ 聚合到达方差按 ~√(生产者数) 收窄（CLT），左尾**部分**收窄；但仍是离散逐 NPC 到达，且相关的集体停工（夜/坏天/节庆）留一层地板 ⇒ **不能消除，只能压低**。

### 路 (b)：给岗位加学徒位

- **schema/机制**：给每个产出职位加 `capacity(pop)` 个学徒持有人（同 title、同 action）。
- **金标影响**：**取决于学徒从哪来**。学徒名额 `capacity(12)=0`（在 base 恒 0）⇒ 在手写 12 人里不加人 ⇒ **法则 A（N=12 不变）**；若从手写 12 人里抽一个当第二 baker ⇒ **法则 B（动 N=12 锚，完整 R12）**。可设计成前者。
- **与池双重计数**：**同 (a)**——多个持有人 → 多次完成 → 必须把池按持有人数除回，否则过产。
- **对 #41/#43**：**同 (a) 的 `_holder_of_title` 复数化硬约束**（学徒与师傅同 title）。外加**新约束**：工位占用——两个 baker 能不能同时占 `counter_1`？工位广告是共享对象，并发占用今天无模型。
- **社会痕迹**：保住（学徒是具名 NPC）；复数化后 #41 的"被看见"分母变大，余量口径要重定。
- **迁移成本**：**中**（比 (a) 少一个"撤池"的量级，但多一个工位并发模型）。
- **对 N=60 左尾**：比 (a) **更可控**（名额是 `pop` 的确定函数，不靠克隆轮转），方差收窄同 (a) 的 √ 律；仍是离散到达。

### 路 (c)：镇级 `IndustryState` accumulator（§二.3 的形状）

- **schema/机制**：新增镇级 per-产业状态（`labor_capacity/backlog/inputs/output_rate`），RATE 上移到连续过程、ATTRIBUTION 留在在班具名工人（§二.3）。在 base 上 `labor_capacity` 退化为单工人离散率 ⇒ **恒等于今天**（同池的 `num==base` 短路）。
- **金标影响**：**N=base 逐字节不变（法则 A）**，前提是累积器在 `pop==base` 退化为原离散触发；N>base 走**法则 C**（改判据门、不动锚）；**仅当把 `IndustryState.output` 折进金标锚**才走法则 B（用户旋钮）。**推断依据**同池：base 上不换尺度、`produce` 事件的 `actor`/`note`/条数/顺序不变。
- **与池的关系——它【subsume 池】而不是撞池**：池 = "一次完成 × N/base"，`IndustryState` = "labor_capacity ∝ 人口 → 连续产出"，后者把前者作为特例吸收（labor_capacity 在 base 上 = 单工人率）。⇒ **不产生 (a)/(b) 的双重计数**（RATE 只有一处算）。
- **对 #41/#43**：**这条路社会痕迹风险最高，但也最可控**——只要落 `produce`/`pay` 事件时**仍把 `actor` 设成确定选出的在班持有人、`witnesses=_nearby_agents(holder)`**（§二.3），#41/#43 逐字段照旧读，且 `_holder_of_title` 单持有人假设**不必动**（每产业仍一个具名归因锚）。
- **迁移成本**：**最高**（一个新子系统 + save_game 要持久化它 + 与 AF1 的 state_projection 盲区相关，§六）。**但它是三条里唯一真正解耦了到达过程（连续率、零单 NPC 方差）的**——(a)/(b) 只是把一个高方差量换成 N/base 个高方差量的平均，(c) 把它换成一个确定率。
- **对 N=60 左尾**：**若 §四证实到达方差是因**，(c) 的预期效果最强（把 §1.6 那条"贴地高方差的单 NPC 完成次数"整个换成产能累积的确定率 ⇒ 左尾结构性收窄）。**若 §四阴性**，(c) 也白搭——它解的正是"到达方差"。

|---|---|---|---|---|---|---|---|

## 四、干预实证的【设计】（**证伪优先：保持总产能不变、只解耦到达**）

⚠️ **这一节是设计，不是实证本身**（实证是实现波的事）。它明写"怎么用干预证明某条路真解耦了到达过程、且那真是 N=60 左尾的因"。**核心纪律（外审 §三.12 + U1）**：反事实必须**总产能不变、仅动到达**；判据用**连续余量**、对**零假设臂**、**别看红数**。

### 4.1 为什么不能只跑"把产量放大"

`Invariants.gd:795-801` 已证：放大产量**不是单调干预**（灌满 `cap` 丢货、灌满整洁关掉 `_clean_mult`）。而且"多产 ⇒ 供给够"是**同义反复**，证明不了"到达方差是因"。⇒ 干预必须**把总产能钉在 null 的均值上**，只改到达的**方差/时刻**。

### 4.2 干预臂设计（三臂，全在隔离副本、N∈{48,60}、seeds ≥ 全 60）

- **NULL（对照）**：今天的树，逐 NPC 离散触发（面点师/渔夫 …）。先在 ≥48 seed 上量出**每职位日均在班完成数**（`prod_stats.work`，`Sim.gd:3388`）与**逐 seed 最差货满足率**的分布——这是"总产能"的基准与"左尾"的基准。
- **T1（产能匹配 + 到达解耦）**：把某产业的产出改成**确定连续率**，其**期望日产 = NULL 臂实测的日均完成数 × 池批量**（逐职位配平，保总产能**均值相等**）、但**方差≈0**（每 tick/每日按率交货，不再等单 NPC 完成）。⇒ **同均值、去方差**。ATTRIBUTION 仍按 §二.3 归因给在班持有人（这样 #41/#43 与社会面不被这次干预污染）。
- **T2（产能匹配 + 到达【不】解耦 = 安慰剂）**：同样把总产能配平到 NULL 均值，但**保留单 NPC 离散触发**（例如把批量按配平系数微调、触发仍绑一个 NPC）。⇒ **同均值、留方差**。T2 是"配平本身"的安慰剂对照，隔离"是解耦起效、还是只是把均值抬到了配平线"。

### 4.3 判据（连续余量，别看红数）

- **主指标**：逐 seed **最差货满足率的左尾**（≥48 seed 的最小值 / 第 5 百分位 / 低于 `SUPPLY_FLOOR` 的 seed 计数**的连续前身**——用满足率的**连续分布**，不用 #40 的红/绿）。
- **判决**：**T1 的左尾必须显著右移，且这个右移要大于 T2**（配平安慰剂）**、也大于零假设臂**。
- **零假设臂（U1 纪律，[docs/80](80-wave-u-u1-open-the-key.md)）**：`utility.obj_dist_penalty` 0.400→0.401——语义为零、却也会移动结果（金标里多处记载它"消掉硬红/给同样的 13"）。**T1 对左尾的改善必须落在零假设臂的带子之外**，否则量到的是噪声不是解耦。
- **阳性对照**：借 K1 的负对照方向——删 `scale` 块 ⇒ 供给塌（`tools/ci.sh:397-399`），确认这套度量对"供给真变"有分辨力。
- **样本量**：**≥48 seed**（`Invariants.gd:762` 明写"要证明修好了先跑 ≥48"），左尾是低频事件（5/60），小网格读作"分辨不出"。

### 4.4 两种结局都照实写

- **阳性**：T1 左尾右移 > T2 且 > 零假设臂 ⇒ **到达方差是因**被证实 ⇒ 才谈得上按某条路（推荐 (c)）建模。
- **阴性**：T1 左尾不动、或与 T2/零假设臂分不开 ⇒ **"到达不是根因"的阴性结果**，照实写（别把 ρ=0.618 硬当因果）。此时该查的是别处：池的 `cap` 截断（`:3325` 满仓丢货）、原料链（泥瓦匠柴薪）、或需求侧时刻集中——**而 (a)/(b)/(c) 都不该在阴性下上马**，因为它们解的都是到达。

## 五、推荐 + 分阶段 + 风险 + 社会痕迹如何保住

### 5.1 推荐：**路 (c) `IndustryState`——但把 §四的证伪作为立项前置闸**

**推荐 (c)**（与 [docs/113](113-macro-roadmap.md) §二、Codex 一致），理由：

1. **只有 (c) 真正解耦到达**（连续率、零单 NPC 方差），(a)/(b) 只把一个高方差量换成 N/base 个的平均，且都**撞 K1 池的双重计数**、都**逼 `_holder_of_title` 复数化**（打中 #41 反向臂）。
2. **(c) 把"移不移金标"变成用户旋钮**（base 恒等=法则 A、折锚=法则 B），且**在 base 上逐字节等同今天**（同池模式）。
3. **(c) subsume 池**（RATE 一处算，不双重计数），**且能保住社会痕迹**（ATTRIBUTION 留具名锚，§5.4）。

⚠️ **但推荐是【有条件】的**（外审 §三.12）：**先跑 §四的产能匹配 + 到达解耦干预**。ρ=0.618 只是相关；(c) 解的正是到达方差，若 §四阴性，(c) 修不动 N=60 左尾，**别上马**。**这一条是整个立项的闸门，不是脚注。**

### 5.2 分阶段（走完整 R12 的那一步明写）

- **阶段 0 — 证伪闸（不改 trunk，隔离副本）**：跑 §四 三臂（NULL/T1/T2）× ≥48 seed，连续余量对零假设臂判。**阳性才进阶段 1；阴性则立项终止、改查别处。**
- **阶段 1 — `IndustryState` 骨架，在 base 恒等（零金标·法则 A）**：新增镇级 per-产业状态，`pop==base` 退化为今天的离散触发。**落地必用自造 A/B 兑现**（改前/改后各跑 `Harness --chain-dump`：`digest`/`event_digest`/`chain`/`events` 四量在 N=12 逐字节相同，法则 A 是推断，落地要实测——历史上"读注释以为没动"翻过车，[docs/41](41-baton-contract.md) §4）。
- **阶段 2 — N>base 走连续率 + 归因路由（改判据门·法则 C）**：累积 `labor_capacity` 驱动批量节奏；落 `produce` 事件时 `actor`=按 `_cand_key` 确定选出的在班持有人、`witnesses=_nearby_agents(holder)`（§5.4）。**验收：4a（N=16/24）保持绿**（`tools/ci.sh` #40 判据），#41/#43 在 N>12 上不红。
- **阶段 3 — N=60 held-out 供需校准 + 补 N=60 门**：在 N=24/40/60 跑 §四的留出验证（阳性该复现）；**N=60 今天无门（`tools/ci.sh:423`）⇒ 修复的自证门要一并建**（照 4a 的判据臂形状，别写死绝对次数，[docs/41](41-baton-contract.md) §2.5）。
- **阶段 4（可选·用户拍板）— 把 `IndustryState.output` 折进金标锚（法则 B·完整 R12）**：若判断"镇级产能必须被 CI 每 seed 钉死"，给它新增锚 ⇒ 每 seed 移金标 ⇒ 三份锚重烘 + `rebake_history` + 留出 13-30 双侧。**纯口径决定，交用户。**

**明写：阶段 0-3 不移 N=12 金标锚 ⇒ 不适用 R12；只有阶段 4 触发** [docs/41](41-baton-contract.md) §3 + R12。**但阶段 1-3 每一步仍须自造 A/B 兑现"没动旧四量"**（法则 A/C 是推断，落地要实测）。

### 5.3 风险清单（**照实列，别装作想清楚了**）

1. **整个推荐压在 §四的阳性上。** ρ=0.618 是相关；若到达不是因，(c) 白做。**阶段 0 是硬闸。**
2. **归因路由的确定性（红线 #1）。** 多人在班时"这批货算谁的"必须由稳定身份 `_cand_key` 定序，**不得取数组下标**（否则枚举序一变、历史被静默改写，[docs/41](41-baton-contract.md) §0 红线 #1）。tie-break 盐取稳定身份，且要负对照（重排持有人枚举序 ⇒ 归因不变）。
3. **base 恒等是推断不是实测。** 阶段 1 必须 A/B 兑现 N=12 四量逐字节不变。
4. **性能（红线 #3）。** 镇级 per-产业 per-tick 累积在 N=60/100+ 真机（骁龙 8 Elite）的成本没测；[docs/54](54-scale-n60.md)/[docs/113](113-macro-roadmap.md) §0.5 明写 N>24 一格没测过。**必须真机实测，不能估**（MEMORY #34 池化史 = 满负载内存是真痛点）。
5. **save_game 要持久化 `IndustryState`。** 它是新的镇级权威态；不入快照 ⇒ 存读档丢产能 ⇒ 恰好落进 AF1 那个"投影盲区"（[docs/121](121-wave-af-af1-state-projection-design.md) §四）。**IndustryState 是 state_projection 的又一个消费者**，两者要一起想。
6. **原料链（泥瓦匠柴薪）在连续率下怎么走。** `inputs` 今天在 `_produce_for` 里逐次 `_stock_take`（`:3371-3383`），连续化后原料扣减的时序/缺料缩水（`:3382`）要重定，且 #38 账本恒等式（`_stock_move` 唯一通道）不能破。
7. **N=60 左尾的量具本身余量已薄**（#40 在 N=24 是 11/12、余量 0，`tools/ci.sh:380`）⇒ 建 N=60 门时别把 fixture 朝最容易过的方向选（[docs/41](41-baton-contract.md) §2 第三盲区）。
8. **(a)/(b) 若最终被选**：`_holder_of_title` 复数化会波及 #41/#43/vendor/`_merge_prod_jobs` 四处，且撤池是对 K1 的大手术——**这些代价要在切路前一起摆上桌**。

### 5.4 社会痕迹如何保住（**推荐路 (c) 的明确承诺**）

- **痕迹的生成三样不动**：`produce`/`pay` 事件的 `actor`=在班具名持有人、`witnesses=_nearby_agents(holder)`（`Sim.gd:3394`）、`CR:<职位>`/`TR:<职位>` 信念 `subject=holder`（`_craft_fallout`/`_trade_fallout` 原样）。`IndustryState` 只改 RATE（何时/多少落批），**不碰 ATTRIBUTION**。
- **`_holder_of_title` 单持有人假设不必动**（每产业仍一个归因锚）⇒ #41 反向臂不被惊动（这正是 (c) 比 (a)/(b) 省的那一刀）。
- **存储侧本就够**（§二.2）：save_game 反射已持久化 beliefs/standing/relationships（AF1 §2.1）⇒ 生成出来的痕迹存得住。
