### 2.1 `Sim.gd`：工位广告的【镇库回拉】`_stock_pull_mult`

```
f = (hi·(cap − stock) + lo·stock) / (den · cap)
```

- `stock=0` ⇒ `f = hi/den`（空仓加把劲）；`stock=cap` ⇒ `f = lo/den`（满仓歇一歇）；线性插值。
- **分子分母全整数、只做一次 IEEE 除法**（除法是正确舍入的）⇒ 红线 #1 的逐位可复现。
  log/sqrt/pow 一概不用，理由与 K1 的池、L2 的 `_form_why` 逐字相同。
- **三道门**：
  ① `den <= 0`（缺 `production.stock_pull` 键 / 任一项非法）⇒ 恒 1.0，一条指令都不多跑；
  ② `mods_ok` 生存门——任一需求告急 ⇒ 整个关掉（它含**抬**的一侧，这道门在这里承重）；
  ③ **这条候选的动作 == 这个人的本职动作，且他在班**——逐字就是 `_produce_for` 开头那道守卫。

> 而 `_job_action` 的抬头注释本来就写着它是**「这个人的本职动作」的单一真相源**
> （`_wage_for` / `_produce_for` / 技能三处共用，"三处一旦分家就会出现只在某个 seed 上现形的偏差"）
> —— **我一开始立了第四个口径，而仓库自己已经写下不许这么做。**
- **不动 `amount`**：`amount/dur_total` 是每 tick 回补的 need 量，改它就是改微观需求侧
  （[docs/41 §0.5](41-baton-contract.md) 写死微观不降级）。F1/F5/G3 三波标定出来的相对比例
  （34/20/46/46/46/32/46/38）**一个字节没碰**。

### 2.2 `production.json`：**出货数据里【没有】这个键**

打开它需要往 `production.json` 加一段：

```json
"stock_pull": {"hi": 110, "lo": 90, "den": 100}
```

**而出货树里没有这一段** ⇒ `stock_pull_den == 0` ⇒ `_stock_pull_mult` 第一行就返回 `1.0`，
`_object_candidates` 里那道 `if stock_pull_den > 0` **连乘法都不进** ⇒
**出货树与开工时逐字节相同**（金标 12/12 含逐 tick 前缀链，实测）。
理由见 §九；本回执 §三~§七 的全部数字都是在**隔离副本**里把它打开跑出来的。

### 2.3 **自带零假设对照**：`hi == lo == den`

`hi=lo=den=100` 时分子恒等于 `100·cap`，与分母逐位相同 ⇒ `f ≡ 1.0`，
**而代码路照跑、乘法照做**。实跑 `--seeds 1-12 --days 60 --det 1 --golden`：

```
✅ #01 12/12  ✅ #38 12/12  ✅ #39 12/12  ✅ #40 12/12
✅ 金标一致 12/12 seed（含逐 tick 前缀链 12 条）
=== S0 GATE: PASS ✅ ===
```

⇒ **算术在中性点上是精确的**，"这一档等于没做"不是推断。
（这一条是照抄 L2 `_calibration` 里那个 `k=1/1000` 零假设的做法，只是本形状可以做到**逐位**而不是"近似不动"。）

### 2.4 选档规则——**在看到 48-seed 结果之前写下**（[docs/75 §〇](75-wave-t-plan.md)「不许挑一格好看的网格」）

1. seeds **13-60**（48 个留出）上 `#40` **两条臂都 0 红**；
2. seeds **1-12** 上 `#40` 12/12 绿、硬不变量 12/12 绿（不许"修好远端弄坏近端"）；
3. 满足 1-2 的档里，取**离 1.0 最近**的那一档——**最小干预**：这个世界被 F1/F5/G3 手工标定过三波，
   扰动越小越好，而本棒交付的是**机制**不是幅度；

## 九、**CI 抓到了我，而抓到的那条是我自己没推导出来的约束**

### 9.1 它红在**上限臂**——而原因是一条我本该先算出来的乘法

隔离副本实测 N=16 seeds 1-12（`analysis/t1/n16_*.jsonl`）：

| N=16 seed 1 | 最差货 | **全年零缺货** | 臂 |
|---|---|---|---|
| 改前 | 口粮 0.732 | **1/6** | — |
| `lo=90` | 口粮 0.805（**更好**） | **4/6** | **上** ❌ |

**最差货变好了，而门红了** —— 红的是【缺货绝迹】，不是供不应求。

**机制（一行乘法）**：`benefit` 上串着**两条**工作乘子，它们相乘：

```
N=12 :  work_pull_mult = 1.000  →  合成范围 = [0.90, 1.10]   ← 两头都管，"满仓歇一歇"真的在歇
N=16 :  work_pull_mult = 1.125  →  合成范围 = [1.0125, 1.2375] ← 【下界跨过了 1.0】
```

⇒ **在 N>12 上，L2 的人口项把我的阻尼那一半整个抵消掉了**，`stock_pull` 退化成
**只抬不压**——而 §〇① 已经用 `hi=180/lo=20` 实测过：只抬不压会把上限臂推红。
**我在 N=12 上做的所有验证，结构上看不见这件事**，因为 N=12 恰好是 `work_pull_mult ≡ 1.0` 的那一点。

> **这正是 [docs/41 §2](41-baton-contract.md) 第三个盲区的教科书样本**：
> 判据没问题，出问题的是**喂给它的那个世界**——我把整棒的预算都花在了
> "换 seed"这一个维度上，而 `N=12` 这个默认阵容**恰好是让本机制的一半失效的那个点**。
> 契约把 `N=12 的默认阵容` 逐字列在"五个会让门失去判别力的温和配置"里，**而我照样掉进去了。**

### 9.2 修法是一条**推导出来的**约束，不是又扫一档

要让"满仓歇一歇"在 CI 真正跑的那两个 N 上**都还是在歇**，需要：

```
work_pull_mult(N) × (lo/den) < 1        对 CI 跑的每个 N 成立
work_pull_mult(16) = 1 + (1/2)(1 − 12/16) = 1.125
⇒ lo/den < 1 / 1.125 = 0.8889  ⇒  lo ≤ 88（den=100）
```

第一版 `lo=90` **恰好落在这条约束的错误一侧**（0.90 > 0.8889）。

### 9.3 **按约束改到 `lo=85` 之后，4a 还是红的——只是换了个红法。这一条是本节的重点。**

`hi=110 / lo=85 / den=100`（`0.85 × 1.125 = 0.956 < 1`，阻尼在 N=16 上确实恢复了），
N=16 seeds 1-12 实测：

|---|---|---|---|
| **改前** | **0/12** | 0.556 (seed 7) | **3** (seed 3,6,7,11) |
| `lo=90` | **3/12**（**全是上限臂**：seed 1,3,5） | 0.661 (seed 4) | **4** (seed 1,3,5) |
| `lo=85` | **2/12**（seed 2 **下限臂** 0.448；seed 7 **上限臂**） | **0.448** (seed 2) | **4** (seed 7) |

**软门要 ≥11/12 ⇒ 两个档位都破。** 而它们破的方式**不一样**：
`lo=90` 全部是产得太多（上限臂），`lo=85` 同时出现了产得太少（下限臂 0.448）。

⚠ 而**在 N=12 上，两档一样好**（seeds 13-60，48 个留出）：

| `lo=85` | **1/48**（seed 38） | 0.496 | 3 |

⇒ **N=12 上两档分不出高下，而 N=16 上两档都破**——换句话说，
**这不是"那两个数调得够不够准"的问题**。见 §9.5。

⇒ **4a 那一格在两个方向上都只有一格余量**（改前：下限余量 0.056、上限余量 1 种货），

[docs/68 §五](68-wave-r-r1-economy-ceiling.md) 与本文 §3.3 都实测过这一族参数**非单调**
⇒ **继续扫 `lo` 直到 4a 变绿，在统计上就是在验收网格上做多重检验。我停在这里。**

> "承认 + 独立开关 + 明写已知 bug + 不出货——一个原型可以留在树上，只要它的状态被写清楚。"

**⚠ 但要把话说全：这不等于任务完成。** 用户定的方向是"让加宽后的网格真的能绿"，
而**打开它才绿，打开它 4a 就红** ⇒ **本棒交的是根因 + 一个可开关的机制 + 一份阻塞点，不是一个已出货的修复。**

### 9.5 阻塞点的性质：**它八成不是我这条乘子的问题，而是 N≥16 上限臂的结构底座**

[docs/72 §2.2/§2.4](72-wave-s-s1-demand-reach-and-base-rate.md) 已经把它量成了结构事实：
**豆子 / 话本的需求分母只来自那 9 个能出 town 平面的居民，与 N 无关**，
而宏观池把它们的**产量**按人口放大 ⇒ **N 越大，这两种货越必然"全年零缺货"**，
上限臂的 6 个名额里**恒定被占掉 2 个**。N=16 改前的零缺货上限已经是 3（余量 1 种货）。
⇒ **任何抬高产出的改动都只剩一格可用**，而这一格不够一次经济改动的重排幅度。

**真正的解在需求侧**，而 [docs/72 §3.3](72-wave-s-s1-demand-reach-and-base-rate.md) 已经把两条路
都判成了**架构级改动**（给克隆体一个家 / 把 `喝咖啡`·`歇着` 挪出 `fun` 维度），
按 [docs/41 §0.8](41-baton-contract.md) **动手前要过外部对抗评审 + 多棒**。
⇒ **这不该由本棒顺手做掉，我也没有做。**

⚠ **上面这一段是【解释】不是【实测】**：我**没有**做"把豆子/话本从判决里摘掉再跑 4a"这类干预来证明它。
按 [docs/41 §4](41-baton-contract.md)，**它是一条假说，不是结论。**
