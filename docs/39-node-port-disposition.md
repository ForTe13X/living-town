# 39 · Node 端口的处置：退役，而不是修复

> **结论（2026-07-26）**：`tools/sim_social_port.mjs` **正式退役为历史文物**。
> 它不再被称作"第二实现"或"引擎的交叉验证"，**不接入 CI**，也不做任何门。
> 文件顶部已加退役横幅，运行时也会打印——任何人跑到它都不会误把红当成引擎回归。
>
> 这是一个**负结果**，按本仓库的惯例原样留档：投入不在修好它，而在于把"它到底还算不算证据"量清楚。

---

## 0. 它是什么、当年办成了什么

`sim_social_port.mjs`（1279 行 JS）是社交底座的一份独立再实现，写于 **2026-07-03**（`ebac5a3`），
此后**逻辑一行未改**。它读真实的 `game/data/*.json`，自己跑 soak，自己查 **33 条**断言。

它当年确实办成了一件事，这份价值保留：

> 同一套社交规则在两种 RNG 实现下性质同时成立（端口用 mulberry32，Godot 用
> `RandomNumberGenerator`），说明那些不变量是**设计的性质**，不是某一份实现的巧合。

`README.md` / `README_EN.md` 里已经把它写成"历史交叉验证 / historical cross-check"，措辞是准的。
本文档把"为什么它只能是历史的"补齐。

**一个常见误读先澄清**：它**不是 differential test**。它从不与引擎比对状态——两边各跑各的轨迹，
只是各自去查同一份不变量清单（这一点它自己的原注就写了："非与 Godot RNG 逐字节一致"）。
真正逐字节的跨进程锚是 `tools/ci.sh` 第 4 步的**金标 + 逐 tick 前缀链**，那个才是红线 #1 的证据。
退役这个端口，不减损确定性证据的强度。

## 1. 现状：它是红的

```
$ node tools/sim_social_port.mjs --days 30 --seed 20260626
❌ 5·谣言传播: 知道 R1 的人 = [aria] (应≥2)
❌ 8·承诺生命周期: 创建=0 兑现=0 (均应>0)
❌ 20·谣言变冷(Maki-Thompson): stifler 数 = 0 (应>0)

```

同 seed 下 **Godot 引擎全绿**（S0 gate PASS，硬不变量全过）。所以这不是引擎回归。
那是什么？

## 2. 根因：逻辑冻结，输入却是活的 —— 二分到单个 commit

端口读 `game/data/{needs,map,personas,agents}.json`。**那是仍在演进的真实数据。**
把冻结的端口逐一喂给历史数据快照（做法：`git show <tag>:game/data/*.json` 落到临时树，
把端口原样拷过去跑），红绿翻转精确落在**一个 commit** 上：

| 数据快照 | 日期 | 规模 | seed 20260626 结果 |
|---|---|---|---|
| `ebac5a3` 初始公开快照（= 端口写成之日） | 07-03 | 6 人 / 24×16 | **exit 0，33/33 全绿** |
| `07367dc` world-systems 层 | 07-04 | 6 人 / 24×16 | **exit 0，33/33 全绿** |
| **`251ab9f` default cast 6 → 12 distinct residents** | **07-05** | **12 人 / 24×16** | **exit 1，3 红** |
| `a0557ae` 64×48 graybox 大地图 | 07-19 | 12 人 / 64×48 | exit 1，同样 3 红 |
| `138c158` 居民住进生成室内 | 07-24 | 12 人 / 64×48 | exit 1，同样 3 红 |
| 今天 | 07-26 | 12 人 / 64×48 | exit 1，同样 3 红 |

**肇因是 `251ab9f`（2026-07-05，端口写成的第 2 天）把默认阵容从 6 人扩到 12 人。**
后面的大地图、室内、多平面对这三条红**没有额外影响**——它们早就红了。

### 2.1 机制：定值高分的冲突动作把 invite/gossip 挤出了 argmax

端口的社交候选打分把两类分数混在同一个 argmax 里：

| 动作 | 打分 | 类型 |
|---|---|---|
| `confront` | `30 + min(severity, 20)` → 30..50 | **定值**，不随 urgency 缩放 |
| `apologize` | `32` | **定值** |
| `rally_oust` | `OUST_BASE(20) + min(severity, 15)` → 20..35 | **定值** |
| `gossip_rep` | `urgency*0.6 + gossipy + 10` | 缩放 + 高定值 |
| `endorse` | `urgency*0.6 + 12 + gossipy` | 缩放 + 高定值 |
| `gossip` | `urgency*0.6 + aff*0.1 + gossipy + 5` | 缩放，低定值 |
| `invite` | `urgency*0.45 + aff*0.15 + fam*0.18 + 4` | **全表 urgency 系数最低、定值加成也最低** |

人数 6→12 之后，同一 seed 同一 30 天：

| 量 | 6 人镇 | 12 人镇 |
|---|---|---|
| 冲突触发 | 7 | **121**（17×） |
| `gossip_rep` | 2 | **95** |
| `endorse` / `rally_oust` | 0 / 0 | **90 / 118** |
| 派系数 | 1 | 3 |
| standing 跨度 | −1..3 | −3..3 |
| **`invite`** | **35** | **0** |
| **`gossip`** | **2** | **0** |
| `meet` 兑现 | 34 | 0 |

链条是清楚的：邻居数翻倍 → 社交事务翻倍 → 拒绝翻倍 → resentment 更频繁越过
`CONFLICT_TRIGGER=6` → 冲突 17 倍；同时第三方候选变多、standing 跨度拉开越过
`REP_GOSSIP_TH=-2`、派系够到 `FACTION_QUORUM` → `gossip_rep`/`endorse`/`rally_oust` 全部解禁。
这些**定值 30-50 分**的动作从此吃掉几乎每一个社交时机，而 `invite`（+4）和 `gossip`（+5）
在 12 人镇里再也没赢过一次。

**三条红是同一个根因**：

- **#8 承诺生命周期** ← `invite` 归零，`meet` 承诺从未被创建；
- **#5 谣言传播** ← `gossip` 归零，R1 永远出不了 aria；
- **#20 谣言变冷** ← #5 的下游：没人遇得到知情者，`stifled` 计数自然是 0。

## 3. 已经不只是标定问题：语义分叉

如果只是上面这个，那是**机械可修**的（重标几个常数）。但还有两处是**语义**的：

1. **端口没有 space/floor 模型。** 引擎自 `1a7e6d6`（P3 Space/Floor/Portal 契约）起，社交地址是
   `_area_key(space, floor, pos)`（`Sim.gd:720`）——阿丽现在住 `cafe/2f`。端口的感知是纯 2D 的
   `areaAt(pos)`（`filter(o => areaAt(o.pos) === myArea)`），**表达不了今天的世界拓扑**：
   它会让站在咖啡馆外的人跟二楼的阿丽搭上话。这不是标定错，是模型错。
   （`game/scripts/player_agency_test.gd` 里 `_summon()` 必须显式设 `space`/`floor` 才能让 NPC
   走到玩家身边，正是这条契约在真引擎里生效的证据。）

2. **端口只读 22 个数据文件里的 4 个。** 没有经济、选举、节日、职业、住房、生涯、技能、
   空间、室内、天气、作息——对应引擎不变量 **#34-#37 零覆盖**。引擎侧 `Sim.gd` 已 3428 行，
   端口 1279 行。

还有一处元层面的：`7227517`（07-25）是**引擎自己**为同一类毛病做的重标定
（"盟约/互助/背叛在默认沙盘里全年零发生——三个门标错了带"），端口从未收到这次重标定。
也就是说端口是**一份已经被重标过两次的规格的旧拷贝**。

## 4. 决定性的一条：它自己的断言本来就不是可靠的门

即使把上面全部修好，还有一个更根本的问题。12 个 seed × 30 天全扫：

| seed | 今天的数据（12 人） | 它自己 07-03 的数据（6 人） |
|---|---|---|
| 1 | 绿 | **红**（#8, #15） |
| 2 | 绿 | **红**（#15） |
| 3 | **红**（#15） | 绿 |
| 5 | **红**（#8, #15） | 绿 |
| 7 | **红**（#8） | 绿 |
| 11 | 绿 | **红**（#15） |
| 42 | 绿 | 绿 |
| 100 | **红**（#8） | **红**（#8） |
| 2026 | **红**（#8） | 绿 |
| 20260626 | **红**（#5, #8, #20） | 绿 |
| 20260703 | **红**（#8） | 绿 |
| 12345 | 绿 | 绿 |
| **合计** | **7/12 红（58%）** | **4/12 红（33%）** |

**它在自己的主场也有三分之一的 seed 是红的。**

原因不难看：#5 / #8 / #15 / #20 都是**单局涌现时机**断言——"30 天里恰好发生过吗"。
这是所有统计量里对轨迹最敏感的一类（最小值 / 首达 / 是否出现过）。
"seed 20260626 绿"从来不是这个门成立，只是表格里运气好的一格。

> **同一个毛病的另一处实例**：`game/scripts/player_agency_test.gd` 第 7 节原来也是这样——
> 固定 2 天窗口问"有没有人来搭话"。B9 的候选加盐把首达从 +190 tick 推到 +523 tick，测试变红，
> 而 30 天社交总量反而从 161 升到 172。本棒把它改成了**跨 8 个 seed 的分布门**（见该文件第 14 节）。
> 端口拿不到同样的救法：它每次调用只跑**一局**，结构上产不出分布。

## 5. 处置

**(A) 修好并接入 CI —— 否决。** 要让它成为真门，得依次做完：
重标 12 人镇的整套打分 → 实现 spaces/floors/portals/interiors → 补经济/选举/节日以覆盖 #34-#37
→ 把 33 条涌现时机断言逐条改成跨 seed 分布 → 然后**每周跟住**一个还在动的 3428 行引擎。
那等于重写一遍引擎，而换来的证据**弱于 CI 已有的**（因为它根本不比对状态，见 §0）。付不起，也不划算。

**(B) 正式退役 —— 采用。** 已落地：

- `tools/sim_social_port.mjs` 顶部加**带日期的退役横幅**，并在**运行时打印**（红/绿两条路径都印），
  明确写"非零退出码不是引擎的判决"；顺手改掉那句过期的"断言 10 条"（真数 33，成功行的 `okCount` 才准）。
- 本文档（docs/39）作为处置留档。
- `docs/README.md` 索引里给它一行**状态说明**，不再让它以"活的第二见证"出现。

**不接 CI。** 一个 58% 抖动率的门接进去只会教人学会忽略红色。

### 仍然可跑

```bash
node tools/sim_social_port.mjs --days 30 --seed 1     # 绿（README 里记的就是这条）
node tools/sim_social_port.mjs --days 30 --seed 20260626   # 红，原因见 §2
```

## 7. 复现

```bash
# 现状（红）
node tools/sim_social_port.mjs --days 30 --seed 20260626 ; echo "exit=$?"

# 根因二分：把冻结的端口喂给历史数据快照
for tag in ebac5a3 07367dc 251ab9f a0557ae 138c158; do
  mkdir -p /tmp/d_$tag/game/data /tmp/d_$tag/tools
  for f in needs.json map.json personas.json agents.json; do
    git show "$tag:game/data/$f" > /tmp/d_$tag/game/data/$f
  done
  cp tools/sim_social_port.mjs /tmp/d_$tag/tools/
  node /tmp/d_$tag/tools/sim_social_port.mjs --days 30 --seed 20260626 >/dev/null 2>&1
  echo "$tag exit=$?"
done
# → ebac5a3 exit=0 / 07367dc exit=0 / 251ab9f exit=1 / a0557ae exit=1 / 138c158 exit=1

# seed 抖动率
for s in 1 2 3 5 7 11 42 100 2026 20260626 20260703 12345; do
  node tools/sim_social_port.mjs --days 30 --seed $s >/dev/null 2>&1; echo "$s exit=$?"
done
```
