## 一、干预：**把那两个货位真的空出来，钥匙照样开不了**

观测证伪的是"永久"两个字；派单要的是**干预**。参数在 `analysis/u1/PREREG.txt` 里**跑之前**就写死了：

> 隔离副本，key=110/90/100，另改两个数让 豆子/话本【真的会缺】：
> `produce.教书先生.amount 6 → 3`（话本）、`produce.咖啡师.amount 36 → 24`（豆子）。
> 对照 `H-freeoff`：同样两个数、但 key 关掉。网格 = `--agents 16 --seeds 1-12 --days 60`（4a 那一格）。
> 判读：H-free 上限臂 0/12 且下限臂 ≤1/12 ⇒ 坐实；仍红 ⇒ 证伪。

**实测**（判据一个字节没改）：

| 配置 | `#40` 红 | 逐货零缺货 seed 数 |
|---|---|---|
| **off**（未改动） | **0/12** | 话本 11 · 豆子 7 · 整洁 6 · 柴薪 1 · 屋瓦 0 |
| **H-freeoff**（只砍产量、key 关） | **0/12** | **话本 7** · 整洁 7 · 豆子 7 · 柴薪 1 · 屋瓦 0 |
| `hi110/lo90`（key 开） | **3/12**（全上限臂：1,3,5） | 整洁 11 · 话本 11 · 豆子 7 · 屋瓦 3 · 柴薪 1 |
| **H-free**（砍产量 + key 开） | **3/12**（全上限臂：2,3,12） | 整洁 10 · **话本 10** · **豆子 8** · **屋瓦 6** · 柴薪 1 |

**三件事一起读**：

1. **砍产量确实能空出货位——但只在 key 关着的时候。** `H-freeoff` 把 话本 从 11/12 压到 **7/12**，
   而上限臂仍是 0/12 ⇒ 这两个数本身不是一次破坏性改动。
2. **key 开着的时候，同样两个数几乎什么都没空出来**：话本 11 → **10**、豆子 7 → **8**（不降反升）。
   **机制是自洽的、也正是本机制的目的**：`stock_pull` 的"空仓加把劲"是一个**消灭短缺的闭环控制器**——
   你把产量砍掉，它就让 教书先生/咖啡师 多上几次工，把你砍掉的那部分补回来。
3. **红格数一个都没少（3/12 → 3/12）**，只是换了 seed（1,3,5 → 2,3,12），而**屋瓦 从 3/12 涨到 6/12**
   ——空出来的名额被 屋瓦 顶上了。

⇒ **假设（若那两格空出来，钥匙就能开）**：**证伪。**
⇒ 而且它给出了一条比派单那句更硬的话：
> **`#40` 的上限臂（「缺货绝迹」）与一个闭环的库存控制器在目标上是直接冲突的。**
> 控制器越有效，"全年零缺货"的货就越多。这不是标定失手，是两件东西在要求相反的事。
> **能同时成立的唯一方式，是让控制器的【净效果】不高于未改动的树**——这正是 §二 做的事。

### 1.1 另一条反事实（**纯算术，零混杂，但它是【改判据】，只做诊断不落地**）

把 豆子/话本 从判决里摘掉（`gated_n` 6→4，阈值随之从 `ns≥4` 变成 `ns≥3`），拿 `hi110/lo90` 的同一批数重算：
**上限臂 3/12 → 0/12。**

⚠ **它与 §一 的世界侧干预结论相反，而两条都对**——差别值得写清楚，因为它正是"改判据"与"改世界"的分野：
- **改判据**同时动了分子（少 2）**和**分母（阈值从 4 降到 3）⇒ 净松 1 格；
- **改世界**只动分子，而**分母不动**（那两种货仍然进判决），于是控制器把空出来的分子重新填满。

⇒ **摘掉它们能让 4a 变绿，但那是把门调松，不是把根因修好。** 本棒不做，也建议下一棒不做。

## 二、阻塞点的真实位置：**T1 §9.2 自己推出来的那条约束，没有任何一个固定的 `lo` 能满足**

T1 §9.1 的机制诊断是**对的**，我复核逐字成立：

```
N=12 :  work_pull_mult = 1.000  →  合成范围 [0.90, 1.10]     ← 两头都管
N=16 :  work_pull_mult = 1.125  →  合成范围 [1.0125, 1.2375] ← 下界跨过 1.0，阻尼整个没了
```

T1 §9.2 由此推出 `work_pull_mult(N) × lo/den < 1`，按 N=16 解出 `lo ≤ 88`，试了 `lo=85`——4a 仍红，**换了个红法**。
**T1 把这件事读成"这不是那两个数准不准的问题"，这句话完全正确，而它下一步归因到了结构性货位上。**

**正确的下一步在同一条约束里**：`work_pull_mult(N) = 1 + ½(1 − 12/N)` 随人口上升**趋于 1.5**
⇒ 要让约束对所有 N 成立就得 `lo ≤ 66`，而 `[0.66, 1.10]` 在 N=12 上是一次远超本机制意图的扰动。
⇒ **一个固定的 `lo` 在结构上做不到这件事。约束必须按【构造】成立，不能靠选数。**

### 2.1 改了什么（`Sim._object_candidates`，**四行**）

**语义**：**本职在班的那条广告，工作吸引力由【镇库】直接决定，人口代理不再另外叠加。**

```gdscript
var spf := _stock_pull_mult(...)
if wp_applied:          # 这条广告刚刚被 work_pull_mult 抬过
    spf /= work_pull_mult
benefit *= spf
```

⇒ 合成的工作吸引力乘子**恒为 `[lo/den, hi/den]`，与 N 无关**。约束不再是"选对了数"，是"写死在形状里"。

**为什么这不是又一个旋钮**：人口只是需求压力的**代理**——`production.json` 的 `scale._pool_why` 自己写着
"人口只是需求的上游代理"；而 `town_stock` 是同一件事的**直接测量**。两者叠乘 = 把同一份压力算两遍。
T1 §1.1 的根因表里，`work_pull_mult` 与 `stock_pull` 是**唯二**作用在同一条工位广告上的工作乘子。

### 2.2 它的代价，写在这里而不是藏起来

**商贩不产货**（`production.produce` 里没有他）⇒ 他那条广告的 `_stock_pull_mult` 恒为 1.0，
除回去之后他**净损失**了人口项。这是上面那条语义的直接推论，不是意外——
但它意味着 **`work_pull` 在 `stock_pull` 打开之后，对"本职在班"的那一族广告实际上退休了**。
L2 立 `work_pull` 是为了大 N（[docs/58](58-wave-l-plan.md)），而本棒只在 **N=16 / N=24 / N=60** 上量了它的替代品（§三.5），
**每一格的 seed 数都比 L2 当年少**。这是本棒最该被下一棒盯住的一格。

### 2.3 **负对照：N=12 上它是逐字节的 no-op**（事先写下的验收 ①）

`work_pull_mult` 在 N=12 上恒等于 1.0（`_work_pull_mult` 的显式短路）⇒ `wp_applied` 恒 false ⇒ 本段**一条指令都不多跑**。

```
seeds 13-60  digest 相同 48/48
```

⇒ **T1 在 N=12 上量到的每一个数，本棒逐字继承，不是"应该一样"而是"逐位一样"。**

## 四、T1 那条 `DetGate` 未解——**追到了，而且原地复现了**

[docs/76 §十](76-wave-t-t1-stock-pull.md) 记的那一行：

```
[freerider] seed=1 事件=1084  硬=✅ 确定=❌ digest 1409322286/... vs 1771125531/...  首个分叉 tick_no=125
```

T1 的处置是对的（立刻去复现、复现不出来就照实写"还没被解释"）。**它是可以被解释的，而且不用猜——那两个数就是答案。**

### 4.1 三条逐位吻合的证据（都在本机重跑得到，不是读日志推的）

| 观测 | 值 |
|---|---|
| 本机跑 **key 开**（`hi110/lo90`）的隔离副本，`freerider seed=1` | `1409322286 / 7111835604591032236 / 1067546138`，事件 **1084** |
| 本机跑 **key 关**的隔离副本，同一格 | 金标 ✅（= `1771125531 / 7181841899908216889 / 1710959258`），事件 **1033** |
| T1 那一行的 `d1` / `d2` | **`1409322286…` / `1771125531…`**，事件 **1084** |

⇒ **`d1` 是键开着的轨迹，`d2` 是键关着的轨迹，三元组逐位相同。**

**同一次 CI 里还有第二组指纹，比上面这条更硬**：那一跑的 `freerider` seed 2/3/4 全部报
`确定=✅ 金标=❌`，而它们的**"实得"**是 `3609654539 / 2405500593 / 4066887159`、事件 **1062 / 1053 / 1054**
——**逐位等于本机 key 关着跑出来的那三个**（我的 `detgate_off.log` 逐行可查）。
而那一跑的**"期望"**（当时刚被 T1 烘进金标的值）逐位等于本机 **key 开着**跑出来的那三个。

⇒ **结论**：那一次 CI 跑到 `freerider seed=1` 的**第二跑**时，`game/data/production.json` 的 `stock_pull` 键
**已经被摘掉了**。`DetGate._run()` **每一跑都调 `S._load_data()` 重读磁盘** ⇒ 两跑读到的不是同一个世界。
之后的 seed 2/3/4 两跑都在新世界里，所以它们 `确定=✅` 而 `金标=❌`。

**它与 T1 自己的时间线对得上**：[docs/76 §八⑥](76-wave-t-t1-stock-pull.md) 写着 "4a 变红之后，`production.json` 的键摘掉、
两个锚文件 `git checkout` 复原"——而 `ci.sh` 在 4a 变红之后**并不停**，它继续往下跑 4b、4c。

## 九、给下一棒的三句话

1. **一条在 N=60 上量到的结论，不能直接搬到 N=16 上用。** T1 §9.5 那条假设本身没错——
   它在 N=24（豆子 11/12、话本 12/12）与 N=60（各 6/6）上都成立；错的是**它被用在了 4a 跑的那个 N 上**，
   而在 N=16 上豆子只有 7/12。**"N≥16"这三个字是整条推断里唯一没被量过的那一步。**
2. **`#40` 的上限臂与一个闭环库存控制器在目标上直接冲突**（§一）：控制器越有效，"全年零缺货"的货越多。
   ⇒ 任何后续的产出侧反馈，**必须先问"它会不会把缺货消灭掉"**，而不只是"它会不会让供给够"。
3. **N=24 那一格现在是红的，而 CI 看不见**（§3.5）。要么给它接一道门，要么明写"N=24 不在能力矩阵里"。
   **两条都行，但"不提"不行**——那正是 [docs/41 §2](41-baton-contract.md) 第三个盲区。

**顺带一条给派棒者的**：`ci.sh` 4a 那一大段注释整段在论证"为什么是 N=24"，
而代码里 `CI_POOL_N:-16`（`6c7c8bc` 翻的，注释没跟上）。**注释与代码说的不是一件事**，
读它的人会以为 CI 在 N=24 上守着——而那正是本棒查出回归的那一格。修它要动 `tools/**`，不在我的行。
