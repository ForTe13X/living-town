# PixelArtistry components for Living Town

Checked 2026-10-19, with the standalone model alternatives below added on 2026-10-20 against pinned primary sources. Here, the user's “license free components” means components usable for commercial asset authoring without a model royalty or a separately negotiated commercial license. It does not mean public domain or absence of attribution obligations.

The useful adaptation is an optional, per-asset authoring workflow: prepare consistent views and alpha masks in Blender, refine or reconstruct a chosen asset, then inspect the result against the town's concept palette, scale and functional requirements. The user permits replacing existing art. New original geometry, furniture, vegetation, materials and composition may supersede the old assets; preserving an old mesh or its placements is not an acceptance requirement. Give replacements a new asset version and provenance, and verify their dimensions, circulation and export behavior. Keep the previous release as a recoverable comparison. The initial license review ran no installer or model. A subsequent standalone full-precision model experiment is recorded below; it produced no usable image.

## Adoption boundary

Adapt the MIT graph and the exact-view method now: an object's front/left/back/right views must share scale, pose, origin and lighting; side views must be true 90-degree profiles. Produce masks from the original Blender object. These controls suit individual rocks, planters, shop props, benches and small architectural details. They do not establish whether generated furniture preserves usable dimensions or whether generated buildings retain rooms and openings.

Keep UltraTex's complete 9B pipeline and Qwen-Image 2.1 disabled in the royalty-free commercial-capable path. Pixal3D remains an optional backend candidate behind an explicit dependency review; model-card MIT badges alone do not settle the DINOv3 encoder or an alternate background remover. A reconstructed café and surrounding furniture/foliage can establish the intended quality before applying the approach across the town. Broader reconstruction is allowed where it improves the result, provided its functional and export requirements are reverified.

For outputs that are eventually accepted, record the exact input/reference rights, new asset version, source object and UVs, workflow/model revisions, model-file hashes, generation settings and human visual review. Compare equivalent cameras before and after, with dimensions, accessible routes and room/furniture use recorded for replacements. Retain the old release for recoverability; do not require a replacement to preserve its geometry or arrangement. Where an asset participates in a game contract, record its new stable identifier or the explicit migration from the previous one. The model license does not grant rights in somebody else's reference image or prove an output's originality.

`tools/asset_refinement/component_licenses.json` records the machine-readable pins, source-document hashes and remaining unknowns. Hashes identify downloaded **small license/model-card documents**, not downloaded model weights. Weight hashes, where present, are published Hugging Face LFS metadata and have not been verified against locally downloaded weights.

## Standalone commercial-capable image models: 2026-10-20

The user has asked for better texture quality; the current café pilot is not an accepted artistic result. A permissive license does not demonstrate equivalent quality. The next comparison uses a separately licensed image-generation stack rather than trying to load UltraTex's 9B adapter into a different backbone. No model inference or quality acceptance is established by this license review; a later run receipt must identify the actual downloaded hashes, executable, settings and outputs.

The selected **FLUX.2 Klein base 4B + Qwen3-4B + FLUX.2 autoencoder** stack is eligible for an experiment under Apache-2.0. The official base-model [LICENSE](https://huggingface.co/black-forest-labs/FLUX.2-klein-base-4B/blob/a3b4f4849157f664bdbc776fd7453c2783562f4d/LICENSE.md) is Apache-2.0. The actual [Qwen3-4B LICENSE](https://huggingface.co/Qwen/Qwen3-4B/blob/1cfa9a7208912126459214e8b04321603b3df60c/LICENSE) is also Apache-2.0. BFL's pinned [official README, autoencoder section](https://github.com/black-forest-labs/flux2/blob/50fe5162777813d869182b139e83b10743caef15/README.md#flux2-autoencoder) explicitly gives the FLUX.2 autoencoder its own Apache-2.0 grant, including a link to `FLUX.2-dev/ae.safetensors`. The surrounding dev-model repository's NC license therefore must not be used as the sole license label for that separately licensed VAE, and the VAE's exception does not approve the dev diffusion model.

These selected single-file weights are available together in the [Comfy-Org 4B repackage](https://huggingface.co/Comfy-Org/flux2-klein-4B/tree/5f526678002e43af5551dadb73ce2e8c91b43afe), whose model card states Apache-2.0. Full precision files are selected rather than FP4 or GGUF quantizations; tensor dtypes and downloaded byte hashes still need to be recorded by the actual experiment. The base transformer has the same published LFS digest as BFL's original file.

The selected `stable-diffusion.cpp` executable revision is `95b3090664d019fcf8fa032a44d1d4793ba244b8`; its actual [LICENSE](https://raw.githubusercontent.com/leejet/stable-diffusion.cpp/95b3090664d019fcf8fa032a44d1d4793ba244b8/LICENSE) is MIT. Its documented CPU/Vulkan backend offers a practical path to a local AMD experiment, with compatibility, timing and output quality still subject to the real run. The runtime's example uses 20 steps and CFG 4; BFL's base-model reference uses 50 steps and guidance 4. A 20-step result is not evidence that final quality equals the longer reference setting. Neither configuration is an UltraTex multiview/texture adapter.

Two realistic paths deserve comparison:

1. **Standalone Klein base 4B images followed by authored texture integration.** Generate material/reference candidates using the cleared stack, then integrate selected results with controlled UV scale, independent roughness/normal authoring and identical Blender/Godot comparison cameras. The image model does not directly emit a calibrated PBR set or guarantee seam-free tiles, neutral lighting or consistency between independent views.
2. **Qwen-Image-Edit-2511 for stronger reference-guided edits**, with Qwen-Image-2512 as a text-to-image challenger. The official Edit-2511 card reports improved consistency, industrial design and new-view generation; the 2512 card reports improved natural detail and text rendering. These are publisher demonstrations rather than evidence for this café's surfaces. They require their own older Qwen-image encoder/VAE pipeline, resource test and comparison; renaming a Qwen 2.1 checkpoint slot does not adapt that architecture.

The existing exclusions remain: **Qwen-Image 2.1 research weights and the UltraTex/FLUX base 9B route are disabled**. The released UltraTex 9B LoRAs do not fit 4B; no equivalent trained 4B UltraTex adapter has been established here.

Texture-specific alternatives also need more than a code badge. [Hunyuan3D-2.1's actual license](https://huggingface.co/tencent/Hunyuan3D-2.1/blob/0b94677654c57bb9a6b6845cd7b704ccf551d327/LICENSE) grants limited royalty-free rights, rather than a blanket NC-only grant, but restricts territory, use of outputs outside that territory, and commercial use above its MAU threshold. It is not a suitable default for unrestricted worldwide game assets. [Paint3D](https://github.com/OpenTexture/Paint3D) has Apache-2.0 code and a texture-specific paper, but that does not clear its diffusion/ControlNet checkpoints or CUDA-oriented rasterization dependencies. [MV-Adapter](https://github.com/huanngzh/MV-Adapter) and [Step1X-3D](https://github.com/stepfun-ai/Step1X-3D) provide published multiview/texture methods and Apache-declared own weights, but their complete base-model/baking/backend dependency sets have not been approved here. They are research candidates, not claimed ready equivalents on the AMD machine.

AMD's [native Windows 8060S ComfyUI demonstration](https://rocm.blogs.amd.com/artificial-intelligence/comfyui-windows/README.html) establishes that a ROCm/PyTorch route exists for substantial diffusion workloads on that GPU family. It does not verify this machine's current installation, any of the candidate models, or a texture-quality result. CPU fallback likewise establishes an execution route, not acceptable speed. Quality remains the acceptance criterion; changing the license or obtaining a green import test cannot satisfy it.

## Actual local experiment and current delivery

The three full-precision Klein base 4B components (about 16 GB) were downloaded
and verified against their pinned LFS SHA-256 values. The pinned MIT runtime
recognized the AMD Radeon 8060S Vulkan device. A standalone 1024-square, CFG 4,
50-step RGB slate experiment then ran, ending at recorded progress **7/50**
when the host unexpectedly rebooted. Windows Kernel-Power 41 and EventLog 6008
confirm an unclean shutdown; the exact cause is not established. No candidate
image or successful completion receipt exists. See
`art/living_town/refinement_pilot/model_slate_v1/interruption_receipt.json`.

That GPU configuration is quarantined. The benchmark now defaults to CPU, but
CPU inference has not been executed or quality-tested. This experiment establishes
neither preserved quality nor dependable local operation. Current texture delivery
instead uses CC0 oak, plaster and terrazzo PBR, plus an explicitly procedural CC0
granite with artist-authored repeat and finish. Their sources, transformations
and actual export checks are described in the [pilot guide](CONCEPT_REFINEMENT_PILOT.md).
