## 〇、判决（先说结论，证据在后面）

**别按 docs/59 提议的顺序立项。它的第一步（"先在单镇上用外来旅人证伪主诉"）我已经替它跑完了，
而主诉在造第二个镇之前就已经被证伪——原因跟"多镇"毫无关系。**

三句话：

1. **"旅人=消息载体"这条主诉的载体今天是空的。** 谣言通道（`gossip`）在**任何 N 上都恒定只有 3-12 次 / 30 天**，
   而名声通道（`gossip_rep`）随 N 平方涨（N=12 的 251 → N=60 的 4210）。两者之比 **21:1 → 421:1**。
   种子谣言 R1 在 N=12/20/24/60 上**知道者恒为 2-3 人**——它从来没有扩散过第二跳。
   一个外来旅人在镇上住 25 天、发起 74 次 `gossip_rep`，**只发起过 1 次 `gossip`，
   而他带来的那条消息一个居民都没学会**（§三）。
   ⇒ **跨镇不会让这条通道变活，它只会让一条本来就近乎死掉的通道多跑几天路。**
2. **"外来旅人"确实能在不改任何现有数据结构的前提下做出来**，成本是**一个下午**，不是一周（§二）。
   我已经做出来了：中途 `append` 进 `agents`，10 天里 86 次事件、11 个不同伙伴、硬不变量全绿。
   **所以主诉可以在明天被证伪，而不是"一周内"。**——事实上上面第 1 条就是这么跑出来的。
3. **旅行当换页买不到它承诺的东西。** 现成的 aggregate LOD（同一形状）在 N=100 上只快 **2.45×**，
   代价是社交事件掉 **77%**、4-5 条软不变量变红——**而掉的正好是多镇提案存在的理由那件事**（§五）。

**如果还是要做**：先做的**不是**第二个镇，是**把 `gossip` 与 `gossip_rep` 的评分重新标定**
（一个常数，走 docs/41 §3 的受控重烘）。那是一次能直接检验主诉的干预，成本比一个镇低两个数量级。

## 一、① 跨镇要新增哪些状态，哪些进 `Inv.digest` / `chain_step`

### 1.1 先说本棒最重要的那个发现：**平面身份今天【根本不在】任何一份金标里**

`Inv.chain_step` 逐 agent 折的是：`_aid` · `pos.x*65536+pos.y` · 每条 need（量化 1/65536）·
`talking` · `option` 的 `kind|target|partner|area|phase|remaining`。
`Inv.digest` 折的是 `event_log` 的 `id:type:actor:target:accepted:subject:tick:witnesses:note`。

**两份里都没有 `space` / `floor`，也没有 `option.dest_space` / `dest_floor`。**

实测（探针 #1，seed 1 跑 200 tick 后，在同一份状态上做局部变异再还原）：

```
A_BASE              chain=3728596654  digest=124450349
B 只改 dan 的 space/floor（pos/needs/talking/option 一字不动）
                    chain=3728596654  digest=124450349   ← 逐位相同
C 连 area 缓存一起改（真 _traverse_portal 会刷新它）
                    chain=3728596654                     ← 仍然逐位相同
D option.dest_space = "town" vs "faraway_town"
                    chain=1540897252 vs 1540897252       ← 逐位相同
E 还原                                                    ← 回到 A_BASE
```

⇒ **今天可以把一个 agent 从镇上瞬移到另一个平面，逐 tick 前缀链与终态摘要一个 bit 都不动。**

这不是"多镇将来会造成的风险"，**这是今天就存在的盲区**——跨平面移动**已经在出货树上大量发生**：
seed 1、60 天，12 个居民里 **9 个**有非-town 平面的 agent-tick，占比 **8.9%-32.7%**
（dan 32.7% · hai 31.6% · ben 26.9% · tie 26.3% · evy 25.8% · aria 25.5% · coco 25.5% · lin 24.9% · mei 8.9%）。

> **为什么它今天没出事**：`_area_key(space,floor,pos)` 对非-town 返回 `"space:floor"`，而 `area` 决定
> `_nearby_agents`；平面一变，**社交对象集合就变**，于是**事件流**跟着变、`digest` 跟着变。
> 也就是说：**平面今天只经由"它改变了行为"这条间接路径被守着，一旦某次平面变化没有立刻改变行为，
> 两份摘要都看不见它。** 跨镇旅行恰恰会大量制造这种情形（人在路上，什么事都没发生）。
>
> **⇒ 立项前该做的第一件事不是设计跨镇，是把 `space`/`floor` 折进 `chain_step`。**
> 它会移动全部 12 条金标（受控重烘，docs/41 §3），**但那次重烘的价值在于：
> 从此"人在哪儿"是被守的状态，而不是被推断的状态。**

### 1.2 逐条枚举：新增状态 × 是否必须进摘要

| 新状态 | 住在哪 | 必须进 `chain_step`？ | 必须进 `digest`？ | 说明 |
|---|---|---|---|---|
| `agent.town` / 现有 `space` | agent dict | **必须**（今天没有，见 §1.1） | 经事件间接 | 不进 = 瞬移不留痕 |
| `agent` 在途标记 / 行程剩余 | agent dict | **必须** | 否 | 否则"还有几天到"这条状态不可回放 |
| 每镇 `town_stock` | 今天是**单个** `town_stock` dict | 否（不在链里） | **必须**，且 **`#38` 要按镇重算** | 见 §1.4 |
| 每镇 `town_coin` | 今天是单个 int | 否 | **必须**，`#34` 的等式要变 | 见 §1.4 |
| 货物在途（车上的） | 新容器 | **必须** | **必须** | 否则 `#38` 的"现存 = 开局 + Σ账本"当场破 |
| 两镇 tick 的定序 | 无状态（见下） | — | — | **别引入**，见 §1.3 |
| 跨镇 `event_log` | 今天是**单条**全局账本 | — | 已在 | **别拆**，见 §1.5 |

**"不进摘要的就是新的无人守的面"这条判断，本棒实测支持**：§1.1 的四条实验就是它的负对照。

### 1.3 两个镇的 tick 怎么定序：**唯一安全的答案是"别有两个 tick"**

今天 `Sim.tick()` 的结构是 `tick_no += 1` → `for ag in agents: _decay_needs; _advance_agent`
→ `_resolve_commitments` → `_sweep_conflicts` → 日界。
**`agents` 是一个平铺数组，遍历序 = 数组序 = `start_new` 的构造序。**

⇒ **正确做法：仍然只有一个 `tick_no`、一个 `agents` 数组，镇只是 agent 上的一个字段。**
一个循环、一个序、零新定序问题。§1.1 的平面机制已经是这么做的（`space` 是 agent 的字段，不是一个新世界）。

⚠️ **"每个镇一个 Sim 实例、各自 tick" 是这里最贵的错误**：它立刻需要一个跨实例的定序规则，
而那个规则会成为红线 #1 的新承重件，且 `Inv.chain_step(prev, S, ev_from)` 的签名只吃**一个** `S`。
**没有任何现成的门守得住两个 S。**

### 1.4 `#34` / `#38` 是本提案里最先破的两条硬不变量

- `#34 金钱守恒`：判据是 `money_total() == econ_total0`，而 `money_total()` = `town_coin + Σ agent coin`。
  **两个镇就有两个镇库** ⇒ 等式要改成 `Σ towns + Σ agents`。这条改动**必须与"钱能跨镇"同一个 commit**，
  否则第一笔跨镇交易就红。
  实测：探针 #3 里旅人带 10 枚钱入镇，**照抄 `add_player` 的 `econ_total0 += coin` 就绿**；
  而**离场时不做对称补偿**，`money_total()` 与 `econ_total0` 立刻差出那 10 枚。
- `#38 库存账本自洽`：对每种货 `现存 == 开局 + Σproduce − Σconsume − Σspoil − 当日待入账`，
  **且有一条"账外货"臂**：`town_stock` 里出现 `goods` 表没申报的键就红。
  ⇒ **`town_stock` 加"镇"这一维，等式与那条账外臂都要重写**；在途货物必须有自己的账，
  否则一件货离开 A 镇、还没到 B 镇的那几天，两边都算它"不见了"。
- `#39 产出溯源到在班本职`：要求每条 `produce` 事件的 actor **在 `jobs["jobs"]` 里**且职位申报了该产物。
  ⇒ **任何"旅人在路上/在别的镇干活"的设计都要先进岗位表**，否则当场红。

### 1.5 `event_log`：**别拆，但要知道它是不死的**

`_log_event` 只是 `event_log.append` + `_next_event_id += 1` + O(1) 折进 `event_digest`。
一条全局账本天然给出跨镇事件的全序，**没有理由拆它**。

**但本棒发现了一个具体的坑，而它正是"人会离开世界"这件事引出来的**：
`event_log` 是**只增不减**的，`agents` 不是。探针 #3 把旅人从 `agents` 里 `erase` 掉之后：

```
SCRIPT ERROR: Invalid access to property or key 'trav' on a base object of type 'Dictionary'.
   at: check_all (res://bench/Invariants.gd:343)
```

`Invariants.gd:343` 是 `prop_a[e["actor"]] = ...`——`prop_a` 只按**当前** `S.agents` 建键，
而 `event_log` 里还留着已离场者的事件。
⚠️ **它不是变红，是抛 SCRIPT ERROR 然后把那一轮 `check_all` 算成半截**（那次打印的是 `hard=[]`）。
`ci.sh` 的 `scan` 会因为 `SCRIPT ERROR` 判红，**但你拿到的判决理由是错的**。
⇒ **"agent 可以离开这个世界"是本提案对不变量层最深的一处改动**，比跨镇本身深。

## 二、② "外来旅人"能不能不改现有数据结构做出来 —— **能，而且已经做出来了**

**结论：能。所需一切原语今天都在，且有一个现成的模板——`Sim.add_player()`。**

`add_player` 就是"往一个已经在跑的世界里塞一个新 agent"：`_make_agent(...)` → `agents.append` →
`_agent_by_id[id] = ...` → `econ_total0 += coin`。**旅人 = 去掉 `is_player` 标记的同一件事。**

实测（探针 #3/#4，N=20，第 5 天抵达、住 10 天，一行 `Sim.gd` / 一个数据文件都没改）：

```
旅人在场 10 天：事件 86 条 · 不同社交伙伴 11 人 · 硬不变量 []（全绿）· 软只有 #8（20 天档本来就不出 meet）
离场（补偿 econ_total0 后）：money_total=312 == econ_total0=312 · 硬 [] 软 []
```

**够用的原语清单（全部现成）**：

| 需要的能力 | 现成的东西 |
|---|---|
| 中途造人 | `_make_agent(def, personas)`（`add_player` 用的同一个） |
| 中途入场 | `agents.append` + `_agent_by_id[id]=` + `econ_total0 +=`（照抄 `add_player`） |
| 独立的"路上" | `space`/`floor` + `_nav_grids[space][floor]` + `_area_key` → `"road:outdoor"` |
| 路边家具 | `world["objects"]` 条目带 `space`/`floor`（`_object_candidates` 已按平面过滤） |
| 走回镇上 | `spaces.json` 的 `portals` + `_route_next_hop`（BFS，文件序定序）+ `_traverse_portal` |
| 承诺式长途 | `journey` option + `_advance_journey`（跨多个 portal、中途不重挑、只被危机打断） |
| 带来一条消息 | `beliefs[id] = {claim,subject,source,via,tick}`（与 `aria` 的 R1 种子同形） |

**要付的三笔钱（都不大，但都得付）**：

1. **入场/离场的确定性触发器必须是 `f(仿真态)`**，不能是墙钟、不能是玩家点击
   （否则 `goto_tick` 重演不出来——`goto_tick` 走的是 `start_new` + 重跑，玩家的历史干预本来就不在重演里，
   `Sim.gd:1074-1076` 已经把这条诚实局限写下来了）。
2. **离场必须对称补偿 `econ_total0`**，且**必须处理 §1.5 那个 `Invariants` 崩溃**。
3. **`chain_step` 看不见他在哪个平面**（§1.1）。这条不是旅人特有的，是今天就欠的。

> **⇒ 对 docs/59 §四第三条的修正**：它说"可以在一个镇的数据结构里先验证……在造第二个镇之前就能证伪主诉"。
> **方向对，时间尺度错——不是一周，是一个下午。而且我已经跑完了，结论在 §三。**

## 三、主诉被证伪了：**旅人带来的消息，一个居民都没学会**

这是本棒最重要的一节，而它不在 brief 的三个问题里。

### 3.1 一个旅人带着一条独家消息进镇，25 天，扩散人数 = 0

探针 #4，N=20，旅人第 5 天入镇，`beliefs["NEWS_B"]` 是一条**只有他知道**的传闻（subject=`coco`，
与镇上种子谣言 R1 同形）。对照臂同时把**同一条消息**种给一个**本地**居民（`NEWS_L`）。

| 旅人人设 | 住 | 旅人的事件分布 | **NEWS_B（旅人带来）知道者** | NEWS_L（本地种下）知道者 | 旅人**听来**的传闻 |
|---|---|---|---|---|---|
| `aria`（爱八卦） | 10d | gossip_rep 27 · greet 4 · endorse 8 · **gossip 0** | **1**（只有他自己） | 1 | **0** |
| `ben`（寡言） | 10d | gossip_rep 60 · greet 11 · **gossip 0** | **1** | 0 | **0** |
| `aria`（爱八卦） | **25d** | gossip_rep 74 · greet 12 · endorse 16 · **gossip 1** | **1** | **3**（aria/ben/shu） | **0** |

⇒ 一个**爱八卦**人设的旅人，住 25 天、74 次名声八卦，**只发起过 1 次真正的传闻八卦，且没传出去**。
⇒ **他也没有"带走"任何东西**：`via=="gossip"` 的 belief 恒为 **0**。
⇒ **"运货的人同时在运消息"这句话，在今天的引擎里是一句空话——两个方向都空。**

### 3.2 机制：谣言通道被名声通道挤死，而挤压随 N 变本加厉

`_social_candidates` 里三条候选的评分：

```
greet      : urgency*0.7 + aff*0.1 + fam*0.05 + 6.0
gossip     : urgency*0.6 + aff*0.1 + 爱八卦?8 + 5.0
gossip_rep : urgency*0.6 +            爱八卦?8 + 10.0     ← 基分比 gossip 高 5.0
```

`gossip` 只有在 `aff > 50` 时才压得过对同一个人的 `gossip_rep`；**而新来的人对所有人 `aff=0`**
（实测 25 天后旅人的最高好感只有 12.0）。同时 `bad_targets`（我对其有坏名声的第三方）**随 N 涨**，
于是每多一个居民就多一批 `gossip_rep` 候选。

实测（seeds 1 与 5，30 天，全保真）：

| N | `gossip` | `gossip_rep` | 比值 | **R1 知道者** | 全镇经 gossip 获得的 belief 总数 |
|---|---|---|---|---|---|
| 12 | 12 / 10 | 251 / 321 | 21:1 / 32:1 | **2 / 2** | 4 / 4 |
| 20 | 11 / 8 | 919 / 979 | 84:1 / 122:1 | **2 / 3** | 3 / 3 |
| 24 | 11 / 4 | 1405 / 1334 | 128:1 / 334:1 | **3 / 2** | 6 / 1 |
| 60 | 10 / 3 | 4210 / 4163 | 421:1 / 1388:1 | **2 / 2** | 2 / 3 |

**`gossip` 的绝对次数不随 N 涨（恒 3-12），`gossip_rep` 随 N 近似平方涨。**
**R1 在任何 N 上都只到 2-3 人——它从来没有扩散过第二跳。**

> **仓库自己早就知道这件事，而且已经把门关掉了**：`Invariants.gd` 的
> `#5 谣言传播`判据是 `r1.size() >= 2 or not harmony or **not small_n**`
> ——**`small_n = agents.size() <= 12`，也就是 N>12 时这条不变量【被豁免】。**
> 注释原话是"大 N 单源谣言 fizzle 是现实"。
> ⇒ **多镇提案的旗舰理由，建立在一条【在提案自己的目标规模上已经被正式弃守】的机制上。**

### 3.3 便宜两个数量级的替代干预

主诉要的是"消息有延迟、有载体、可追责地传开"。今天缺的**不是**延迟和载体，是**传开**。
`gossip` 与 `gossip_rep` 的基分差 5.0 是一个常数（`Sim.gd` 的 `_social_candidates`，可经 `utility.json` 的
`_w()` 数据化）。**改它是一次 docs/41 §3 的受控重烘**，然后重跑上面那张表：
若 R1 知道者在 N=20/60 上从 2 涨到 6-10，主诉就活了，**而这时候再谈第二个镇才有东西可运**。

## 四、③ 路上的 agent 怎么维持社交 —— 两个可行设计 + 各自的负对照（全部实测）

### 4.0 先纠正 M2 的诊断（brief 逐字转述了它）：**social 有无条件满足者，而且全镇天天在用**

brief 与 `d7f4ac4` 都写着"**social 是五个需求里唯一没有无条件满足者的**"。**这条是错的。**

`map.json` 里 `bench_1`（长椅，`社交`，amount 40）与 `counter_1`（吧台，`闲聊`，amount 42）
**都广告 `need: social`**，`interiors.json` 的咖啡馆 1F 还有一件。它们走的是 `_object_candidates`，
**不经 `_social_candidates` 那道 `SURVIVAL_GATE` 提前 return**。

实测（探针 #8，30 天，物件 social 动作被选中的 agent-tick）：

| N | `counter_1` | `bench_1` | 其中发生在 `min_need < SURVIVAL_GATE` 时 | 用过的人 |
|---|---|---|---|---|
| 12 | 1893 | 630 | 25 | **12/12** |
| 20 | 2261 | 1214 | 117 | **20/20** |
| 60 | 2366 | 453 | 94 | **41/60** |

⇒ **`needs["social"]` 这个数值是物件可满足的，且生存门之下照样能满足。**
M2 真正成立的那句要窄得多：**`_social_candidates`（伙伴发起通道）没有无条件满足者。**
**"需求满足"与"社交发生"是两件事，而 M2 的措辞把它们合并了。** 下面 R2 那一行就是这个区别的实验形态。

### 4.1 路上到底先死于什么：**不是 social，是 hunger**

`needs.json` 的每 tick 衰减：hunger 0.28 · fun 0.16 · social 0.15 · energy 0.18 · hygiene 0.11。
`#01` 的判据是任一 need ≤ 0.5。从满值算：

| need | 到 `SURVIVAL_GATE=36` | 到触底 0.5 |
|---|---|---|
| hunger | 229 tick = **0.95 天** | 355 tick = **1.48 天** |
| social | 427 tick = 1.78 天 | 663 tick = **2.76 天** |

⇒ **一条什么都没有的路，1.5 天就把人饿穿，比 social 早一倍。**
实测（探针 #3/#7 R1，光秃秃的路、独行、7 天）：**五条 need 全部归零，触底 6176 need·tick，硬 `#01` 红。**

**但 social 的特殊性仍然成立，只是理由要换**：hunger/energy/hygiene/fun 的"路上解法"是**摆一件家具**
（纯数据）；**social 的家具解法能过 `#01`，却过不了 `#3`**——见下表 R2。

### 4.2 五条臂（探针 #7，N=20 + 旅人，独立 `road/outdoor` 平面，自带导航网，7 天）

| 臂 | 人数 | 路边家具 | 旅人最低 need | 旅人触底 | 旅人已接受社交 | 硬 | 软 |
|---|---|---|---|---|---|---|---|
| **R1 光秃秃的路（负对照）** | 1 | 无 | 全部 **0.0** | **6176** | 0 | **[1]** | [3, 8] |

### 4.3 两个设计 + 各自的负对照

#### 设计 A ——「**商队**」：跨镇移动的**最小单位是 ≥2 人**，不是 1 人

- **实测成立**：R4/R5 硬全绿、`social` 地板 **70.5**（比留在镇上还高）、7 天里 20/60 次已接受社交、
  软 `#3 无永久孤立` **绿**。
- **负对照（已跑）**：**R3**——同一条路、同一套家具、**只把人数从 2 减到 1** ⇒
  `social` 归零、触底 **1204** need·tick、**硬 `#01` 红**。
  ⇒ 这条负对照证明的是**人数**这一个变量，不是"路上有没有东西吃"。
- ⚠️ **R3 还顺带复现了 M2 的那条链**：social 被钉死时 `fun` 一起塌到 6.9、`hunger` 塌到 20.1
  （`_social_candidates` 在 `_min_need < 36` 时整段 return ⇒ 一切社交候选消失 ⇒ 效用竞争被单极化）。
  M2 说这条链"是推断不是隔离出来的"——**R3 把它隔离出来了**：唯一变量是长椅在不在。
- **成本**：`_journey_candidates` 今天是**逐 agent** 独立发起的，没有"结伴"概念。
  要么加一个"同行"绑定（新状态 ⇒ 必须进 `chain_step`），要么**用出发条件把结伴变成涌现**
  （只有当同平面已有另一个待出发者时才生成 journey 候选——纯读现有状态，不新增状态，**推荐**）。

#### 设计 B ——「**驿站**」：路上摆一件广告 `social` 的家具

- **实测：能过硬门，过不了主诉。** R2 硬全绿（`social` 地板 52.0），
  **但已接受社交 = 0，软 `#3 无永久孤立` 红。**
- **负对照（已跑）**：**R1**（同一条路、把家具全撤掉）⇒ 硬 `#01` 红。证明这道判据有牙。
- **它真正的判决在 `#3` 那一栏**：一个人靠长椅把 social 填满，**不产生任何社交事件**
  ⇒ 不长关系、不传消息、不留证词。
  ⇒ **对多镇提案而言，设计 B 是一个陷阱：它让所有硬门变绿，同时把提案的理由清零。**
  这正是 docs/41 §2 第三个盲区的形状——判据没问题，出问题的是它守的东西和你想要的东西不是一回事。

#### 设计 C（brief 没要求，但它是三者里最便宜的）——「**在途冻结**」

`_decay_needs` 第一行就是 `if ag.get("is_player", false): return`——**"某个 agent 的需求不衰减"这条机制今天就在树上**。
把在途 agent 标成不衰减，路上就没有任何 need 问题。
- **实测**：探针 #6 臂 A（满载抵达，等价于路上零衰减）⇒ 10 天内一切正常，`social` 地板 66.2。
- **负对照**：探针 #3 SILENT_ROAD（同一条路、不冻结）⇒ 硬 `#01` 红、6176 need·tick。
- **代价是叙事而不是正确性**：路上的人**什么都不经历**，于是"他在 A 镇听到的事"这半句也没了。
  ⇒ **C 适合"货运"，A 适合"消息"。** 而 docs/59 §四说要先做消息 ⇒ **先做 A。**

### 4.4 一条把 brief 与我自己的预期一起证伪的实测：**抵达时 social 很低【不会】掉进吸收态**

我原本预期"旅人带着路上掉下来的 social 抵达 ⇒ 复现 M2 的吸收态"。**实测是反的**（探针 #6，N=20 的镇，10 天）：

| 抵达时 social | 生存门锁定 | social 触底 | 已接受社交（其中**别人**发起的） | 回到门上 |
|---|---|---|---|---|
| 100（路上冻结） | 0 tick | 0 | 36（27） | n/a |
| 45（门上） | 0 tick | 0 | 34（21） | n/a |
| **20（门下，≈2.5 天的路）** | **61 tick = 0.3 天** | **0** | 36（**27**） | **54 tick 后** |
| 20 + 1 同伴 | 73 tick | 0 | 66（43） | 54 tick 后 |
| 20 + 3 同伴 | 61 tick | 0 | 128（69） | 54 tick 后 |

⇒ **一个 social=20 的人走进一个有人的镇子，54 个 tick（0.22 天）就爬回门上**，
因为居民会**主动对他** `greet`（36 条里 27 条是别人发起的），而 `greet` 的接受式带 `(100−need)*0.4`
——**他越渴，别人越容易接受他**（`_acceptance_margin` 的 `_: sum = (100.0-need)*0.4 + ...`）。
⇒ **M2 的吸收态需要的是【隔离】，不是【低 social】。**
⇒ **风险全部集中在"路上"这一段，抵达那一刻是安全的。这把要防的面缩小了一半。**

## 五、④ 旅行当换页：买得到多少性能，V2 认不认

### 5.1 先把没有换页时的成本量出来（探针 #2，seed 5，2 天，headless）

| N | 全保真 µs/tick | 全保真 tick/s | aggregate LOD µs/tick | LOD tick/s | 加速 |
|---|---|---|---|---|---|
| 12 | 440 | 2275 | — | — | — |
| 24 | 942 | 1062 | — | — | — |
| 60 | 2619 | 382 | 1338 | 748 | **1.96×** |
| **100** | **6171** | **162** | **2513** | **398** | **2.45×** |
| 120 | 8915 | 112 | 3402 | 294 | **2.62×** |

⇒ **成本是超线性的**：N ×10（12→120）而 tick 成本 ×20.3。
⇒ **区域目标 100+ 在全保真下的 headless 成本是出货阵容 N=12 的 14 倍**（440 → 6171 µs/tick）。
⚠️ 这是**桌面 headless**，不是手机；红线 #3 的 8 Elite 目标**仍然一格没测**（M2 与 §0.5 都这么写，我复核属实）。

### 5.2 「谁在哪个镇」是不是合法的 cohort 键 —— **是，但 V2 证明不了这件事**

`lod_verify.gd` 的 V2 臂：同一 seed、**五个不同的 `lod_focus`**（含 `(-1,-1)` 与 `(999,999)`）
必须给出同一份 `[Inv.digest, event_digest]`。而 aggregate 档的 cohort 是
`_compute_lod_cohort()`：`玩家 ∪ _is_salient(工作态) ∪ 无状态轮转(|_aid| % span == tick % span)`
——**整段一次都没读 `lod_focus`**（读它的是保守档的 `_compute_near_set`）。

⇒ **"谁在哪个镇"是 agent 上的 `space` 字段，是已提交的仿真态。用它当 cohort 键，V2 必然全绿。**

**但这正是问题**，而它是 docs/41 §2 第三个盲区的教科书实例：

> **V2 只变 `lod_focus` 一个东西。它不变玩家的位置——因为【所有被门控的跑法里根本没有玩家】。**
> 实测：`lod_verify.gd` / `Harness._run_once` / `DetGate` **没有任何一处调 `Sim.add_player()`**
> （全仓 `add_player` 的调用点只有 `Main.gd` 与四个交互测试场景）。
> 于是 `_player_pos` 在每一道 CI 门里**恒为 `(-1,-1)`**，
> `_is_salient` 里那条 `lod_player_r=12` 的近玩家臂（`Sim.gd:2575`）**结构上永不执行**。

⇒ **如果换页键写成"玩家所在的那个镇"，V2 会全绿**——因为玩家的 avatar 位置**也是**已提交仿真态，
而且门里压根没有玩家。**"由仿真态得出"这个条件被满足了，红线的意图却被绕过了。**

**⇒ 换页要立项，V2 必须先加一条臂**（这是本棒能给的最具体的一条建议）：

```
V2b：同一 seed、同一份仿真态，把【玩家 avatar 的初始落点】设成 K 个不同的镇/位置，
     摘要必须一致。今天这条臂【不存在】，且它跑不起来——因为 bench 从不建玩家。
     负对照：把 cohort 键改成"玩家所在镇"⇒ V2 仍绿、V2b 必须红。
```

### 5.3 换页真正的代价：**它吃掉的正是多镇提案的理由**

探针 #2，同一棵树，20 天：

| 配置 | 社交事件 | 孤立者 | 触底 | 硬红 | **软红** |
|---|---|---|---|---|---|
| N=20 全保真 | **1281** | 0/20 | 0 | [] | [8] |
| N=20 aggregate LOD | **280（−78%）** | 0/20 | 0 | [] | **[8, 11, 17, 18, 19, 40]** |
| N=100 全保真 | **7973** | 0/100 | 0 | [] | [8] |
| N=100 aggregate LOD | **1810（−77%）** | 0/100 | 0 | [] | **[8, 11, 17, 26, 40]** |

⇒ 换页（现成的同形机制）在 N=100 上**买 2.45× 性能，卖掉 77% 的社交事件**，
并让 `#11 冲突生命周期`、`#17 坏名声可恢复`、`#18 观点演化`、`#19 有界信任`、`#26 同派系亲和`、
`#40 产出闭环` **成批变红**。
⚠️ **而 `#3 无永久孤立` 全程是绿的**（无状态轮转保证每人每 31 tick 有一满帧，20 天足够攒到一次社交）
⇒ **今天没有任何一道门能报出"冷镇的社会生活掉了 77%"这件事。**

**接到主诉上**：多镇要的是"A 镇的事几天后出现在 B 镇"。
**如果 B 镇是冷的，那条消息落地时没有人在真的社交** ⇒ **换页与主诉在设计上直接对冲。**

### 5.4 「后台异步」：**按今天的结构，不能做**

`Sim.tick()` 是纯同步的：`tick_no += 1` → 单个 `agents` 数组顺序推进 → 同步结算。
`Inv.chain_step(prev, S, ev_from)` 在**每个 tick 结束时**折一次，`ev_from` 是**上一 tick 的
`event_log.size()`** ⇒ **"本 tick 产生了哪些事件"是链的输入之一**。
⇒ 任何"算完了就把事件塞进 `event_log`"的异步落地，**会改变事件落进哪个 tick 的分桶**，
而分桶是链的输入 ⇒ **逐字节回放当场破**。

**唯一能过红线 #1 的两种形态**（与 §0.5 写的 (a)/(b) 一致，我这里给出本仓库的具体判据）：

- **(a) 纯预计算**：异步只算**导航/寻路**这类 `f(静态地图)` 的东西——
  注意 `_path_cache` 已经被显式标为 `transient(DERIVED、不入 digest/存档)`，
  **这是仓库里已经存在的、正确的"异步安全"边界的样板**。凡是能进 `DERIVED` 那张表的，异步都安全。
- **(b) 确定 tick 边界 join**：结果必须**排队到一个由仿真态决定的 tick 才生效**，
  且同一 tick 内多个结果的落地顺序必须由 `agents` 数组序 / `_aid` 决定，**不能由完成先后决定**。
  **代价**：这样做等于"异步只是提前算，收益只有延迟不是吞吐"——
  因为你还是必须等到那个 tick，且必须等**全部**结果都到齐才能确定顺序。

⇒ **我的判决：把"后台异步"从立项范围里划掉，至少划到"证明它值得"之后。**
理由不是它不可能，是**它的可行范围被红线 #1 挤成了一条窄缝**：
最好的情况下只能覆盖已经在 `save_game` 的 `DERIVED` 白名单里的那几样
（`_path_cache` / `_nav_grids` / `_near_set` / `_player_pos`）——**那张表就是现成的"异步安全"边界**。
⚠️ **而这几样占 tick 成本的多少，我没有量过**（`cand_calls` 从 N=12 的 249 涨到 N=120 的 2056，
只有 ×8.3，而总成本 ×20.3——**这说明候选枚举不是唯一的增长源，但它说不出寻路占几成**）。
**立项前该先做这一个 profile，而不是先设计异步。**
