## 三、H3 · 精灵槽耦合的根治

**owns**：`game/scripts/WorldView.gd`
**不得触碰**：`game/data/*.json`（改数据是绕开，不是根治）

`id.split("_")[0]` 当精灵槽是一个**隐式契约**：数据里的 ID 前缀必须恰好等于某张贴图名，
而**没有任何东西在检查它**——F1 的四个工位就这么以占位框出货了一整波，G3 的砖垛还在这条路上。
要一张显式的 `type→slot` 表 + 一条断言：**任何 `advertises` 的对象，其槽位必须解析到一张真实存在的贴图**。
包络里必须写清：它抓不到"贴图存在但画错东西"（砖垛像木凳属于这一类，需要 H1 的判断）。

## 四、H4 · 给方法论装分母（**brief mutation test**）

**owns**：`docs/52-brief-mutation.md`（新文件）、`tools/brief_mutate.py`（新文件）
**不得触碰**：任何 `game/**`

外审的原话：**"24 不是质量指标……你不知道分母。"**
做法：取本 session 已经合入的若干份 brief，**注入 N 个已知的假事实**（类型分层：
错行号 / 错文件名 / 把改前基线说成现状 / 声称某道门会红而它不会 / 不可满足的验收），
派若干只读棒去执行"指出这份 brief 哪里是错的"，**测发现率**。

产出：`Injected: N / Detected: M / False acceptance: N-M / Detection rate`。
**这个数不好看也要写**——它是本方法论第一个真正的度量。

## 五、H5 · #40 从存在性判据升级为连续性判据（外审给的干预）

**owns**：`game/bench/Invariants.gd`
**不得触碰**：`game/data/*.json`、`Sim.gd`

外审的原话（照抄，因为它比我说得准）：`粮食 produce 3 / consume 200` ⇒ **过门**，
然后库存耗尽、居民饿死在 60 天以后。#40 是 `∃producer ∧ ∃consumer` 的**存在性**判据。
候选干预：`coverage = produce/consume` 落区间，或 `days_of_supply = inventory / daily_consumption`。

⚠️ **收紧前先量余量**（本 session 反复的教训）：先在 12 seed × 60 天上量出每种货物的
`coverage` 与 `days_of_supply` 分布，再决定阈值——**且 G3 刚加的屋瓦/柴薪是有 `inputs` 依赖的，
柴薪同时供澡堂与烧瓦，它的分布大概率最紧**。
⚠️ 另一条外审警告：**将来若引入本就不该被生产的货物，"每种货物 produce>0" 会假红**——判据要分档。
